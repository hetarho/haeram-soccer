# Automatic-play bottleneck measurements (T681/T682)

See [the session report](../261103-hr05.md). These artifacts distinguish a store-only component benchmark, real Host CPU measurements and actual browser throughput. Only the browser matrix measures displayed days with normal automatic saves. Production pace options remain x1/x2/x5/x10.

## Contents and interpretation

- Root `ab-batched.json` / `aa-batched.json`: isolated prepared-view store publication. Eight processes, 16 alternating pairs each, three warmups, adaptive batching with a 50 ms calibration target and 5 ms minimum CPU sample, normalized per identical exercise. A/A uses identical bundles. The candidate's normalized CPU ratio rounds to 0.0001; this is the removed duplicate store traversal, not whole-game speed. Initial `ab.json` / `aa.json` used unbatched samples below timer resolution and are excluded from CPU interpretation. The historical script's duplicate `cpu` metadata key leaves the verdict at that key; machine details are retained in the Host/browser metadata.
- `host/{baseline,candidate}/`: 1 ms main-thread Node inspector profiles, per-day stage spans and sampled self/inclusive attribution. Fourteen warmup days followed by 60 measured days, two real helper Workers and an explicit structured clone of each posted response. The profile excludes helper CPU, codec/autosave, the page and storage. Compressed profiles preserve original bytes; decompress before opening in DevTools. Self times avoid inclusive double counting.
- `host/ab.json`: four independent paired Host processes, alternating side construction and day order, 14 warmup + 60 measured days per side. Main-thread CPU is primary; timings below 5 ms are excluded. The reported ratio is the bootstrap verdict of process medians of paired day log-ratios, not the ratio of weighted total CPU. `host/aa.json` is the two-process identical-bundle noise control. All full-World output hashes agree after deleting only transport `receiptIds`. Fixture metadata is included; serialized World input is private.
- `browser/`: all 16 primary results, DOM/RPC/save/long-task traces, pooled analysis, environment, source/build hashes and fixture provenance. Two fixtures × four variants × two rounds; the second round reverses variant order within each fixture. Fresh careers execute 660 exact day commands, retained careers 365, including season boundaries. Every run must admit, complete and show exactly its target count, commit an automatic and a final save, pass checkpoint decoding/validation, match every saved World fact and reload to its final displayed date. Only transport `receiptIds` are omitted from fact hashes. Throughput excludes the final save, independent decode and reload; automatic saves during play remain included. Engine summer skips are part of the same deterministic date sequence.
- `verification.json`: stage-complete coordinator proof, including explicit Chromium continuation, isolated rechecks and the final main sync validation. The initial combined invocation was interrupted, not a passing full-suite invocation. `verification-initial.json` retains its nine successful pre-browser stages. `chromium-coverage.json`, initial completed list and resumed/isolated/repaired JSON reports prove exact coverage of all 349 cases: 26 initial passes, 318 resumed passes, four unchanged isolated passes and one repaired long-journey budget. Compressed initial/resumed/isolated logs preserve failures and interruption. `chromium-synced-results.json` and `verification-before-sync.json` document the additional test-infrastructure merge check. `provenance.json` hashes captured artifacts. Original user exports, prepared/final checkpoint payloads, serialized Worlds and generated API bundles are excluded.

Browser results report observed capacity on this Linux/Chromium host, with external load and cache warmth uncontrolled. Two browser repetitions are descriptive ranges, not a population confidence interval or a mobile guarantee. The separate paired CPU benchmarks include A/A controls. The 50 ms experiment changes the existing x10 interval only in temporary builds, keeping the seven-day buffer; it does not ship x20 or establish sustained 20 days/s.
