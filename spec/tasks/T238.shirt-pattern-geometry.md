## goal
Make the eight shirt patterns a single pure geometry source shared by clash sampling and both Canvas previews.

## acceptance
- [v] shirtPatternRegions and shirtColourAt implement the exact normalized polygons, circle clipping and optional trim in design §4.
- [v] kit-patterns.test.ts cases each named pattern occupies the expected broad regions, checks use a readable 3x3 grid, optional trim is the same ring for sampling, and custom colours remain exact pass.
- [v] Tests cover boundary/interior points and at least one asymmetric sash/chevron example, plus one-/two-/three-colour designs; no test only asserts an enum has eight entries.
- [v] No Canvas/DOM/React import or per-world mutation exists; pattern functions do not call a match simulator.
- [v] Targeted verification passes: `pnpm exec vitest run packages/engine/src/kit-patterns.test.ts && pnpm run typecheck`.

## impl notes
- Read `docs/CLUB-IDENTITY-CONTRACT.md` sections named below; it owns the stable interfaces used in this task.
- Prerequisites: T234. Read their implemented interfaces/results before editing; extend those modules rather than reproducing a prerequisite.
- Read design §4. Polygon points are readonly normalized tuples; generate the tiny fixed geometry once, not during a player animation frame.
- For pattern regions use explicit secondary, with primary as the outside field. Schema validation already guarantees secondary on a patterned shirt. Apply the optional radius 0.84–1 trim last.
- Keep the circle inclusion and region edge rule consistent (a documented inclusive convention) so the same point cannot get different colours in selection and painting.
- Return the caller’s original colour spelling; any normalized lookup keys stay internal. No additional texture or graphics dependency is needed.

## result
- outcome: completed. `packages/engine/src/kit-patterns.ts` builds the §4 regions once at module load as frozen `Polygon` arrays (`readonly (readonly [number, number])[]`; stripes, hoops, halves, band as rectangles, sash and chevron as the listed hexagons, checks as the five filled cells of a 3×3 grid from the top left) and exports `shirtPatternRegions`, `shirtColourAt`, `insidePolygon`, `insideShirtMarker`, `insideShirtTrim` and the constants `SHIRT_MARKER_CENTRE`/`SHIRT_MARKER_RADIUS` (0.5) and `SHIRT_TRIM_INNER` (0.84). Coordinates are the 0–1 box with y downward like Canvas. Edge convention: every boundary is inclusive within 1e-9 — a point on a polygon edge or vertex takes the secondary, the marker rim is inside, and the trim ring includes both normalized radius 0.84 and 1. `shirtColourAt` applies trim last (ring over field and pattern), then secondary inside any region, else primary, returning the design's own strings; a `plain` shirt ignores a stray secondary. Outside the circle it answers for the unclipped box, so callers clip with `insideShirtMarker` (a Canvas painter clips with the same radius). Imports only the identity types; no Canvas, DOM, React, world state or simulator. kit-patterns.test.ts (13 cases): a 5×5 grid per pattern, the checks 3×3 grid `#.# / .#. / #.#`, 28 boundary/just-past points, sash (top-left to bottom-right, not its mirror) and chevron (points down, not its mirror), frozen same-identity geometry, polygon membership equal to `shirtColourAt` on a 21×21 lattice, the inscribed circle, trim over both halves and at r 0.84/0.82, the trim colour equal to the 0.84–1 ring on a 40×40 sample for all eight patterns with the rest unchanged, one-/two-/three-colour designs on the 16×16 marker sample, and exact custom spellings.
