## goal
Create one reusable runtime resource boundary that discovers locale/theme choices from JSON registries without per-pack application code.

## acceptance
- [v] Define shared `PackRegistry`, registry-entry, `LocalePack`, `ThemePack`, message, font, icon and semantic-image-slot contracts, with pure validators. Registries have `schemaVersion`, `defaultId` and `entries`; each entry has `id`, `label` and a relative `resource` URL, with locale direction metadata where needed. Supported IDs come from validated entries, never an enumerated TypeScript union or another list.
- [v] `loadRegistry(kind)` and `loadPack(kind, entry)` use injected fetch through `presentationResources.ts`, resolve URLs relative to the registry/pack that declares them, and cache successful resources. The central path constants name the two registry endpoints only; there is no loader branch, import list or build configuration for an individual pack ID.
- [v] Validation rejects malformed/duplicate IDs, unsupported schema versions, absent defaults and malformed message/resource structures. Unknown selected IDs resolve through the registry's default. Load failures have a retryable presentation error and never call a game/save API.
- [v] Theme contracts cover semantic palette/surface/typography/shape/image-treatment tokens, font files, era/kind/stage image patterns, and SVG-path or image icon resources. Locale messages support named parameters and plural forms selected through `Intl.PluralRules`; schema/placeholder checks are shared rather than reimplemented by consumers.
- [v] Unit cases in `registry.test.ts` and `presentationResources.test.ts` cover `discovers choices from registry data`, `loads an unseen pack ID without a code branch`, `rejects duplicate entries and missing defaults`, `resolves resources relative to their declaring JSON`, `uses the registered default for an unknown preference`, and `can retry after a failed fetch` with injected resources and no engine/world fixture.
- [v] Fast checks and affected unit tests follow ARCH-30. No browser spec runs in this task, and no production locale/theme entry is added here; T300 and T301 provide the sole baseline packs before T302 connects them.

## impl notes
- Keep contracts and registry validation free of React, DOM, storage and simulation imports. Use the existing TypeScript/fetch toolchain and small shared guards; no translation library, YAML parser, dynamic executable module or new runtime package is needed.
- `PRESENTATION_PATHS` points to `/presentation/locales/index.json` and `/presentation/themes/index.json`. Each default is declared only in its registry; do not add `SUPPORTED_LOCALES`, `SUPPORTED_THEMES`, hardcoded default-ID fallbacks or duplicate picker arrays.
- Locale JSON contains a `messages` map keyed by stable semantic message IDs. A value is a string with named `{parameter}` placeholders or a plural descriptor `{ plural: parameterName, forms: { other: template, ... } }`; plural forms share the same message identity and validate their parameters. This is data interpolation, not HTML or executable templates.
- Expose `validateRegistry`, `validateLocalePack`, `validateThemePack`, `resolvePackEntry` and resource URL helpers for T300-T303. Their consumers reuse these functions; a new ID with the same schema requires no new validator.
- This task introduces contracts and an unused adapter only. It does not edit active full-model tasks, worker protocols, save encoding, playback clocks or the pitch renderer.
