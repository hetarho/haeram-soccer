## goal
The engine can field generated lab sides in a grid match and expose, override, restore and probe every numeric grid configuration value.

## acceptance
- [ ] `generateLabSide({ seed, tactic, average, spread })` returns a full modern-era matchday squad (formation slots in order, then the named substitutes) whose starters' mean OVR equals `average` (rounded) and whose every player is within `average ± spread` before the shift; same inputs give identical players (sides.test.ts "same seed same side", "mean equals average", "spread bounds").
- [ ] `setLabPlayerOvr(side, index, ovr)` regenerates only that player at the new OVR with his id stream unchanged (sides.test.ts "single player edit").
- [ ] `buildGridSetup(w, f, { lab: { squads, tactics } })` plays the given squads with rosters, bench, takers, tendencies, ratings/gap and both sides' match context derived from them and neutral context (0) on both sides; without `lab` every existing digest is unchanged (existing grid/match-model/settle tests pass; new setup test "lab squads drive the setup").
- [ ] `GRID_TUNABLES` lists every exported `*_CONFIG` object under packages/engine/src/grid by its export name; `tunableLeaves()` lists every finite-number leaf as `{ path, value }` with paths like `SHOT_CONFIG.candidate.base` (tunables.test.ts "every grid config is listed" scans the grid sources for `export const \w+_CONFIG` and compares).
- [ ] `applyOverrides(map)` sets the listed leaves after restoring every leaf to its default; unknown paths and non-finite values come back as rejected without changing anything else; `restoreDefaults()` returns every leaf to the value captured at first use (tunables.test.ts "apply/restore round trip", "rejects unknown paths").
- [ ] `probeReads(run)` returns the set of leaf paths read while `run()` executes and leaves the objects as plain data afterwards (tunables.test.ts "probe records reads and restores data properties").
- [ ] With `applyOverrides({ 'SHOT_CONFIG.<some leaf>': other })` a seeded lab match differs from the default, and after `restoreDefaults()` it reproduces the default digest (tunables.test.ts "override changes play, restore reproduces it").
- [ ] typecheck, lint, format:check and the affected unit tests pass.

## impl notes
- sides.ts (new, `packages/engine/src/lab/`): positions and roles from `FORMATIONS[tactic].slots` for starters and `squadPlaces(tactic)` order for the bench; bench size from `eraRules(LAB_YEAR)` named substitutes. Each player is `makePlayer('ENG', seed, \`lab:${side}:${index}\`, LAB_YEAR, ovr, position, age, 0, role)`; ages drawn from the side's seed stream 20–31. OVRs: draw `average + uniform(-spread, spread)` per starter and bench player, then shift the starters by the rounded difference between `average` and their mean and clamp to 1–99; regenerate each player at his final OVR so `overall` lands on it. Export `LAB_CONFIG = { year: 2024, averageRange: [40, 90], spreadRange: [0, 15], ovrRange: [1, 99] }` here; later tasks read these names.
- `LabSide = { seed: string; tactic: Tactic; average: number; spread: number; players: Player[] }`; setLabPlayerOvr returns a new LabSide.
- setup.ts / match.ts: a measurement-only `lab?: { squads: [Player[], Player[]]; tactics: [Tactic, Tactic] }` option (documented like `tactics`/`model`), threaded into `prepareMatch` so `squads` replace `startingSquad` (starters) and the rosters' bench, `tactics` replace the clubs' styles, and the NPC context term is 0 for both sides. Fatigue 0, adaptation as generated (0.8 → set 1 for lab players), no injuries/bans (`w.discipline` lookups skip lab players because their ids are not in the world).
- tunables.ts (new, `packages/engine/src/grid/`): imports each `*_CONFIG` and exports `GRID_TUNABLES: Readonly<Record<string, object>>`. Defaults captured by deep-cloning leaves on first call. Overrides write leaves in place (objects are plain, not frozen; `as const` is type-only — cast through a writable helper). This module reaches grid execution, so only the lab worker and tests import it, never UI (ARCH-4).
- probeReads: replace each numeric leaf with an accessor property recording its path on get, run, then redefine as plain data properties with the same values. Values captured into module-level constants at import cannot be overridden: grep the grid sources for top-level reads of `*_CONFIG.` outside functions and export them as `LOAD_TIME_LEAVES` (paths) so the catalog can mark them read-only.
- Do not change any existing config value or digest; revisions 1–8 replay unchanged.
