## goal
The game in play lives in its SQLite file: the engine worker opens it, validates it and saves only changed rows between simulation steps; the codec worker, the world hand-off clone and the per-save envelope are gone.

## acceptance
- [ ] Protocol messages `open-game {gameId}`, `create-game {gameId}` (after a takeover, writes every row) and `save` (writes changed rows, answers `{ revision }` after the transaction commits) exist; `CodecJob`/`CodecResult`, the `codec` control message, `host.codec`, `runtime/codec.ts` and the client's codec worker, `builds` map and `CODEC_TIMEOUT_MS` save use are removed.
- [ ] `open-game` loads `rowsToWorld(store, { includeCold: false })`, applies the checks `decode` applies today (versions, catalog pin and hash, currency, relevelled-money refusal, `validateWorld`), the writer upgrade of SAVE-10, attaches the store (`attachRecordStore`) and primes a `RowSaver` with the loaded rows so the next save writes only changes. An unsupported schema/version is a typed `SaveCompatibilityError` and leaves the file untouched.
- [ ] Autosave cadence and rules of SAVE-8 are unchanged in `client.ts` (30 s running clock, stop/hide/close, owner decisions at once, one save at a time, newer request replaces a waiting one); the client's saved revision/time come from the `save` answer.
- [ ] `Host` takes an injectable `openStore(gameId): RecordStore` (default: the OPFS pool of T1005); host unit tests use `memoryRecordStore()` and show: create → save → one day → save writes < 10% of rows → reopen equals the in-memory world (`canonical`).
- [ ] Task stage, owner implementer: `vibe check --tier task` passes; browser save/reload journeys are an integration handoff (CI), recorded in result limits.

- Startup load: `client.load()` 396-455 used `SaveRepository.load` + RPC `inspect`; now the slot index's active game ID (`GameIndexStore`, `adapters/games.ts`) → RPC `open-game`. A slot whose database file does not exist reads as an empty slot (SAVE-29). Generation/parentGeneration lineage is not used for the game in play any more (the revision is).
- The transaction runs inside the worker between steps (`afterRound`-style boundary used by reads, `host.ts:349-376`); never in the middle of a day.
- Keep `inspect`/`encode`/`decode` only where export/import and slots still need them until T1008/T1009.
- Errors: quota/IO failure from the driver → the existing storage-error path (no acknowledgement, exportable memory kept, SAVE-3).
