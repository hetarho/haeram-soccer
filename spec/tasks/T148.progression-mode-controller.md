# T148 Make runtime clock behaviour obey automatic versus manual mode

## goal
Connect the clock to next-event requests while isolating automatic debt, resume and background behaviour.

## acceptance
- [ ] Automatic retains play/pause, x1/x2/x5/x10 and existing pacing/debt limits; changing pace cannot start a stopped clock.
- [ ] Manual sends one next-event request and remains stopped afterwards. eventDecided(), playThrough(), endWatch(), resumeAway() and hidden-tab timers never start unattended manual play.
- [ ] Switching into manual clears automatic debt/resume flags; switching back does not manufacture elapsed manual days. An old browser clock record cannot restart a saved manual career.
- [ ] Automatic event resolution resumes only when its prior run was event-stopped and no actual stopping decision remains. Opening settings/task navigation keeps the existing explicit-play rule.
- [ ] Readonly ownership, world replacement, critical/bankruptcy and save/worker failures remain blockers. Manual progress saves at its decision boundary without turning autosave into a paced wait.
- [ ] runtime/progression.test.ts names cases manual-no-resume-after-watch, manual-no-away-debt, automatic-resume-after-last-decision, mode-change-during-inflight and repeated-next-event-single-flight.

## impl notes
