## impl notes
- Split from T286 (261024, t5q2): T286 keeps the final release gate (accuracy registry on the final football, century performance and capacity, the switch, documentation) after T401 and T308; this task is the activation machinery none of those numbers change, so the manager-history lane can start now.
- T281's review left two gaps this task closes: dispatch follows the world's model and ignores the switch (kept: a recorded model is the career's model, SAVE-23), and `persistence.ts` accepts container-3 imports. Decided: no load gate. Production cannot write a model-carrying career while the switch is off, measurement and the e2e fixtures import such careers into the build, and a gate would make a released career unloadable if the switch were ever turned back off. The switch gates activation only.
- Reuse `trackingBoundary` and `openNpcSeason` from `npc-stats.ts`, `checkpointSchemaFor` and `carriesMatchModel` from `contracts/src/match-model.ts`, and the host's existing inspection/activation flow (`inspected`, `upgraded`, `encode`); do not add a second save path, store or reset. The safe boundary is the same one the host already uses before switching worlds with playback pending; find it from the queued/revealed playback state rather than a new flag.
- Supported careers are rules 4.0.0 (SAVE-19); anything earlier stays under SAVE-19's legacy handling and never activates.
- Do not run playwright or `tests/e2e` from this task (ARCH-30); the batch run before the lane's push to main runs them.
