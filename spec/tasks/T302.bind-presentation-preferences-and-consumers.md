## goal
Make the single Korean locale and pixel theme actual application dependencies through one shared provider and registry-derived preference UI.

## acceptance
- [ ] A browser presentation controller loads registries/default packs, exposes stable `useLocale`/`useTheme` services through one provider and installs the theme before exposing the app as ready. The base Korean/pixel appearance and existing first-play/lazy-loading behavior are preserved; initial resource failures offer retry without modifying game data.
- [ ] One reusable presentation-settings component is reachable before founding, from game slots and through the HUD menu. Its locale/theme options are mapped from registry entries, showing one current choice each. It has no hardcoded language/theme options, per-ID conditions or separate component tree for a pack.
- [ ] A namespaced preference adapter stores the selected IDs separately from game checkpoints. Restore valid selections, use registry defaults for removed IDs, and keep session selection usable when storage is denied or malformed. Read-only game tabs can change presentation without sending worker commands or acquiring save ownership.
- [ ] Bind existing shell/navigation/settings strings and facility-image descriptions to T300's catalog; update document language/direction through the controller. Existing display-format helpers consume the shared locale service while preserving Korean output, WEB-67 monetary policy and fixed game-calendar meaning. Other feature/engine source extraction is explicitly outside this task.
- [ ] Bind existing global theme styles, FacilityArt/facilityScene, PixelIcon and TrophyIcon to T301's tokens/resources through shared adapters. Preserve current image URLs, image semantics, icon layers/accessibility and default layout. Adding another valid registry resource later changes these consumers without modifying their TSX or resolver code.
- [ ] Asynchronous selection is transactional and latest-request-wins: a failed or stale request cannot overwrite the active pack, leave mixed old/new resources, remount/reset the game, change navigation/drafts or dispatch a game command. Existing stored titles/details/names pass through unchanged.
- [ ] Unit cases in `controller.test.ts` and `presentationPreferences.test.ts` cover `restores a registered selection`, `falls back after a pack is removed`, `uses session settings when storage is denied`, `ignores stale load completion`, `keeps the active pack on failure`, and `never sends a game command for presentation changes`. Update focused format/facility tests for default behavior; task checks and build follow ARCH-30, with browser journeys deferred to T303 and the batch run.

## impl notes
- Compose T299's resource adapter, T300's translator/formatters and T301's resolver/installer; do not create another discovery/default/asset-resolution implementation in a React component. React consumers receive a stable semantic service contract while registry IDs remain data.
- `PresentationPreferencesStore` reads/writes `haeram-soccor:presentation`; it does not use the save manifest, slot envelopes, World, worker messages or save migration. Own this one preference record here rather than extending the current career profile/codec.
- Keep one settings host/provider across the shell's existing screens, with compact triggers that respect founding and slot bounds. Reuse existing accessible Select/Dialog controls. Modal use follows existing suspension behavior; do not introduce a new progression policy.
- The one-time adapter changes replace pixel-specific constants and paths behind current component APIs; future theme additions touch only the registries/packs/assets. Preserve existing data attributes used by default-theme browser tests where they still describe the current resources.
- Keep the engine-driven Canvas and its timing/trajectory modules untouched. Semantic font aliases allow themed text styling without injecting a theme into playback or changing recorded kits/crests. This task has no dependency on T275/T283 and does not edit their files.
