## goal
Prove the complete browser workflow preserves real designs and history rather than only showing correct local previews.

## acceptance
- [v] The continuity journey creates a custom one-/three-colour crest and patterned shirts, settles a match, edits the current design, exports/imports and verifies current identity plus earlier recorded appearance exactly.
- [v] A choice saved before the next fixture survives reload and slot parking/restoration; a different game receives neither that choice nor any unapplied editor draft.
- [v] Supported old-envelope fixtures preserve exact legacy crests and gameplay facts, generate only missing shirts and keep historical appearance absent with the correct notice.
- [v] Readonly inspection performs no identity installation/disk upgrade; taking ownership later uses the validated writer path once. A failed apply or checkpoint preserves recoverable original data and the current draft/export path.
- [v] A future envelope/identity metadata fixture with a valid older predecessor remains protected rather than being reset or silently replaced.
- [v] The new journeys run on Chromium in the batch run and on Firefox and WebKit in CI (ARCH-30, ARCH-23), at both 360x740 and 390x844 for the primary edit/preview path; screenshots/traces retain actual preview/observation evidence.
- [v] Targeted verification passes: `pnpm exec vitest run apps/web/src/adapters/persistence.test.ts && pnpm run typecheck && pnpm run build`; `tests/e2e/club-identity-continuity.spec.ts` and the four other `tests/e2e/club-identity-*.spec.ts` journeys are written or updated here and confirmed by the batch Chromium run before the push (ARCH-30), named in `- limits:`.
