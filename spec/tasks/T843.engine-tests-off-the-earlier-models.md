## impl notes
- About a hundred files name `DISABLED_RELEASE` (measured 261111). Most use it to get a cheaper or frozen world for a test of something else — money, staff, calendar, saves. Such a test keeps its meaning on the released model: change the release, let `tests/fixtures/worlds.ts` rebuild the cached world, and fix expectations that were tied to particular match results by asserting the rule instead of the number where the test allows it. A test whose subject is the pre-feature model itself (its summary path, its grid matches, activation from it) goes, with its fixture.
- Work directory by directory and run each file as you go (`pnpm exec vitest run <file>`); the integration tier is slow — never run all of it.
- An own match on the released model costs about what a pre-feature grid match did once T837 is in; if a file's cold cost grows materially, record it in `tests/config/cold-costs.ts`.
- `MatchModelRelease.enabled` and the pre-feature branches themselves are removed in T845, after T844 has cleared the scripts and the web; this task only removes their readers under `packages/` and `tests/fixtures`.
- Golden regeneration (→ARCH-20/21): the file stores end-state facts of synthetic scenarios, own matches included; they change because own matches are now settled by the result path. Compare the non-match facts before and after and explain every difference.
