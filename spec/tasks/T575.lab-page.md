## goal
The owner opens `/lab`, generates and edits both sides, edits engine numbers, runs simulations and compares each run against a pinned baseline.

## acceptance
- [ ] apps/web/lab.html is a second Vite entry (`build.rollupOptions.input` main + lab); `/lab` serves it in dev (a small plugin rewriting `/lab` to `/lab.html`), in `scripts/preview.mjs` and on Netlify (`/lab /lab.html 200` in `_redirects`). The game's initial assets are unchanged (build output lists the lab as its own chunks).
- [ ] Sides panel, left and right: tactic select (4), 평균 OVR and 편차 inputs within `LAB_CONFIG` ranges, seed with 새로 뽑기, 생성 (confirm when individual OVRs would be replaced), and the squad list (slot position, name, OVR input, starter/bench) with the starters' live average.
- [ ] Values panel: groups from tunables.json, search over path and comment, default vs current, changed marked, reset per value / group / all, `loadTime` leaves read-only with a note, leaves not in the probe's read set hidden behind "이 리비전에서 안 읽는 값 보기". 변경값 복사 (JSON path → value, changed only) and 붙여넣기 import that reports skipped paths.
- [ ] Run bar: N select (1/20/100/300/600, default 100), run seed, 시뮬레이션, progress, 취소. Editing during a run does not change the running run.
- [ ] Results: outcome line, MATCH-23 table (band, value ± interval, verdict, equal-sides note) and side table; with a pinned baseline each row shows the baseline value and the difference, marked when the intervals do not overlap. 1-match runs show the match details.
- [ ] Kept runs: last 10 finished runs with time, N, sides' averages/tactics and changed-value count; pin as baseline, load settings back, delete; clear all.
- [ ] state.ts persists sides, overrides, run settings and kept runs under one versioned localStorage key, every access in try/catch, the page working without storage. state.test.ts "persist round trip", "kept runs cap at 10", "import skips unknown paths", "difference marking".
- [ ] tests/e2e/lab.spec.ts: open `/lab`, generate sides at 70, set one player's OVR, change one value, run a 1-match and a 20-match run, pin the first 20-match run, rerun with a changed value and see the baseline column; the game at `/` shows no lab link. Browser execution belongs to the batch gate.
- [ ] typecheck, lint, format:check, build and the affected unit tests pass.

## impl notes
- Korean labels; value paths shown as code. Plain React + CSS module like the game; no new dependency. The lab page imports only tunables.json, protocol.ts, `LAB_CONFIG`/types from sides.ts if sides.ts stays a read leaf (it imports makePlayer → world generation: so generation happens in the worker through protocol.ts's `generate`/`setOvr` messages (T574); keep the page free of engine runtime imports, ARCH-4).
- Layout: two columns on desktop (sides | values) with the run bar and results below; single column under 900 px. No game chrome, theme or save code.
- Kept run record: `{ id, at, count, runSeed, sides (seed, tactic, average, spread, ovrs), overrides, summary }`.
