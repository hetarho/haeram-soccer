## goal
Checkpoints are built, compressed, checksummed and validated in a background codec worker, so no command and no UI update waits for a save.

## acceptance
- [ ] New module worker `apps/web/src/runtime/codec.ts`, bundled like worker.ts: it receives a world snapshot with generation/parentGeneration, runs `encode`, then validates its own candidate with `decode` (→ARCH-13), and returns raw + envelope, or a typed error without anything written.
- [ ] The client creates the codec worker and hands the engine worker a MessageChannel port to it; the engine worker posts snapshots straight to the codec (no world copy through the UI thread).
- [ ] host.ts no longer encodes on ordinary commands: replies carry no `raw`; a `save` request (and the save that follows an owner decision, →SAVE-8) posts a snapshot of the current world and revision to the codec. Export keeps its explicit encode.
- [ ] The client commits a codec-produced checkpoint without calling `inspect` again: SaveRepository.commit accepts the codec's validated envelope; slot write → read-back compare → manifest stays as it is (→ARCH-13). Load, import and recovery still decode and validate in the engine worker as now.
- [ ] At most one save is in flight; a newer request replaces the waiting one, and a checkpoint older than the last committed generation is never written.
- [ ] host.test.ts: an `advance-days` reply carries no `raw`; a `save` request yields a checkpoint of the world's current revision.
- [ ] client.test.ts: a codec checkpoint is committed without an inspect round trip; a codec validation failure writes no slot and surfaces the existing save error.
- [ ] persistence.test.ts: the codec path round-trips a 10-season world (encode → validate → decode equals the world).
- [ ] `pnpm run typecheck && pnpm run test:unit` pass.

## impl notes
- Nested dedicated workers are not dependable on every supported browser (→ARCH-18), hence the client-created codec with a transferred port.
- Snapshot: `structuredClone` of the world in the engine worker. If it costs more than ~50 ms on the 100-season benchmark world (`.tmp/release-storage-worst-world.json`), post `pack(w)`'s output instead and let the codec finish encoding from it.
- Measured 261012 in Node on this server: encode 124–358 ms and decode+validate 268–626 ms from 1 to 30 seasons, against under 1 ms for an ordinary simulated day; that cost is what moves off the command path.
- The clock still waits for saves until T049; keep that behaviour here so this task can be merged on its own.
- Engine rules and the save format are unchanged: no version bump.
