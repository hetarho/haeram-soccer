## goal
Prefer applied explicit crests while preserving old two-colour slot summaries and correctly displaying single-colour negative space and optional accent.

## acceptance
- [v] crestOf/crestMap prefer each club’s explicit identity and use the exact legacy lookup only for absent data; changing the own crest does not change any opponent’s crest.
- [v] identityCrest.test.ts uses React server rendering to verify one-colour negative space has no undisclosed coloured field, optional third colour reaches its emblem, and existing two-colour SVGs retain the expected geometry.
- [v] The current HUD, standings/team links and runtime summarize() all show the same applied crest, including after a new own identity replaces the old object.
- [v] games.test.ts accepts existing two-colour summaries plus new one-/three-colour summaries, keeps optional colour fields and skips malformed entries without rejecting all slots.
- [v] Existing callers compile with optional secondary/accent; chart contrast fallback has a deliberate neutral fallback instead of assuming secondary is always a string.
- [v] Legacy generator behavior tests remain intact; no cache based only on seed/old primary can hide an explicit new crest.

## result
- outcome: completed. `ui/crests.ts`: `Crest` is now the contract `CrestDesign` (secondary/accent optional); `crestOf` finds the club and returns `club.identity.crest`, else the cached `legacyCrestMap` entry, else the fallback; `crestMap` is built on each call from the identities and computes the legacy map only when some club lacks an identity, so the legacy cache (keyed on clubs array, seed, player club and own colour) can never hide a replaced identity; both read current identities only. The transitional `kits()` shim uses the primary where a crest has no secondary and generates no colour. `CrestMark` (ClubCrest.tsx) keeps the two-colour markup byte for byte (literal recorded from the previous renderer before the change); the emblem takes `accent ?? secondary`; with no secondary, an SVG mask with its own `useId`-derived ID (`<clip>-holes`) cuts the field pattern, the disc ring and an accent-less emblem out of the primary as negative space, and the fixed neutral outline is drawn as before; labels and `aria-hidden` semantics are unchanged. `MatchCharts` exports `seriesColours(kits, awayCrest)`: when the lines look alike it tries the away secondary, then accent, when present, then the existing warm `#ff9257`, then neutral ivory `#f6f1e1`. `SlotSummary.crest` has optional `secondary`/`accent`; `entryOf` requires `#RRGGBB` primary, checks optional colours the same way, keeps bounded-text parts, and skips only the malformed entry. `summarize()` copies the current crest. New `identityCrest.test.ts` (7 cases): two-colour literal geometry for two crests; one-colour crest paints only its primary outside the mask, the mask carries the pattern/ring/emblem holes and the outline class stays; accent reaches the emblem with and without a secondary; unique clip/mask IDs and label semantics; ClubCrest (HUD/team sheet), ClubLink (standings/fixtures) and `summarize()` read through a `GameIndexStore` round trip agree on the applied crest, then on a replaced own identity (a new view object, and in place on the same clubs array after a lookup), with the rival's markup unchanged; chart fallback order. `crests.test.ts`: the legacy assertions now run on a world with identities stripped; added cases for an absent secondary in `kits()`, a new world's installed identities equal to the exact legacy map, an own replacement (crest and `Club.color`) leaving every opponent unchanged, and a crest applied in place after a cached legacy lookup. New `games.test.ts` (9 cases): two-, one- and three-colour summaries read and rewrite unchanged with optional fields kept or absent; eight malformed crest shapes each skip only their slot.
