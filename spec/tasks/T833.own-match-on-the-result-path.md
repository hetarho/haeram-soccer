## impl notes
- `candidateMatch` (`match.ts`) today: other clubs → `simulateAggregate`; the own club → `buildGridSetup` + `playGrid` (+ `buildFrames` when observed). Under revision 11 the own branch becomes: `playAggregate` with an attribution trace (the path already prepares an own side: the manager's substitution policy in `aggregatePlan`, the style profile, multiplier and drain from `prepareMatch`) → `aggregateRecord` → `matchDetail` (T825) → `writeScript` (T826/T827) with the seed `${w.seed}:${f.id}` → `validateScript` and `compareRecord` → `scriptMaterial` (T832) onto `record.material` → the playback.
- `MatchPlayback` (`packages/contracts/src/types.ts`) gains optional `script?: MatchScript`, `staging?: [StagingSide, StagingSide]` and `problems?: string[]`; `frames` stays `[]` on this path — frames are staged by the consumer (`stageFrames`, T831; the web's worker, T834). `script` and `staging` are set only when `observe` is true.
- `StagingSide` numbers: `anticipation`, `discipline`, `pressing`, `freedom` from `playerTendencies(player, manager, matchdayRole(...))` (`packages/engine/src/grid/tendencies.ts`, the four the inspector shows, →PLAYER-26); `pace` from the player's 속도 at his slot; a substitute is listed in record line order with the slot his stint gives him.
- Settlement (`season.ts` `recordMatch`, `knockout.ts`) reads the record only and needs no change beyond what the tests show; an own playoff tie (`resolveTie`) is never watched and takes the same path with `observe` false. Helper workers compute only fixtures without the own club (→ARCH-6) and are untouched.
- `packages/engine/src/testing.ts` `advanceToNextMatch` (used by browser journeys in Node) returns the playback as the engine gives it; add `stagedPlayback(playback)` beside it, which fills `frames` with `stageAll` when a script is present, for T834's and T839's tests.
- Watching equals skipping (→MATCH-7): the script and the material are written in both cases; only the hand-over of `script`/`staging` differs, and they are not part of the world.
- The fallback of →MATCH-38: on `problems` from the writer or a non-empty count comparison, settle the record as it is, leave `material` unset and return `problems`; never throw out of settlement.
- Not in this task: releasing the revision (T838), anything under `apps/` (T834).
