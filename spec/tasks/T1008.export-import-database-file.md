# T1008 Export and import the gzip-compressed database as `.haeram-save`

## goal
Export writes `haeram-<club>.haeram-save` = header + gzip(database bytes); import checks it fully into a temporary file before it takes a slot; old `.haeram-save.json` files are refused as unsupported.

## acceptance
- [ ] `saveFile.ts`: `encodeSaveFile(header, dbBytes): Promise<Uint8Array>` and `decodeSaveFile(bytes): Promise<{ header, dbBytes }>`; layout = ASCII magic `HRSAVE1\n`, one line of header JSON `{ format: 'sqlite-1', schema, engine, catalog, catalogHash, worldId, sha256, size }` and `\n`, then gzip of the database. Decoding refuses files over `PORTABLE_FILE_LIMIT`, stops gunzip at `DECOMPRESSED_LIMIT`, and checks size and SHA-256 before anything opens the bytes.
- [ ] Import order (SAVE-9): header → limits → checksum → write to a temporary pool file → `PRAGMA integrity_check` = `ok` → schema/versions → `rowsToWorld` + world validation → only then becomes the slot's game file; any failure deletes the temporary file and leaves every slot untouched. A file without the magic (e.g. an old JSON envelope) is a `SaveCompatibilityError` with a localized message.
- [ ] Export of the game in play saves first, then exports the file; per-slot export works for a game not in play; the download name keeps `haeram-<name>` with the `.haeram-save` extension, and the file inputs accept `.haeram-save`.
- [ ] Unit tests (node driver, `DatabaseSync#serialize` for bytes): export → import round trip equals the world; truncated, wrong-checksum, oversize and JSON-envelope files are refused.
- [ ] Task stage, owner implementer: `vibe check --tier task` passes; e2e specs that upload/download saves are updated (maintain only, CI) — list them in result limits.
