# T054 App notices as notifications in the HUD inbox
> st:todo | ssot:WEB-66 | base:WEB@51 | dep:T053 | touches:apps/web/src/runtime/client.ts apps/web/src/runtime/store.ts apps/web/src/ui/App.tsx apps/web/src/ui/App.module.css apps/web/src/ui/EventCenter.tsx apps/web/src/runtime/client.test.ts apps/web/src/runtime/store.test.ts | lane:ui-base

## goal
Rules-upgrade, recovery and take-over notices arrive as unread 시스템 notifications in the HUD inbox instead of a banner that never goes away.

## acceptance
- [v] `client.ts` no longer sets `state.notice` for the rules upgrade, the recovered checkpoint or the take-over after another tab closed. It records a system notification `{ id, text, at, read }` in per-browser storage under the app namespace, kept until read and never inside the world.
- [v] The HUD inbox lists system notifications marked 시스템 alongside world items, counts them as unread until opened, and they never stop the clock.
- [v] The notice banner (App.tsx `state.notice && !state.readonly`) is removed. The read-only badge keeps its own explanation (→WEB-10).
- [v] client.test.ts: activating an upgraded save adds exactly one unread system notification and sets no banner.
- [v] store.test.ts: reading a system notification marks it read and persists.
- [v] `pnpm run typecheck && pnpm run test:unit` pass.

## impl notes
- The read-only notice text (`다른 탭이 플레이 중입니다…`) stays the badge's text.
- The storage key sits beside the device profile's keys (→ARCH-29); other applications' keys stay untouched.

## result
- outcome: the rules upgrade, the recovered checkpoint and the take-over after another tab closed arrive as system notifications `{ id, text, at, read }` in `haeram-soccor:notifications` beside the device profile's keys, never in the world or its checkpoints; the HUD inbox lists them as 시스템 (unread ones above the club's items, read ones below), counts unread ones on the bell and reads them when the opened inbox closes or on 모두 읽음, and they never stop the clock because the world inbox alone drives stops. The banner is gone; `state.notice` now only explains the read-only badge (other tab playing, or no Web Locks). Only the writer notifies a recovery, so read-only tabs reloading the same checkpoint do not repeat it; notices sync across tabs through the client's storage listener.
