## goal
구단 leaves the tab bar and sidebar; home's 구단주 사무실 entrance opens a focused office screen with only the office bar, and entering stops automatic play until the owner leaves.

## acceptance
- [ ] The mobile tab bar has six destinations in the order 리그 · 컵 · 기록 · 홈 · 선수단 · 훈련 with the raised home tab; the wider-screen sidebar lists the same six; neither lists 구단 / 구단 운영.
- [ ] Home shows the 구단주 사무실 entrance card after the stadium scene (office illustration `FacilityArt kind="manager"`, name, the six area names); pressing it opens the office.
- [ ] On `page === 'business'` the HUD, information row, bottom control area, tab bar, sidebar and TaskReturn bar are not rendered; one office bar stays at the top of the content region (sticky, safe-area aware) with 나가기, 구단주 사무실 and the HUD cash control opening the cash sheet. Event cards, outcome toasts, sheets and runtime errors still appear.
- [ ] 나가기 returns to the task that detoured into the office when one exists (`returnToTask`), otherwise to the page the office was entered from, home by default.
- [ ] `ProgressionController.enterOffice()` stops a running automatic clock as an owner stop and remembers it; `leaveOffice()` starts it again only then; manual mode and an already stopped clock are untouched; nothing else in the office starts the clock. Unit cases in `apps/web/src/runtime/progression.test.ts`: running → enter stops, leave resumes; stopped → enter/leave stay stopped; manual → no change; a second leave without an enter starts nothing.
- [ ] `apps/web/src/ui/ClubHub.test.ts` covers the entrance card markup; a unit test covers the six-tab order (export the tab list or test `NAV`/`TABS` through a small exported helper).
- [ ] tests/e2e: a shared helper (e.g. `openOperations(page, area)` in `tests/e2e/events.ts` beside `openOffice`) enters through home and selects the area; every spec that clicked the 구단 운영 navigation button uses it. New Chromium journey in `tests/e2e/management-surfaces.spec.ts` (or a new `owner-office.spec.ts`): enter from home with the clock running → clock stopped, no tab bar/HUD → 나가기 → home with the clock running again. ## impl notes
- `App.tsx`: drop `'business'` from `NAV` and `TABS`; `const office = playing && page === 'business'`. Skip `GameHud`, `ProgressOverview`, `ProgressControls`, the mobile `<nav>` and `TaskReturn` when `office`; add `s.officeLayout` to the shell (no sidebar column, full-width main) and do not render the `<aside>` then. Keep `RuntimeFeedback`, `ActionOutcome`, `CommunicationsCenter`, `EventCenter`, sheets and hosts mounted.
- Move `HudCash` out of `App.tsx` into `apps/web/src/ui/HudCash.tsx` (export, unchanged behaviour) so `OfficeBar` reuses it without importing App.
- `OfficeBar.tsx` (+ module css): `{ back: { label: string; onClick: () => void }, title: string, client?: GameClient }`; a `<header data-ui="office-bar">` sticky at the scroller top with `padding-top: env(safe-area-inset-top)`, back as a text button (`← ` + label, 44px target), title as heading, `HudCash` at the right. `Operations.tsx` renders it above its tabs with back `나가기` (T492 switches it per area).
- Origin: `state.ts` keeps `officeFrom?: Page` in the navigation store, set whenever `page` becomes `'business'` from another page (in `setPage`, `openBusiness`, the popstate handler and `returnToTask`). `leaveOffice()` helper in state.ts: if `useTaskMemory.getState().returning?.target === 'business'` call `returnToTask()`, else `setPage(officeFrom ?? 'dashboard')`.
- Entrance: `ClubHub` `OfficeEntrance` (`data-home-part="office"`, button named `구단주 사무실`) calling a new `openOfficeLobby()` in `state.ts`; until T492 it opens `openBusiness('strategy')`.
- Clock: `ProgressionController` gets `private resumeAfterOffice = false`, `enterOffice()` (`if (mode==='automatic' && running) { resumeAfterOffice = true; this.pause(); }`) and `leaveOffice()` (`if (resumeAfterOffice) { resumeAfterOffice = false; this.start(); }`), mirroring `beginWatch`/`endWatch`. `App.tsx` calls them from an effect keyed on `office` (enter on true, leave in cleanup).
- Themes: the office bar uses the HUD's surface tokens from `App.module.css`; check standard, pixel and print at 390x844 and 1280x800.
- No engine, contract or save change.
