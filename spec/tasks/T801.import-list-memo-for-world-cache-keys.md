# T801 remember each file's import list for world-cache keys
> st:todo | ssot:ARCH-21 | base:ARCH@38 | dep:- | touches:scripts/lib/source-graph.ts scripts/lib/source-graph.test.ts tests/fixtures/json-cache.ts | lane:cache-key-memo

## goal
Computing a test world's cache key stops re-parsing every imported file with TypeScript in every test process: each file's import list is remembered by its path and content, so the key costs tens of milliseconds instead of 1–3 s, while every key stays byte-identical.

## acceptance
- [v] `sourceGraph()` takes an optional memo of import lists keyed by sha256 of (repo-relative path, NUL, file bytes), with a header holding a format version, the installed TypeScript version and the sha256 of `source-graph.ts`; a header mismatch or a corrupt memo means an empty memo; imports are still resolved against the live file system every run
- [v] `json-cache.ts` passes a memo file in its cache base (`runtime-imports-v1.json`; the clone-wide store locally, `node_modules/.cache/haeram-worlds` on CI) and saves it only after misses (read, merge, temp file, rename); no memo with `HAERAM_WORLD_CACHE=off`; the prune loop never removes it; the memo is rewritten with only current entries past a cap
- [v] optional, only if the keys stay identical: TypeScript is loaded only on a memo miss
- [v] unit tests: unmemoised, cold-memo and warm-memo keys are identical on the same temp tree; adding a runtime import of a new file changes the key and includes that file; a corrupt memo or another TypeScript version in the header falls back to parsing
- [v] a comparison over the scope set (scout tv10-I `compare.mts`, 138 scopes) shows every key identical to the repo's current `computationFingerprint`, cold and warm; per-process key time before/after on the same host
- [v] `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`, `pnpm exec vitest run --project unit scripts/lib tests/fixtures --maxWorkers 2`

## result
- outcome: `sourceGraph(root, memo?)` takes an `ImportMemo` from `importMemo(file)`: entries keyed by sha256 of (root-relative path, NUL, file bytes) hold the raw `runtimeImports` names, which `dependencies()` still resolves on the live file system each run; a miss parses `bytes.toString('utf8')` (identical to the former `readFileSync(file, 'utf8')`). The file's header is `format: runtime-imports-v1`, `typescript` (installed version) and `sourceGraph` (sha256 of `source-graph.ts`); a missing, unparsable or differently headed file, or a non-object `entries`, gives an empty memo, and entries that are not string arrays are dropped. `saveImportMemo(memo, cap = 10000)` writes only after misses: re-reads the file, merges, writes `<file>.<pid>.<uuid>.tmp` and renames; past the cap it writes only the keys this process looked up. TypeScript is required lazily (only on a parse); `fingerprintFiles` hashes the exported `typescriptVersion` read from `typescript/package.json`, which a unit test pins to `ts.version`, so every key keeps its bytes and script callers without a memo work unchanged. `json-cache.ts` builds one graph per process on first use, with `<cacheBase>/runtime-imports-v1.json` (no memo when the base is `off`), and saves after each newly computed scope (a failed write is ignored; the key is already correct); the prune loop only matches 16-hex scope directories. Unit tests: compiler version, unmemoised = cold = warm keys plus an added dynamic import changing the key and listing the new file on a warm memo, and corrupt / other-compiler (poisoned entries) memos falling back to parsing plus the cap rewrite. Identity (`.tmp/t801/compare.mts`, scout's 138 scopes, worktree tree, fresh process each): the unchanged `computationFingerprint` (dade94e6 copy) vs the new code unmemoised, cold memo (552 misses, 124 KB file, saved in 5–6 ms) and warm memo (552 loaded, 0 misses): 138/138 identical in each, 138 distinct keys; over three runs, 138 keys in one process took 4.6–6.7 s unchanged, 5.1–6.9 s unmemoised, 4.7–6.8 s cold and 2.1–2.7 s warm. Per-process key (`.tmp/t801/probe.mts`, worlds scope, 197 files, import + key, load average 13.6–14.1 during the release gate): unchanged 1,622–2,090 ms (5 runs, ~0.9 s of it loading TypeScript), warm memo 69–84 ms (5 runs), cold memo first process 1,319 ms; idle after the gate (load ≈1.1): unchanged 1,385–1,455 ms vs warm 53–56 ms (5 runs each), cold 1,135 ms; an earlier set at load ≈17: 2,510–2,933 ms vs 76–163 ms, and `host.test.ts` (249 files) 2,542–2,796 ms vs 103–117 ms warm (1,147 ms cold). With `HAERAM_WORLD_CACHE=<tmp>` `json-cache.test.ts` wrote the memo there; with `off` it wrote none and the shared memo's mtime stayed.

- limits: the first process after any edit to a reached file pays one parse per changed file (all files only when the header changes: a TypeScript upgrade or an edit of `source-graph.ts`). `sharedGraph()` now resolves the cache base even when a caller passes `options.directory`, so such a process asks Git once (as T788's lookup, about 12 ms). Concurrent savers can drop each other's new entries (last rename wins); the next miss re-adds them. Crashed writers can leave `.tmp` files in the base, which the prune loop does not remove. The e2e path (33 specs) was not run (ARCH-30 gate); it loads `source-graph.ts` through the same `import.meta.url` that `json-cache.ts` already relies on. The shared store now holds a `runtime-imports-v1.json` from this worktree's runs.
