## goal
Build a fast probabilistic kernel whose coupled facts supply every numerical team counter with the detailed engine's meanings.

## acceptance
- [ ] Define and export `AggregateInput`, `AggregateTeamFacts`, `buildAggregateInput` and `generateTeamFacts` as specified in the contract. Consume prepared strength/effective skills, lineups, roles, tactics, era and participation intervals without duplicating the strength formula.
- [ ] Generate all Metrics and TD counters, team xG and compact shot/flow facts through a coherent ledger. Possession, passes, chances, xG, entries, transitions, set pieces and spatial classifications are coupled; denominators and successful/attempted counts reconcile.
- [ ] Use named candidate-model seeded streams and grouped aggregate draws. Neither a 22-player trajectory simulation nor a loop over every match minute/action is used; bounded iteration over actual shots/incidents/participants is allowed.
- [ ] The kernel accepts participation/man-short intervals, extends period facts for extra time and preserves the existing conditioning factors. It does not create player attributions or activate production dispatch before T280/T281.
- [ ] Tests cover `produces every team counter`, `derives shot xg and classes from the same chances`, `derives spatial counters from shared flow facts`, `conserves attempts and completions`, `responds to tactic and strength inputs`, `accounts for man-short intervals`, and `is deterministic for its named streams`.
- [ ] Ledger tests reject inconsistent facts rather than zero-fill/clamp unrelated counters. Task checks follow ARCH-30 using compact synthetic contexts.
