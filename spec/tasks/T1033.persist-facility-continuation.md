## impl notes
- Use an optional `World.facilityAutoUpgrade` partial record keyed by `FacilityPart` with values `'armed'` and `'awaiting-funds'`. Missing field or key means off. Armed covers an idle part awaiting a manual start and an enabled part with ongoing work. `facilityWorks` distinguishes those cases and still holds the construction facts. Awaiting-funds is the saved authorization following completion. Keep updates by replacement so projected snapshots and patches see additions, changes and removals.
- In `schema.ts`, read the world validation near `facilityWorks` and keep absent legacy fields absent. In `worldProjection.ts`, include the optional field in the published facts. The generic `worldToRows` / `rowsToWorld` path in `apps/web/src/adapters/worldRows.ts` uses one row per ordinary world field, so this adds no storage layout, migration or database schema version. Cover the persisted states on the existing save round-trip path where its assertions do not already prove them.
- The in-process schema and projection are unit scope. The live SQLite save/open journey in `apps/web/src/runtime/saveRoundTrip.test.ts` is integration scope and belongs to the single shared `pnpm run verify:batch` gate.
