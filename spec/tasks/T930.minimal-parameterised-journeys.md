## goal
Remove parameterised Chromium journey instances that repeat one flow and its assertions in the same layout class, so the CI browser shards run the minimal journeys that still prove every distinct path and touch-sized layout.

## acceptance
- [ ] Every parameterised group in `tests/e2e/*.spec.ts` (loops or tables over viewport, width, height, theme, mode, locale, reduced motion or setup) is listed in result with file, parameter, instances before→after and, per removed instance, the kept instance or lower-tier test that carries its assertions; per kept instance, the distinct path, layout class or assertion it alone proves.
- [ ] No assertion that only one instance makes is lost: distinct behaviour paths stay (for example mediation's manual/automatic modes, manual-progression's direct/delegated authority, live-state's observation orders), and theme or height instances stay where their assertions read theme-specific art, contrast or fit.
- [ ] ARCH-18 stays met: every screen a journey covered at a touch-sized width (≤ 430 px) keeps at least one touch-sized instance; a desktop instance stays only where the screen switches layout or controls at desktop width and the assertions observe it.
- [ ] `pnpm exec playwright test --list --project=chromium` case counts before and after are recorded in result, and the after list contains every kept case; task-tier checks (typecheck, lint, format) pass through `vibe check --tier task`.
- [ ] Handoff: the CI Chromium shards after the push run the narrowed suite; their pass and shard durations against the last run before the push are recorded by the coordinator, not required for done.
