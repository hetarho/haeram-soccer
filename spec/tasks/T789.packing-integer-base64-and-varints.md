# T789 base64 and variable-length integers in the save packing with integer operations
> st:todo | ssot:SAVE-3 | base:ARCH@38 | dep:- | touches:apps/web/src/adapters/packing.ts apps/web/src/adapters/packing.equivalence.test.ts | lane:codec-speed-2

## goal
The save packing's own base64 and variable-length integer helpers stop working one character or one floating-point division at a time, with byte-identical output and the same validation, like T780 did for the bit columns.

## acceptance
- [v] `packing.ts`'s `base64`/`unbase64` use the same loop approach as `bitpacking.ts` after T780 (same validity checks and error messages); the LEB128-style helpers use integer shifts while values fit in 31 bits and keep the exact path above
- [v] a new unit test compares a frozen copy of the old helpers with the new ones byte for byte over seeded inputs (empty, single byte, all byte values, large buffers; varints 0, 1, 127, 128, 2^31−1, 2^31, 2^53−1, negative or invalid inputs as today) and that malformed input throws the same errors
- [v] the existing codec tests pass by path: `packing.test.ts`, `matchModelPacking.test.ts`, `careerPacking.test.ts`, `identityPacking.test.ts`, `managerHistoryPacking.test.ts`, `bitpacking.test.ts`
- [v] an interleaved old-vs-new timing probe on a real save reports the speed-up with its spread
- [v] `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`, `pnpm run validate:i18n`

## impl notes
- from review/test-value-261110 (T780 review P3): `packing.ts` keeps its own `base64`/`unbase64` with the spread and per-character callback and floating-point varint helpers.
- No new prose; error messages are existing source-message IDs (AGENTS.md).

## result
- outcome: `packing.ts`'s `base64` is `bitpacking.ts`'s loop (standard alphabet and `=` padding written as ASCII codes into one `Uint8Array`, turned into text by one `TextDecoder` call; no 32 K-argument `String.fromCharCode` spreads, no `btoa`); `unbase64` keeps its own regex and message `copy.packing.0e84000039`, still decodes with `atob` (so whatever `atob` refuses still throws the same `InvalidCharacterError`) and fills a `Uint8Array` with a `charCodeAt` loop instead of the per-character `Uint8Array.from` callback. `integers` reads the same row-to-column index formula in a plain loop (fractional or zero widths give exactly what they gave), validates each value with the same check and message, and writes values below `INTEGER_LIMIT` (2^31) with `& 127`/`>>> 7` into a growing `Uint8Array`; values from 2^31 to 2^53−1 keep the old `% 128`/`Math.floor(/ 128)` loop. `reader` decodes with `|`/`<<` up to a fifth byte of 7 (2^31−1); a fifth byte above 7 continues on the old exact floating-point arithmetic (scale 2^28 then ×128, the same eight-byte limit, truncation and overflow checks and messages), and the column-to-row transpose fills a preallocated array with the same index formula; `take`/`done` are unchanged. `integers` and `reader` are exported for the test only. No prose was added. `packing.equivalence.test.ts` (unit tier: not listed in `tests/config/test-tiers.ts`) holds a frozen copy of the four aeb2c618 helpers as the oracle and four seeded cases (engine `random`): base64 text and decoded bytes identical for the empty buffer, all 256 single bytes, 0–255 up and down, 40 random lengths 0–39, three views into a larger buffer, and 65,541- and 200,001-byte buffers; 522 `unbase64` inputs (22 hand-made including `null`/`undefined`/a number, whitespace, `-_`, Latin-1, bad padding, plus 500 random strings) give the same value or the same error class and message, both the regex message and `atob`'s `InvalidCharacterError`; LEB128 streams identical, and open/take/done traces identical, for each of 23 edges (0, 1, 127, 128, 2^14±, 2^21±, 2^28±, 2^30, 7·2^28, 2^31−1, 2^31, 2^32±, 2^35±, 2^42, 2^49±, 2^52, 2^53−1) alone and in three columns, `-0`, empty input, 400 seeded tables (widths 1–9, up to 40 rows, random takes) read back to their input, and a 200,006-value stream; 18 invalid values or widths (negative, fractional, NaN, ±Infinity, 2^53, a string, `undefined`, `null`; fractional/zero/negative/NaN widths, some of which encode without error) give the same outcome; 1,521 read streams (21 hand-made: truncations in the integer and exact bytes, a ninth byte, eight-byte values 2^53−1, 2^53 and 2^56−1, fifth bytes 7 and 8, overlong encodings, widths 0/1.5/−2, plus 1,500 random byte strings biased to continuation bytes) give identical open/take×10/done traces, covering all seven `copy.packing` IDs of these helpers. Mutation checks (scratchpad `t789/mutate.mjs`): fifth-byte threshold 16, `INTEGER_LIMIT` 2^33, pad `A`, dropping the read mask, or `n > 128` in the encoder each fail 1–3 of the four cases. Timing probe (scratchpad `t789/probe.mts`, tsx/Node, old = aeb2c618 `packing.ts` copied with absolute imports, order alternated per rep after 3 warm-ups each, host load average ≈ 2 after 19:00; the probe first checked that both pack each save to the same canonical text, unpack to the same world, and re-encode and re-read every real stream identically): prepared save `manager-journey` (19 LEB128 streams, 27,423 cells, none ≥ 2^31, 44,520 base64 characters), 21 reps: stream encode 4.3 ms (3.9–9.8) → 0.6 ms (0.5–0.7), paired ×7.4 (IQR 7.1–8.0); decode 6.0 (5.4–11.4) → 0.8 ms (0.7–8.3), ×7.1 (IQR 6.9–7.5); both ×7.2 (IQR 7.0–7.8, range 1.2–13.1); whole `pack`+`unpack` 443.7 ms (398.3–938.2) → 416.8 ms (361.3–469.5), ×1.05 (IQR 1.00–1.10). `manager-activation` (12,747 cells), 21 reps: streams 4.6 → 0.6 ms, ×7.2 (IQR 6.6–7.5); `pack`+`unpack` 162.4 → 158.4 ms, ×1.02 (IQR 1.01–1.06). `simulatedWorld({}, { seasons: 1 })` (11,577 cells), 15 reps: streams 4.2 → 0.6 ms, ×6.7 (IQR 6.5–7.0); `pack`+`unpack` 153.5 → 147.3 ms, ×1.04 (IQR 1.02–1.05).
