## goal
The save packing's own base64 and variable-length integer helpers stop working one character or one floating-point division at a time, with byte-identical output and the same validation, like T780 did for the bit columns.

## acceptance
- [ ] `packing.ts`'s `base64`/`unbase64` use the same loop approach as `bitpacking.ts` after T780 (same validity checks and error messages); the LEB128-style helpers use integer shifts while values fit in 31 bits and keep the exact path above
- [ ] a new unit test compares a frozen copy of the old helpers with the new ones byte for byte over seeded inputs (empty, single byte, all byte values, large buffers; varints 0, 1, 127, 128, 2^31−1, 2^31, 2^53−1, negative or invalid inputs as today) and that malformed input throws the same errors
- [ ] the existing codec tests pass by path: `packing.test.ts`, `matchModelPacking.test.ts`, `careerPacking.test.ts`, `identityPacking.test.ts`, `managerHistoryPacking.test.ts`, `bitpacking.test.ts`
- [ ] an interleaved old-vs-new timing probe on a real save reports the speed-up with its spread
- [ ] `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`, `pnpm run validate:i18n`
