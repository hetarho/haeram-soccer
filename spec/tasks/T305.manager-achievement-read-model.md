## goal
Answer which factual accomplishments belong to each own-club tenure without sending every historical match to the browser UI.

## acceptance
- [ ] Derive tenure summaries from T304's canonical links and existing live/archived results: actual league/cup titles, promotions, best final league rank per country/tier/group, recorded 90-minute W-D-L and win rate with its denominator, and longest winning/unbeaten runs across official own competitions. All-time own-match input is used, not the UI's short match window.
- [ ] Keep separate reappointments and interims, cup-final versus season-close attribution, and explicit shared-season context. Winning/unbeaten runs may cross seasons only within one tenure; a manager change or unattributed match breaks continuity. Include run endpoints, relevant seasons and ongoing status; current league standings/promotion zones are not completed honours.
- [ ] Expose complete, partial and unavailable coverage distinctly, including an honestly tracked zero. Preserve known service dates separately from tracking dates. Older raw appointment/departure entries stay readable without matching names to manufacture tenure IDs, and repeated reads do not rewrite old attribution.
- [ ] Add a bounded `manager-history` worker read and client method, with newest-first cursor pages and stable tenure/event row keys. Replies include summary values, coverage, relevant season/competition/division identifiers and continuation state, never full match archives. The read can run between queued simulation steps with the existing session checks; it creates no command receipt, revision, clock step, RNG draw or save write and works in a read-only game session.
- [ ] Regular projections still omit heavy manager-history fact arrays and read-model caches. A response is scoped to the active world/session; switching games or a stale async response cannot insert another club's history, and pagination never deletes canonical records.
- [ ] `manager-achievements.test.ts` covers `uses all retained matches`, `penalty win is a 90-minute draw for runs`, `same manager crosses a season but not a reappointment`, `unattributed match breaks a run`, `cup title does not move to the closing manager`, `different divisions do not share a best rank`, `partial zero differs from no achievements`, and `read is deterministic and does not mutate canonical state`.
- [ ] Runtime/protocol/client tests cover bounded multi-page history, invalid/stale cursors and sessions, a readable legacy-only career, read-only access, no unsolicited projection/receipts, queued-step reading and game-switch response isolation. Task-tier checks and build pass under ARCH-30; full suites/browser execution stay with the batch.

## impl notes
- Define `ManagerHistoryPage` and discriminated tenure/legacy-event view rows in `packages/contracts/src/manager-history-view.ts`; T304's fact types remain the sole attribution source. The engine's `manager-achievements.ts` owns `managerHistoryPage`, shared by every consumer rather than duplicating attribution in React.
- Add `{ type: 'manager-history', cursor?: string }` to the existing read-request union and `managerHistory?: ManagerHistoryPage` to replies. `client.managerHistory(cursor?)` uses the same request correlation/session isolation as `archive`; bridge protocol version remains unchanged. Legacy event cursors are based on retained event order, never a parsed display name.
- Define `MANAGER_HISTORY_VIEW_CONFIG` here with `pageSize: 20`. An omitted cursor starts the newest page; an unknown cursor returns a readable retryable query error. Return `nextCursor` only when more rows exist. Aggregate compact results in one pass over retained matches/outcome references before slicing a page, avoiding a full career scan per tenure; any memoisation is transient and invalidated by all relevant fact/manager/season changes, including changes within a league round.
- Count each own match once under its frozen tenure and use `regulation ?? score` for the own side's W-D-L/runs. Label the scope as all official competitions/90 minutes; keep the actual sample count and tracked-from boundary with partial results. Choose best ranks within the same country/tier/group and retain tied source seasons for context.
- Accomplishment source links name the recorded club season and its competition scope. A league final rank is the team's season outcome, not a claim that a mid-season manager coached its entire W-D-L; those figures come only from individually attributed matches.
- Include old unstructured personnel events as distinct narrative rows with unavailable accomplishment attribution, and preserve the post-tracking appointment/departure details through the structured tenure/source links. Do not duplicate the same current manager as both a new tenure and a synthetic legacy tenure. Use shared small fixture worlds for numerical/read-path tests.
