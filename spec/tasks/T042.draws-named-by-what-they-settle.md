# T042 Draws named by what they settle
> st:todo | ssot:ARCH-5 CLUB-20 | base:ARCH@8 CLUB@16 | dep:- | touches:packages/engine/src/care.ts packages/engine/src/operations.ts packages/engine/src/transfers.ts packages/engine/src/care.test.ts packages/engine/src/operations.test.ts packages/engine/src/transfers.test.ts | lane:-

## goal
No random draw, and no ID a draw is keyed by, reads the command counter `w.revision`; reading the inbox or any bookkeeping command changes no later outcome.

## acceptance
- [ ] Owner requests draw from `${seed}:care:${kind}:${year}:${round}` (care.ts resolveCare); every request kind has a cooldown of at least 3 rounds, so the key is unique per use.
- [ ] A caretaker manager is drawn from `${seed}:interim:${year}:${day}:${n}` (operations.ts), n = the club's manager-departure events so far.
- [ ] Campaign IDs are `${year}:${round}:${kind}` (operations.ts campaign command); an active campaign of the same kind already blocks a second start.
- [ ] Outgoing bid IDs are `out:${year}:${day}:${n}:${playerId}` (transfers.ts placeBid/bidId), n = earlier outgoing bids for that player this season, so a renewed bid on the same day still gets a new ID.
- [ ] No non-test engine source uses `w.revision` inside a `random(...)` key or an ID that feeds one (`grep -n "revision" packages/engine/src/*.ts` shows only counter increments and the protocol check).
- [ ] transfers.test.ts "an inbox read does not change a bid": two worlds equal except one ran `operate(w, { type: 'read-inbox' })` before the same bid get the same bid ID, due day and answer.
- [ ] care.test.ts "an inbox read does not change a request": the same request after an extra inbox read gives the same outcome.
- [ ] operations.test.ts: a campaign's ID and settled result do not depend on earlier commands.
- [ ] `pnpm run typecheck && pnpm run test:unit` pass.

## impl notes
- `w.revision` stays the world's write counter for the host's stale-request check (→ARCH-6); only draws and draw-feeding IDs stop reading it.
- IDs already stored in saves (campaigns, bids) keep their old form; only new ones use the new form. Stored campaign results keep drawing from their stored ID.
- Portable goldens (`tests/fixtures/portable-v1.json`, `pnpm run test:contract`) may change: do not regenerate them here; T047 does it once for the group. test:contract is outside this group's task and unit checks.
- No rules version bump here; T047 bumps to 1.15.0.
