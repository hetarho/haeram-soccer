# T722 reject host transcendental Math in engine and contracts source
> st:todo | ssot:ARCH-5 ARCH-9 ARCH-30 | base:ARCH@33 | dep:- | touches:eslint.config.mjs packages/engine/src/kit-patterns.ts | lane:dev-cost

## goal
A host `Math.exp/log/sin/…/hypot/pow` call in engine or contracts source fails `pnpm run lint` at task time, pointing to `portable-math.ts`, so linux-x64 and darwin-arm64 cannot diverge again through one (review/self-improve-local-261109 F3); the last four direct calls move to the portable implementation with identical results.

## acceptance
- [ ] `eslint.config.mjs` has its own appended block (the Feature-Sliced layer rules at the top stay untouched) with `no-restricted-properties` on `Math` for exp, expm1, log, log1p, log2, log10, sin, cos, tan, asin, acos, atan, atan2, sinh, cosh, tanh, asinh, acosh, atanh, cbrt, hypot and pow in `packages/engine/src/**` and `packages/contracts/src/**`, excluding tests and `portable-math.ts` itself, with a message naming `portable-math.ts`
- [ ] `packages/engine/src/kit-patterns.ts`'s four `Math.hypot` calls use `portable-math.ts`'s `hypot`; no other engine behaviour changes
- [ ] results identical: `pnpm run test:contract` passes with the portable golden file unchanged, and the kit-pattern and portable-math unit tests pass
- [ ] `pnpm run lint`, `pnpm run typecheck`, `pnpm run format:check` pass with no disable comment added; a deliberately inserted `Math.cos` in an engine file fails lint (checked, then removed)

## impl notes
- If lint finds other real calls (not comments), route them the same way only when `portable-math.ts` documents bit-equality with V8 for that function; otherwise stop and report them instead of changing results (a results change is a model change, →SAVE-23).
- `**` with non-integer exponents is out of scope (inbox 261108 T713 suggestion).
