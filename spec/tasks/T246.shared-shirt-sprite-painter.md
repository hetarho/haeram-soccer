## goal
Create one bounded Canvas painter for large samples and actual match-scale shirts without changing the live pitch yet.

## acceptance
- [v] The painter applies the shared main field, secondary polygons, circular clip and optional trim; KitSwatch uses this same painter and provides a meaningful accessible label.
- [v] kitPainting.test.ts cases reuses an identical style-size-DPR sprite, invalidates for changed secondary/trim/DPR, and evicts beyond its fixed 128-entry bound pass.
- [v] Tests with a recording Canvas context verify clipping is restored and number/outline drawing does not leak state to the next side; they do not merely assert a helper returns its input.
- [v] A minimal offscreen canvas factory can be injected in the painter test; production uses normal Canvas without adding a DOM-test or graphics dependency.
- [v] The sprite cache contains no players, world references, fixture history or rAF callbacks. Player position and animation remain owned by Pitch.
- [v] Actual pixel checks are scheduled in the later browser integration task; this task does not claim visual parity from mock drawing calls alone.
- [v] Targeted verification passes: `pnpm exec vitest run apps/web/src/ui/kitPainting.test.ts packages/engine/src/kit-patterns.test.ts && pnpm run typecheck`.

## impl notes
- Read `docs/CLUB-IDENTITY-CONTRACT.md` sections named below; it owns the stable interfaces used in this task.
- Prerequisites: T238. Read their implemented interfaces/results before editing; extend those modules rather than reproducing a prerequisite.
- Read design §§4 and 7. Define a small createKitPainter(canvasFactory?) with draw(ctx, shirt, x, y, radius, options) and bounded internal sprite cache. Keep its instance stable per mounted preview/pitch.
- Cache style backgrounds, not names or numbers. Keys include every visible style field, pixel size and DPR; cap at 128 entries with deterministic FIFO eviction.
- Use shirtPatternRegions for polygons and the same normalized trim ring as shirtColourAt. Build paths/textures once per cache entry, not once per player per frame.
- Draw the readable number and a stable side outline after blitting the shirt, inside save/restore. Existing selection rings are added by Pitch outside this painter.
- No imagegen, uploaded image, network asset, data URL stylesheet, full player sprite overhaul or new animation engine is necessary.

## result
- outcome: completed. `apps/web/src/ui/kitPainting.ts` exports `createKitPainter(canvasFactory?)` returning `{ draw(ctx, shirt, x, y, radius, options), size }`, with `KIT_SPRITE_LIMIT` (128), `spriteKey`, `spritePixels`, `describeShirt` and `SHIRT_PATTERN_LABELS` (Korean names of the eight patterns). A sprite is an offscreen canvas of `ceil(2·radius·DPR)` device pixels keyed by pattern, primary, secondary (dropped for `plain`, which shows none), trim, pixel size and DPR; it is painted once inside save/restore — circular clip, primary `fillRect`, one path of `shirtPatternRegions` polygons in the secondary, then the trim ring (outer radius and `SHIRT_TRIM_INNER`, `evenodd`) last — so all geometry comes from `kit-patterns.ts`. The cache is a `Map` of sprites only, FIFO (a hit does not refresh), evicting the oldest beyond 128. `draw` blits the sprite at `x−r, y−r, 2r, 2r` (CSS pixels under the caller's DPR transform), then, within one save/restore, an optional side outline (default width 1.2 as on the pitch) and the optional number in `inkOn` of `shirtColourAt` at the centre, with an opposite-ink halo (`strokeText`) on patterned shirts; numbers and outlines never enter a sprite. A missing offscreen context falls back to a solid primary marker. The default factory makes a normal DOM `<canvas>` lazily on the first sprite; types are structural (`KitPaintContext`, `KitContext<S>`, `KitCanvas`) so a real `CanvasRenderingContext2D`/`HTMLCanvasElement` and a test fake both fit without a DOM-test or graphics dependency. `KitSwatch.tsx` keeps one painter per mounted swatch (`useState`), sizes its canvas to the DPR (≤2) in a layout effect and draws through the same painter; it renders `role="img"` with the accessible name `"<label>: <pattern>, 주색 …, 보조색 …, 테두리 …"`. No App, Pitch or entry-loaded module imports either file yet (ARCH-28). kitPainting.test.ts (11 cases) uses a recording 2D context with a real save/restore state stack: the stripes sprite's clip/field/polygon vertices/trim ring against the shared geometry, plain with a stray secondary, the checks 3×3 cells, reuse of an equal style-size-DPR sprite and its blit rectangles, new sprites for changed secondary/trim/size/DPR/pattern, FIFO eviction past 128, no numbers/outlines in sprites, state fully restored with the second side drawn under the initial state and without the first side's outline, number ink on halves, the null-context fallback, and `describeShirt`.
