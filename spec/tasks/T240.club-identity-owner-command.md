## goal
Add a validated club-identity command that edits only the own club and retains normal revision, duplicate-request and autosave behavior.

## acceptance
- [v] Command and bridge accept {type: club-identity, identity}; no club-ID target parameter lets a caller edit an NPC.
- [v] identity-operations.test.ts cases applies a deep copied identity and primary alias, malformed edit leaves canonical world unchanged, and cosmetic edits preserve sporting outcomes pass.
- [v] All other clubs, existing match appearances, cash, date, players, standings and event history remain unchanged; only the own identity/color plus ordinary revision/receipt metadata may change.
- [v] protocol.test.ts rejects extra target fields, malformed colours and a future identity version before dispatch.
- [v] host.test.ts cases duplicate identity receipt has one effect and stale identity request does not overwrite newer work pass. The existing GameClient.command owner-decision save path is reused.
- [v] Targeted verification passes: `pnpm exec vitest run packages/engine/src/identity-operations.test.ts apps/web/src/runtime/protocol.test.ts apps/web/src/runtime/host.test.ts && pnpm run typecheck`.

## impl notes
- Read `docs/CLUB-IDENTITY-CONTRACT.md` sections named below; it owns the stable interfaces used in this task.
- Prerequisites: T237, T235. Read their implemented interfaces/results before editing; extend those modules rather than reproducing a prerequisite.
- Read design §5. Parse the whole identity first, then replace a structuredClone on clubOf(w) and set only its color to identity.colours[0]. Do not mutate a nested object referenced by an old snapshot.
- Add an explicit operate case and a leaf handler. operate already increments revision once; do not increment in the handler or publish a second ad hoc view.
- No addEvent, news, cash cost, game-time step, manager negotiation or progression-setting change is part of this cosmetic command. Keep the existing bankrupt/readonly protections.
- For neutrality, clone one valid world, edit one clone, advance both with identical commands and compare sporting projections after excluding visual fields, receipts and revision. Do not merely assert the edit handler did not call simulateMatch. The valid world comes from `simulatedWorld` in `tests/fixtures/worlds.ts`; only the edit and the identical advance are simulated (ARCH-21).
- The editor’s explicit representative-colour reuse remains a draft action; this engine command saves the complete selected identity and does not auto-recolour any shirt.

## result
- outcome: completed. `Command` (contracts `types.ts`) adds `{ type: 'club-identity'; identity: ClubIdentity }`, which has no club field. The worker request schema takes it as a `z.strictObject` holding the shared `clubIdentitySchema`, so a `club`/`clubId`/`target` key is refused, not stripped. New leaf `packages/engine/src/identity-operations.ts` imports only the contract identity leaf, `identitySchema` and `world`. Its `applyClubIdentity(w, identity)` checks the whole design with `clubIdentitySchema` first, then sets `clubOf(w).identity = structuredClone(identity)` and `club.color = identity.colours[0]` in the stored spelling. It replaces the identity object instead of changing it, so a snapshot that still holds the old object keeps it. It adds no event, news, cash, day or draw. `operate` has an explicit `club-identity` case and keeps its single `revision++` and its bankrupt refusal; the host's existing session/receipt/expected-revision path and `GameClient.command`'s immediate owner-decision save (`saveSoon` for every non-automatic command) are reused unchanged. Build sizes: the `settlement` chunk is unchanged at 66.80 kB gzip, `index` grew from 119.26 to 119.28 kB gzip and the worker from 1,991.73 to 1,992.10 kB raw, so zod did not move into a new chunk.

The engine cases are: a deep copy that is not the caller's object or the old one, where changing the input afterwards changes nothing; 11 malformed designs plus bankrupt each leaving `canonical(w)` unchanged; a command naming a rival club still edits only the own club, with revision +1 and every other field, including an own-match appearance aliasing the old crest object, canonically unchanged; neutrality, where a `simulatedWorld` clone is edited, both clones run `advanceDays(w, 7)` through our first match, and the sporting projection without identities, colours, appearances, receipts and revision is equal.
