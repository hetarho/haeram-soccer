## goal
The game runs rules 4.0.0; recognized careers of rules 3.0.0 and earlier are cleared once on writer activation (even though today's code can no longer unpack them) and the owner is told once.

## acceptance
- [ ] `CURRENT_ENGINE_VERSION = '4.0.0'`; `LEGACY_ENGINE_VERSIONS` adds `'3.0.0'`; the rules history comment gains a 4.0.0 line (grid engine, 16 attributes, discipline, in-match changes, post-match material).
- [ ] Legacy recognition does not depend on the current unpack/schema: `recognizedLegacy(raw)` accepts an envelope whose header engine is in `LEGACY_ENGINE_VERSIONS`, whose codec is known, whose payload decompresses within limits, whose SHA-256 checksum matches, and whose decompressed JSON has `format: 'compact1'` and a `world` object with the envelope's `id`/`engine`/`catalog`/`catalogHash` — without calling `unpack` or `validateWorld`.
- [ ] `resetLegacy` returns the number of games it cleared; `client.ts` `load()` adds one notice when it is > 0: `이전 규칙 커리어 {n}개를 정리했어요. 새 경기 엔진(규칙 4.0.0)으로 새 커리어를 시작하세요.` (WEB-66 store; the store already drops a duplicate unread notice).
- [ ] `legacyFixture.test.ts` (T200's fixture) now asserts `recognizedLegacy(raw) === true` and that `decode(raw)` fails with `SaveCompatibilityError` naming 4.0.0; `legacyReset.test.ts` gains `clears the frozen real rules 3.0.0 save and reports it` using that fixture; the other legacy fixtures (renamed current worlds) keep working.
- [ ] `schema.contract.test.ts` `refuses every recognized earlier gameplay version` expects `['4.0.0']` as supported; `save-upgrade.spec.ts` expectations change from 3.0.0 to 4.0.0 and pass (`pnpm exec playwright test --project=chromium tests/e2e/save-upgrade.spec.ts`).
- [ ] `pnpm exec tsx scripts/update-golden.ts --write` (header engine 4.0.0); README and `docs/SAVE-FORMAT.md` say 4.0.0; typecheck, lint, unit and contract tests pass.

## impl notes
- `readCheckpoint` (persistence.ts ~L50) already validates header, codec, catalog pin and checksum before calling `unpack`; split it into `readEnvelope(raw, engines)` (everything up to and including the checksum and JSON parse, returning `{ envelope, json }`) and the rest; `recognizedLegacy` uses `readEnvelope` and checks `json.format === 'compact1'` and `json.world` header fields.
- Catalog pins: a legacy save may pin a prior catalog; accept `CATALOG_VERSION` or `PRIOR_CATALOG_HASHES` keys exactly as `readCheckpoint` does.
- Keep the safety rules of SAVE-18: never clear on a read-only tab; future or unrecognized saves stay protected (SAVE-11).
