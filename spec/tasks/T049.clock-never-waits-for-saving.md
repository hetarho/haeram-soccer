# T049 Clock never waits for saving; background autosave cadence
> st:todo | ssot:SAVE-8 WEB-18 ARCH-13 | base:SAVE@20 WEB@50 ARCH@8 | dep:T048 | touches:apps/web/src/runtime/progression.ts apps/web/src/runtime/client.ts apps/web/src/runtime/store.ts apps/web/src/ui/App.tsx apps/web/src/runtime/progression.test.ts apps/web/src/runtime/client.test.ts apps/web/src/runtime/store.test.ts tests/e2e | lane:background-save

## goal
The clock steps one day per pace interval while automatic progress is saved in the background every 30 s of running clock and at once on stop, hide and close.

## acceptance
- [v] progression.ts `tick` no longer returns while `savedRevision !== revision` (line ~487); it still sends one command at a time (`inFlight` / `processing`).
- [v] An autosave scheduler in the client requests a background save (T048):
  - every 30 s of running clock while automatic progress is unsaved;
  - at once when the clock stops for any reason, on `visibilitychange` to hidden, and on `pagehide` (best effort);
  - at once after every owner decision.
- [v] Owed days only come from a step that itself ran late; ordinary steps at x10 advance one day each.
- [v] The save status (`App.tsx` saveText, data-testid save-status) shows when the game was last saved (e.g. `n초 전 저장`) instead of flipping between 저장 완료 and 저장 대기 on every step; the active/saved distinction stays readable (→SAVE-8).
- [v] The read-only tab notice (BroadcastChannel) still fires on every commit.
- [v] progression.test.ts with fake timers: a command resolving in 20 ms and a save taking 800 ms at x10 give one-day steps every 100 ms that never wait for the save, and a stop triggers a save.
- [ ] tests/e2e journeys that reload or open a second tab after advancing first stop the clock or wait for the save status; affected journeys pass in Chromium.
- [v] `pnpm run typecheck && pnpm run test:unit` pass.

## impl notes
- Unsaved automatic days hold no owner decision and replay identically after a reload (→ARCH-5); losing up to ~30 s of automatic progress on a crash is accepted (→SAVE-8).
- Keep the away-time catch-up (→WEB-64) working from the last saved world: it already plays the time away from the stored clock record.
- Save failures (quota, write) still stop unattended progress and offer export/retry (→ARCH-13, →WEB-31).
- e2e files commonly read save-status; search `save-status` and `저장 완료` under tests/e2e.
- No engine change and no version bump.

## result
- outcome: clock steps never wait for saving: `tick` dropped the saved-revision gate and a visible step carries owed days only after a step that itself outran the pace (or on return from time away); no command awaits its save any more: owner decisions (commands, founding, alert acknowledgement) call `GameClient.saveSoon()` at once, clock ticks arm one `AUTOSAVE_MS` (30 s) timer per unsaved run, and the clock's stop (including a step that lands after it), tab hide and `pagehide` save at once; a background save may queue behind a long command, so its request gets the checkpoint watchdog (60 s) instead of 15 s; save status reads `저장 완료` when all is on disk and otherwise `방금 저장`/`n초 전 저장` from `savedAt` (`저장 대기` when no save happened in this tab); `저장 재시도` shows only after a failed save (`saveFailed`); read-only tabs are still told of every commit
