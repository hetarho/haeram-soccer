## goal
The engine worker can open, create, list, export and delete game database files in an OPFS SyncAccessHandle pool through the official SQLite WebAssembly build, behind the `SqlDriver` of T1003.

## acceptance
- [ ] `@sqlite.org/sqlite-wasm` is a pinned root dependency (exact version, lockfile updated); it is loaded only inside the engine worker (dynamic import), never in the entry bundle (ARCH-28 entry budget unchanged).
- [ ] `apps/web/src/adapters/sqliteWasm.ts` exports `openGamePool()` (installs the `opfs-sahpool` VFS once, name `haeram-soccor-games`, capacity ≥ 8 files), `gameDriver(pool, fileName): SqlDriver`, `exportFile(pool, fileName): Uint8Array`, `importFile(pool, fileName, bytes)`, `deleteFile(pool, fileName)`, `listFiles(pool)`, `pause/unpause(pool)`; file names are `/game-<gameId>.sqlite3` and `/backup-<gameId>-a|b.sqlite3`.
- [ ] Missing OPFS (`navigator.storage.getDirectory`/`FileSystemSyncAccessHandle`) or a failed VFS install produces a typed capability error with a localized message (ARCH-11/17), not a crash.
- [ ] `apps/web/public/_headers` CSP `script-src` adds `'wasm-unsafe-eval'`; `vite.config.ts` excludes the package from `optimizeDeps` and the production build emits the wasm asset; `vibe check --allow-final -- pnpm run build` passes (record the command in result verified).
- [ ] Task stage, owner implementer: `vibe check --tier task` passes. Browser behaviour (OPFS) is an integration handoff: add `tests/e2e/sqlite-store.spec.ts` that creates, writes, reopens and deletes a game file in the preview build; record it as not run locally (ARCH-30).

## impl notes
- Install with `pnpm add -E @sqlite.org/sqlite-wasm` at the repository root (root `package.json` owns app dependencies); use the current stable release and record it.
- Init: `const sqlite3 = await sqlite3InitModule(); const pool = await sqlite3.installOpfsSAHPoolVfs({ name: 'haeram-soccor-games', initialCapacity: 8 }); new pool.OpfsSAHPoolDb(fileName)`. The SAH pool needs no COOP/COEP headers (ARCH-11). Wrap `oo1.DB` in `SqlDriver` (`exec`, `run` via prepared statements, `all`/`get` with `rowMode: 'object'`, `transaction` with `BEGIN IMMEDIATE`/`COMMIT`/`ROLLBACK`).
- Only one tab may hold the pool at a time; T1011 pauses and unpauses it on takeover.
- `host.ts` gets a lazily created pool handle (no behaviour change yet; T1006 opens games through it).
- New copy (capability error) follows AGENTS.md localization: message IDs in `packages/contracts/src/source-messages.ts` and every locale pack.
