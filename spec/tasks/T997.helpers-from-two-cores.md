## goal
A device with two or more cores starts two fixture helpers, never one, and on a round day the engine worker computes its own share of the other fixtures once our match is played; worlds stay identical with and without helpers.

## acceptance
- [ ] `HELPER_CONFIG` starts two helpers from `hardwareConcurrency` 2 (minCores 4→2, count 2); one core or an unknown count starts none (deterministic; worker, task stage).
- [ ] `HelperPool.run` gives the engine worker a share computed after our match with the same round-job code the helpers run, and resolves every result in job order; a failing or late helper still ends helper use and the engine worker computes the rest (helperPool.test.ts) (deterministic; worker, task stage).
- [ ] Identical worlds: fixtureHelpers.integration.test.ts plays a season each way — no helpers, two helpers, two helpers with the engine share — and finds the worlds equal (deterministic; worker, task stage).
- [ ] Measured round-day wall time on this Linux host pinned with `taskset -c 0,1`, `taskset -c 0-2` and unpinned: no helpers, the current setup and the new one, through scripts/perf/helpers.mjs, kept in artifacts/benchmarks/x10-cost-levers/T997. If two helpers measure slower than none on two cores, minCores stays at the lowest core count where they measured faster and the result says so for the owner (deterministic; worker, task stage).
- [ ] ARCH-30 task-tier checks pass through `vibe check --tier task`; the full batch stays with the landing gate (handoff only).
