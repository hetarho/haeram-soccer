## goal
One shared painter draws a posed top-down human figure wearing a `WornKit` or `WornKeeper`, with size-dependent detail and readable number tags, for match observation and kit previews alike.

## acceptance
- [ ] `createFigurePainter()` returns `{ draw(ctx, pose, kit, options) }`. It draws, bottom to top: shadow, legs with socks and boots, shorts, arms with sleeves in shirt colours and skin or gloves, torso, and the hair-covered head with a small facing cue (MATCH-36).
- [ ] The torso shows the shirt's pattern and trim through `figureShirtColourAt` and `FIGURE_TORSO` from `kit-patterns.ts`, so painted colours agree with what selection samples (KIT-7). All eight patterns paint distinctly at the large sample size.
- [ ] Detail reduces in steps by torso width in device pixels (`FIGURE_LOD`). The smallest step keeps team colours, facing and limb silhouettes (MATCH-36 scale rule).
- [ ] `playerLook(id)` returns a stable skin tone and hair colour and style from a palette by ID hash. It carries no gameplay meaning (MATCH-36).
- [ ] `numberTags.ts`: `placeNumberTags(figures, bounds)` deterministically picks, for each figure, one of eight non-rotating offsets with the least overlap with other tags, figures, the ball and the carrier cue; `drawNumberTag(ctx, tag, options)` draws it readably on every theme.
- [ ] Painting draws only. It never changes a pose, position or kit. Static parts may be cached up to `FIGURE_SPRITE_LIMIT` entries keyed by kit, detail step and DPR.
- [ ] Unit tests in `figurePainting.test.ts` (recording 2D context in the style of `kitPainting.test.ts`): "draws layers in order", "torso sample points use the shirt geometry colours", "keeper draws gloves", "detail steps by torso width", "same look for the same id", "cache is bounded".
- [ ] Unit tests in `numberTags.test.ts`: "tags never rotate", "crowded figures get distinct offsets", "placement is deterministic".
- [ ] ARCH-30 task tier passes (typecheck, lint, format:check, changed unit tests) and `pnpm run build`.

## impl notes
- Reference drawing: prototype B (`/private/tmp/claude-501/-Users-seonghyunkim-Desktop-2026-PROJECTS-Game-haeram-soccer/d2497f8e-476a-4647-ba31-f8d1e8400aeb/scratchpad/kit-proto/b/index.html`, `drawPlayer`, its LOD and caches). Replace its independent pattern drawing with the shared torso geometry from T542: `FIGURE_TORSO`, `insideFigureTorso`, `figureShirtColourAt` and `shirtPatternRegions` mapped onto the torso box.
- `draw(ctx, pose: FigurePose (T543), kit: WornKit | WornKeeper (T542), options)`. The options are:
  - `{ x, y }`: the centre in CSS px.
  - `radius`: half the torso width in CSS px. Callers pass today's `markerRadius(width)` so the torso keeps the current marker scale (MATCH-36).
  - `dpr`, `look: PlayerLook`.
  - `outline`, `outlineWidth`: theme skin tokens (WEB-91).
  - `ball?`: its socket drawn by the caller.
  - A `WornKeeper` paints gloves on the hands.
- `FIGURE_LOD`: steps by torso width in device px, numbers defined here. ≥ 40 px is full (hair strands, sleeve cuffs, boot detail, shading); 18–40 px drops the strands and cuffs; below 18 px leaves flat colour areas, the pattern's largest regions, limb outlines and the facing cue.
- `FIGURE_SPRITE_LIMIT` = 128, oldest out first, the same policy as `KIT_SPRITE_LIMIT` in `kitPainting.ts`.
- `PlayerLook { skin; hair; style }`. The palettes are defined here; the skin palette covers a broad, natural range. The hash is a local FNV-1a.
- `numberTags.ts`:
  - `NumberTagInput { id; number; x; y; radius }`, `placeNumberTags(inputs, { width, height, avoid: [x, y, r][] })`.
  - `TAG_OFFSETS` (8 directions) and `TAG_CONFIG` (font scale, padding, minimum gap) are defined here.
  - Text and backplate come from the pitch skin tokens the caller passes, so every theme stays readable.
- Keep both modules free of React and engine orchestration (ARCH-4). They import contracts types, `kit-patterns`/`kit-wear` leaves and `figurePose` types only.
- `kitPainting.ts` stays for the tactical diagrams and swatches.
