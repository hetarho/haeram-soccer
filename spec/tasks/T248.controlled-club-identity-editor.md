# T248 Build accessible controlled crest and shirt editing panels

## goal
Expose the agreed design controls in one controlled component that works for both founding and career editing.

## acceptance
- [v] ClubIdentityEditor implements the value/onChange/readonly interface in design §7 and uses the pure reducer rather than mutating value or talking to the worker.
- [v] Six preset crests, optional 직접 꾸미기, shape/field/emblem choices, home/away/third and the eight shirt patterns are reachable with labelled controls and visible selected states.
- [v] Colour controls correspond to visible regions: one-to-three representative colours, applicable crest colours, main/pattern/optional trim for the selected shirt, and an explicit 대표색 적용 action.
- [v] A one-colour crest visibly explains its fixed neutral outline/negative space; no extra random secondary is hidden behind the SVG. Shorts, socks, goalkeeper, upload and sponsor controls are absent.
- [v] identityEditorMarkup.test.ts uses server rendering for meaningful boundary cases one-colour disclosure has no hidden editable colour, readonly disables mutation controls, and selected-role labels match the actual controlled value.
- [v] Parent apply/cancel/persistence is deliberately left to later wrappers; the new component typechecks and its pure model tests still pass.
- [v] Targeted verification passes: `pnpm exec vitest run apps/web/src/ui/identityEditorMarkup.test.ts apps/web/src/ui/clubIdentityDraft.test.ts apps/web/src/ui/identityCrest.test.ts && pnpm run typecheck`.

## impl notes
- Read `docs/CLUB-IDENTITY-CONTRACT.md` sections named below; it owns the stable interfaces used in this task.
- Prerequisites: T245, T246, T247. Read their implemented interfaces/results before editing; extend those modules rather than reproducing a prerequisite.
- Read design §7 and use the shipped Select/Dialog styling conventions, semantic fieldsets/legends and real buttons. The component itself does not open a dialog, own an applied identity, save to storage or start simulation.
- Keep optional composer-open state and selected role as local UI state; every design change dispatches a typed reducer action and returns a new complete value through onChange.
- Use colour inputs with visible text values and region labels; changing a role cannot copy the previous role’s edits into another shirt. Show main/secondary only where their regions exist and offer explicit add/remove for optional accent/trim.
- Show the large sample via KitSwatch and the crest via CrestMark. Use a preview children/slot prop if necessary; the next task supplies the actual pitch preview.
- The markup test uses createElement/renderToStaticMarkup in .test.ts so the existing Vitest include patterns discover it. Keep interactive assertions in the real browser wrappers rather than adding a DOM-test dependency.
- Maintain 44px primary targets and reachable internal vertical scrolling at 360x740/390x844. SSR tests check real semantics; interactive browser evidence belongs to the later founding/management tasks, not a shipped test-gallery route.

## result
- outcome: completed. New `apps/web/src/ui/ClubIdentityEditor.tsx` exports `ClubIdentityEditor({ value, onChange, readonly })`. Every change goes through `reduceIdentityDraft` (T247), and `onChange` is called only with a new complete identity, never when an action is refused. It imports no worker, storage, GameClient, dialog or simulation code. It also exports the Korean labels `KIT_ROLE_LABELS` (홈/원정/서드), `CREST_SHAPE_LABELS`, `CREST_PATTERN_LABELS` and `CREST_EMBLEM_LABELS`; shirt patterns reuse `SHIRT_PATTERN_LABELS` from `kitPainting`. Layout, in three fieldsets with legends:
  - 대표색: one field per colour (대표 주색/보조색/강조색), 빼기 on the second and third, and 대표 보조색/강조색 추가 while fewer than three. A note says changing them leaves the crest and shirts unchanged and that 대표색 적용 copies them into a shirt.
  - 엠블럼: a large `CrestMark` preview (`엠블럼 미리보기: <shape> · <emblem>`) and the six ready-made crests as pressed buttons, each previewing the crest it would produce. 엠블럼 색 has 바탕색 (field and disc), plus 무늬색 (pattern and ring) and 엠블럼색 only when present, each removable, or explicit 무늬색/엠블럼색 추가 buttons when absent. A disclosure always states the fixed neutral outline, and for a one-colour crest says the pattern, ring and (without accent) emblem are left empty so the background shows. 직접 꾸미기 is a disclosure (`aria-expanded`) holding 모양 (6), 바탕 무늬 (10) and 엠블럼 모양 (20) pressed choices; it opens on its own when the crest matches no preset.
  - 유니폼: 홈/원정/서드 role buttons (local state, each with its own `KitSwatch`), a large 96 px `KitSwatch` with sample number 10, and a note that goalkeeper colours are chosen automatically per match. `<role> 유니폼 무늬` has the eight patterns, each previewing what the reducer would produce, including an explicit secondary. `<role> 유니폼 색` has 주색, 보조색 only for patterned shirts, and 테두리 with 빼기 (or 테두리 추가), plus 대표색 적용 with a description saying it changes only this shirt.
  Each colour field is a labelled colour picker plus its visible `#RRGGBB` text. Invalid text stays local (`aria-invalid`, alert message) and dispatches nothing. Role-specific fields are keyed by role, so typed text never carries over to another shirt. A newly added optional colour starts visibly from a representative colour, else the first unused palette colour; nothing is hidden or random. Read-only shows a note and disables every input and change button; the role selector and 직접 꾸미기 toggle stay usable for inspection. There are no shorts, socks, goalkeeper, upload, sponsor, apply or cancel controls. `ClubIdentityEditor.module.css`: 44 px minimum targets for choices, colour inputs and actions, wrapping grids, no fixed heights, so the parent dialog/tab scrolls; pressed choices take the accent border. New `identityEditorMarkup.test.ts` (6 cases, `createElement`/`renderToStaticMarkup`):
  - preset/role/pattern labels and pressed states, and none of those forbidden controls;
  - a composed crest opens the composer with 6/10/20 choices and the right ones pressed;
  - a one-colour crest has only the 바탕색 inputs and explicit add buttons, the disclosure text, and a preview painting only its primary outside the mask; also the accent-only and two-colour cases;
  - read-only disables every input and every button except role and composer, the writable editor disables none, and values stay visible;
  - selected-role swatch labels and colour fields match the controlled home shirt without the other roles' colours; a plain shirt has no 보조색 and a removable 테두리; the 체크 preview names the supplied secondary;
  - one, two and three representative colours with the right add/remove buttons.
