## impl notes
- Read `docs/CLUB-IDENTITY-CONTRACT.md` sections named below; it owns the stable interfaces used in this task.
- Prerequisites: T245, T246, T247. Read their implemented interfaces/results before editing; extend those modules rather than reproducing a prerequisite.
- Read design §7 and use the shipped Select/Dialog styling conventions, semantic fieldsets/legends and real buttons. The component itself does not open a dialog, own an applied identity, save to storage or start simulation.
- Keep optional composer-open state and selected role as local UI state; every design change dispatches a typed reducer action and returns a new complete value through onChange.
- Use colour inputs with visible text values and region labels; changing a role cannot copy the previous role’s edits into another shirt. Show main/secondary only where their regions exist and offer explicit add/remove for optional accent/trim.
- Show the large sample via KitSwatch and the crest via CrestMark. Use a preview children/slot prop if necessary; the next task supplies the actual pitch preview.
- The markup test uses createElement/renderToStaticMarkup in .test.ts so the existing Vitest include patterns discover it. Keep interactive assertions in the real browser wrappers rather than adding a DOM-test dependency.
- Maintain 44px primary targets and reachable internal vertical scrolling at 360x740/390x844. SSR tests check real semantics; interactive browser evidence belongs to the later founding/management tasks, not a shipped test-gallery route.
