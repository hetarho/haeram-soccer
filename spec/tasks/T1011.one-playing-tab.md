## goal
A second tab never opens the game database: it shows that the game is playing in another tab with 여기서 이어 하기, which makes the playing tab save, close the database, release the pool and the lock, and hand the game over.

## acceptance
- [ ] On start, a tab that cannot take the `haeram-soccor:writer` Web Lock shows a full-page state "다른 탭에서 플레이 중" with 여기서 이어 하기 instead of a read-only game; it never installs the SQLite pool.
- [ ] 여기서 이어 하기 posts a takeover request on the `haeram-soccor:updates` BroadcastChannel; the playing tab stops the clock, saves, closes the database, pauses the pool (T1005 `pause`), releases the lock and shows that the game moved to another tab, offering to take it back the same way; the requesting tab waits for the lock, unpauses/installs the pool and opens the game.
- [ ] If the playing tab does not answer, the requesting tab keeps waiting for the lock and says so; it takes the game once the lock frees (tab closed).
- [ ] Both moves add a 시스템 notification (WEB-66); the language/theme preferences work in the waiting tab (WEB-90).
- [ ] Unit tests (lock and channel stubs as in `client.test.ts:218-251`) cover takeover, give-back and unanswered request.
