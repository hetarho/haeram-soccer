## goal
Every player off the ball has a football target — formation shape by phase and tactic, role habit, block height, ball-side shift, pressing, marking or a run — and moves toward it at a speed his pace and legs allow.

## acceptance
- [ ] `grid/shape.ts` exports `SHAPE_CONFIG` (design §4.2 values), `targetOf`, `moveAll`, `startRuns`, `offsideLine`, `lineX`.
- [ ] `grid/testkit.ts` (test helper, not exported from the engine index) builds `{ w, f, setup, state }` for a top-tier NPC fixture with chosen tactics.
- [ ] `shape.test.ts` cases:
  - `holds each tactic's defensive line inside its bounds` (DF-line targets out of possession stay within `line` for ball x 10…95)
  - `pushes the possession and press shapes higher than counter` (mean outfield target x in possession: press ≥ possession > balanced > counter; out of possession: press > possession > balanced > counter)
  - `sends the nearest player within pressing distance at the ball` and `adds a second presser only under press`
  - `counter-presses for five seconds after a loss`
  - `moves an inverted full-back inward and a false nine back in possession` (role shift applied only in possession)
  - `shifts the block toward the ball side`
  - `starts runs in behind for forwards and overlaps for overlapping full-backs` (over 2000 decisions with the ball in band ≥ 3: behind runs only by FW/AM/shadow strikers, overlaps only by overlapping FB/attacking WB; deterministic for a seed)
  - `never moves a player faster than his pace allows` (one `moveAll(dt)` step ≤ `speed × dt` + 1e-9)
  - `keeps a sweeper keeper higher than a shot stopper behind a high line`
- [ ] `pnpm run typecheck`, `pnpm run lint`, the test file pass.

## impl notes
- Follow design §4 exactly; all positions in the state are engine frame — convert with `attackFrame(side, …)` before applying a side's shape and back after.
- Signatures:
  ```ts
  export function lineX(s: GridState, side: 0 | 1, line: 'DF' | 'MF' | 'FW'): number;   // mean x of that side's on-pitch outfield players of the line, in that side's attack frame
  export function offsideLine(s: GridState, defendingSide: 0 | 1): number;              // x of the second-last defending player (GK counts), in the ATTACKING side's frame
  export function targetOf(s: GridState, side: 0 | 1, idx: number): [number, number];  // engine frame
  export function startRuns(s: GridState, side: 0 | 1, r: () => number): void;         // design §4.3 runs, roster order, one r() per eligible player
  export function moveAll(s: GridState, dt: number): void;                              // every on-pitch player except the owner
  ```
- Phase for the shape: in possession = `s.possession === side`; transition = within 4 s of `lastRegain`/`lastLoss` — during transition the side that lost the ball uses out-of-possession targets but at 1.15× speed (recovery), the side that won keeps in-possession targets.
- Lines come from `lineOf(FORMATIONS[tactic].slots[slot].position)` (`player.ts`); GK is slot 0.
- Pressing distance: `SHAPE_CONFIG.tactic[t].press`; within `counterPressSeconds` after `lastLoss.side === side` use `max(press, counterPress)`.
- Marking blend (§4.3): pick the nearest opponent outfielder within `markRadius` of the player's own spot; target = blend(spot target, point 1.5 m goal-side of that opponent, `markBlend`).
- Runs: weight = `actionWeight(role, traits, 'run')` (exported from `match.ts`); eligibility by role id: behind = slot line FW, or role `attackingMidfielder`/`shadowStriker`/`trequartista`; overlap = `overlappingFullBack`/`attackingWingBack`; box = `boxToBox`/`mezzala`/`shadowStriker` when the ball is in band ≥ 5 of the attacking frame. A player already on a run (`run.until > elapsed`) is skipped.
- Speed: `(base + pace · attrs.pace/99) × (1 − tired · min(1, minutesOn/90))`; the sweeper keeper rule: `keeperMax.sweeperKeeper` only when the own DF-line mean x ≥ 40.
- Testkit: `createWorld({ country: 'ENG', name: 'Grid Lab', color: '#2a5d8f', seed, level: 'normal' })`, pick two top-tier ENG clubs (`tier === 0`, not the own club), build `f = { ...w.fixtures[0], id: 'grid-lab', home, away }`, then override `w`'s NPC tactic by passing tactics into `buildGridSetup` via a test-only option `tactics?: [Tactic, Tactic]` (add it to `buildGridSetup` opts; default = the real tactics).
