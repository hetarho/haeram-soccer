## goal
Make the web runtime and persistence tests independent of the release switch: a fixture of an older or pre-model container builds that container explicitly, and a new-career case expects what the switch produces.

## acceptance
- [v] Fixtures that stand for a pre-model container (an older save, an earlier-rules career, a career created before activation) build their worlds with `DISABLED_RELEASE` (T415) or strip the model explicitly; the host is constructed with an explicit `release` option wherever the case is about the switch or about activation on load.
- [v] A case about a new career founded in the browser reads the release it runs with and asserts the matching container (model data present exactly when the release is on), so it holds on both switch states.
- [v] All seven touched files pass under `pnpm exec vitest run <files>` and under `pnpm exec vitest run --config vitest.release-on.config.ts <files>` (probe failures were host 7, persistence 6, client 6, legacyReset 5, matchModelPacking 2, managerHistoryPacking 1, persistence.history 1).
- [v] Task checks (ARCH-30): typecheck, lint, format:check, `vitest run --changed`, and `pnpm run build`.

## impl notes
- Test-only change: no runtime or adapter source edit. A case that needs a source change to pass with the switch on is a finding: leave it pinned off and name it in limits for T420.
- Loading and activation rules come from T402 (`activateMatchModel` on the writer path, a career keeps the model it recorded, no load gate); assert those rules, do not restate them in the fixtures.
- Browser journeys stay for the batch run (ARCH-30); list any spec that assumes the switch off in limits for T286.
