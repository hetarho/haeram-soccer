# T780 pack and unpack save columns with integer operations
> st:todo | ssot:SAVE-3 ARCH-21 | base:ARCH@36 | dep:- | touches:apps/web/src/adapters/bitpacking.ts apps/web/src/adapters/bitpacking.test.ts | lane:codec-speed

## goal
The save codec produces byte-identical output and the same validation while packing, unpacking and base64-coding columns with integer operations instead of one floating-point bit at a time, so every save a player makes and every journey that saves costs less CPU.

## acceptance
- [v] widths up to 31 bits use shift-and-mask; wider widths keep today's path; results and every validation check and error message are unchanged
- [v] `take` and the unpack loops fill preallocated arrays without a per-cell callback; `unbase64` decodes with a `charCodeAt` loop after the same validity regex; `base64` output is unchanged
- [v] a new test compares the old and new implementations byte for byte (packed bytes, base64 text, unpacked values) over seeded random columns with widths 1–53, negative/zero/max values, both layouts and empty input, and that malformed input still throws the same errors
- [v] existing codec tests pass unchanged: `bitpacking.test.ts`, `packing.test.ts`, `matchModelPacking.test.ts`, `careerPacking.test.ts`, `identityPacking.test.ts`, `managerHistoryPacking.test.ts`
- [v] a timing probe (old vs new, interleaved, same input from a real save) reports the speed-up with its spread
- [v] `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`, `pnpm run validate:i18n`

## result
- outcome: `bitpacking.ts` codes a column whose range needs at most `INTEGER_BITS` (31) bits with 32-bit shifts and masks: row layout writes each value into its first byte with `|=` and its later bytes directly (the stream only moves forward), plane layout ORs one bit per row; `take` decodes into `new Array(n)` with a running column/row and per-column `mins`/`widths`/`offsets` read once at open, rows by shifting up to five bytes and masking, planes by OR-ing one bit per plane. Columns of 32–53 bits go through `writeWideColumn`/`readWideValue`, today's floating-point code moved verbatim. `unbase64` keeps the regex and fills a `Uint8Array` with a `charCodeAt` loop over `atob`; `base64` writes the standard alphabet and `=` padding as ASCII codes and turns them into text with one `TextDecoder` call (no 32 K-argument `String.fromCharCode` spreads, no `btoa`). The column scan keeps `Math.min`/`Math.max`, so a `-0` minimum stays `-0` as before. Validation order, checks and message IDs are untouched; no prose was added. `bitpacking.test.ts` keeps its eight cases unchanged and adds a frozen copy of the 81463c87 codec as the oracle plus three cases (seeded with the engine's `random`): 748 pack/read cases (100,119 cells, 4,108 columns of which 1,276 are wider than 31 bits, every width 1–53 in both layouts, empty input at widths 1/3/156, zero, `-0`, `MAX_SAFE_INTEGER`, 2^31−1/2^31/2^32, a 156-column 31-bit row) compare the packed object `toStrictEqual`, the decoded bytes and 23,184 random-size takes (empty included) step by step and against the input; 41 byte strings (2–41 bytes and 65,541 bytes, all byte values) equal the legacy `btoa` text and decode back; 22 invalid pack inputs (widths, layouts, negative/fractional/unsafe/non-number values, row mismatch, over `MAX_COUNT`, `null`) and 486 read streams (86 hand-made header/count/layout/data/width corruptions including overflowing narrow and 40-bit minimums, plus 400 seeded mutations) give identical open/take×10/done traces, error class and message included, covering all eight read-side message IDs. Mutation checks: `INTEGER_BITS = 32`, dropping the read mask, or a wrong pad character each fail the new cases. Timing probe (scratchpad `t780/probe.mts`, tsx/Node 24, old = frozen 81463c87 file, order alternated per rep, 3 warm-ups; host load average ≈ 19–21 on 12 cores): all 136 bit-packed streams of `simulatedWorld(ENG compact-brackets, 1 season)` plus 12 observed rounds (657,871 cells, ≈382 KB, none wider than 31 bits), 21 reps: encode old median 215.4 ms (168.7–473.6) → new 31.7 ms (24.6–80.9), paired speed-up median 5.9× (IQR 4.7–7.5×); row-by-row decode 668.6 ms (517.9–949.8) → 65.1 ms (40.7–405.4), 10.0× (IQR 7.0–13.7×); together 892.9 → 98.4 ms, 8.6× (range 2.8–16.2×). The same world without observed rounds (99 streams, 24,553 cells): together 23.7 → 2.6 ms (15 reps, 8.4×, range 5.7–17.9×); with the candidate model 18.0 → 1.9 ms (21 reps, 9.7×). Before timing, the probe re-packed and re-read every real column with both codecs: identical.
