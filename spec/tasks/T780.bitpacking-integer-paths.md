# T780 pack and unpack save columns with integer operations
> st:todo | ssot:SAVE-3 ARCH-21 | base:ARCH@36 | dep:- | touches:apps/web/src/adapters/bitpacking.ts apps/web/src/adapters/bitpacking.test.ts | lane:codec-speed

## goal
The save codec produces byte-identical output and the same validation while packing, unpacking and base64-coding columns with integer operations instead of one floating-point bit at a time, so every save a player makes and every journey that saves costs less CPU.

## acceptance
- [ ] widths up to 31 bits use shift-and-mask; wider widths keep today's path; results and every validation check and error message are unchanged
- [ ] `take` and the unpack loops fill preallocated arrays without a per-cell callback; `unbase64` decodes with a `charCodeAt` loop after the same validity regex; `base64` output is unchanged
- [ ] a new test compares the old and new implementations byte for byte (packed bytes, base64 text, unpacked values) over seeded random columns with widths 1–53, negative/zero/max values, both layouts and empty input, and that malformed input still throws the same errors
- [ ] existing codec tests pass unchanged: `bitpacking.test.ts`, `packing.test.ts`, `matchModelPacking.test.ts`, `careerPacking.test.ts`, `identityPacking.test.ts`, `managerHistoryPacking.test.ts`
- [ ] a timing probe (old vs new, interleaved, same input from a real save) reports the speed-up with its spread
- [ ] `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`, `pnpm run validate:i18n`
