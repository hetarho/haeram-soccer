# T939 Hand the autosave world to the codec worker as JSON text

## goal
Shorten the engine thread's stall at every autosave (SAVE-8: the simulation does not wait for a checkpoint) by posting the world as one JSON string, which the codec worker parses, instead of structured-cloning the world object.

## acceptance
- [ ] `Host.save` (host.ts:665-677) posts the save request ID, generation, parent generation and `JSON.stringify` of the world; the codec worker's `serve` (codec.ts) parses the text and builds the checkpoint through the existing `build` path, so the envelope, checksum, validation, typed compatibility errors and reply are unchanged. The text job type lives in codec.ts; apps/web/src/runtime/protocol.ts (owned by the in-flight transfer work) is not edited (deterministic; worker, task stage).
- [ ] A unit asserts that the envelope and raw text built from the parsed JSON of testkit worlds (a fresh career and one with NPC careers, history and free agents) equal those built from the world object, and that a failing world still answers `ok: false` without throwing.
- [v] Engine-thread measurement (deterministic; worker, task stage): a script under artifacts/benchmarks/lifecycle-perf-261117/T939/ loads the stored 1950 world (`/tmp/claude-2378/-home-deep-haeram-haeram-soccor/df2135f9-ba36-4023-bb25-ee99a520d827/scratchpad/scout-play/world-1950.bin`, read the scout's loader in the same folder) and times in interleaved pairs, at least 12, the current hand-off (`structuredClone(world)`) against the new one (`JSON.stringify` then `structuredClone` of the string), reporting the median ratio with a 95% interval in a JSON file beside it; the change is kept only when the interval is below 1.
- [ ] Existing codec, host and adapters persistence units pass unchanged.
- [v] ARCH-30 task-tier checks pass through `vibe check --tier task`; integration, contract and build stay with the coordinator's final batch gate (handoff only).

## impl notes
- from review/lifecycle-perf-261117 F6
- Do not change pack, canonical, the codec choice, compression or the save budget; stored save bytes stay identical.
- The scout measured structured clone 1155–1299 ms against stringify 370–466 ms plus string clone 77–88 ms on that world; parse cost moves to the codec worker.

## result
- outcome: not kept, no speed claim; production code is as at base. On the stored 1950 world (26.3M JSON chars, 15 interleaved pairs, `node --expose-gc`) the acceptance proxy favours the text: `structuredClone(world)` against `JSON.stringify` plus `structuredClone(text)` has median ratio 0.627 with interval [0.598, 0.643] (order statistics 4 and 12 of 15, 96.5% coverage; medians 697 ms against 432 ms). `structuredClone` also deserializes, which a `postMessage` leaves to the receiving codec worker. Timing only what the sending (engine) thread pays, the text is slower: `v8.serialize` 1.306 [1.294, 1.335] (288 ms against 375 ms) and a real `MessagePort.postMessage` call 1.303 [1.278, 1.318] (284 ms against 369 ms). Kept, it would lengthen every autosave stall by about 30% (about 85 ms on this world), so F6's premise (1155-1299 ms of engine-thread clone) does not hold. `artifacts/benchmarks/lifecycle-perf-261117/T939/handoff.mjs` and `handoff.json` hold the measurement; `text-handoff.patch` keeps the unlanded change (host and codec text job, host.test types, a new codec.test.ts) for the record.
- at: 79a417ccdd669938f9ea67097984a7a9b0314a31 (the task-tier checks and measurement ran on this base plus the T939 artifact folder)
- verified: `npx --yes @haeram/gusta@latest vibe check --heavy --timeout-ms 1200000 -- node --expose-gc artifacts/benchmarks/lifecycle-perf-261117/T939/handoff.mjs /tmp/claude-2378/-home-deep-haeram-haeram-soccor/df2135f9-ba36-4023-bb25-ee99a520d827/scratchpad/scout-play/world-1950.bin 15` (gate field true on the proxy alone); with the patch applied, `pnpm exec vitest run --project unit apps/web/src/runtime/codec.test.ts` passed 3 of 3 (text and object checkpoints equal for a fresh career and a one-season career with squads, player records, history and free agents; a failing world and unreadable text answer `ok: false`; `serve` answers text jobs in order); `npx --yes @haeram/gusta@latest vibe check --tier task --diff-base 79a417ccdd669938f9ea67097984a7a9b0314a31 --task T939` passed typecheck, lint, format, i18n and affected units
- limits: the first, second and fourth acceptance lines describe the change that was not kept and stay open. Node's V8 serializer stands in for the browser's postMessage serializer (the same V8 ValueSerializer); no browser trace was taken. The engine-thread autosave cost on this world is about 285 ms of serialization, not 1.2 s; shortening it needs a smaller hand-off (posting less than the whole world), outside T939's scope and left to the coordinator as a proposal.
