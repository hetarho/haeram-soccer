## goal
Every type, schema field, command and delegation the three feature lanes need exists up front, with older saves migrating into it, so the lanes never edit contracts.

## acceptance
- [ ] types.ts and schema.ts (strict, bounded), all optional for older saves:
  - `sponsors`: one contract per slot `{ slot, kind, annual, bonus, from, until }`;
  - on players, `talk` (demand, floor, asked day, kind renew or raise), `unhappy` (since day, reason) and `transferRequest`;
  - on manager and staff, the chosen term;
  - delegation keys `contracts` and `manager`;
  - `managerRule` ('school' | 'best' | 'strategy');
  - inbox kinds `contract-talk`, `unhappy`, `transfer-request`, `sponsor-ending`;
  - ledger kinds `league-share`, `league-merit`, `parachute`, `sponsor:<slot>`, `free-transfer-compensation`.
- [ ] Commands are added in types.ts and protocol.ts:
  - `contract-offer {player, wage, term}`;
  - `contract-decline {player}`;
  - `sign-sponsor {slot, offer}`;
  - `renew-manager {term}` and `renew-staff {role, term}`;
  - `hire-manager` and `hire-staff` with `term`;
  - `manager-rule {rule}`.
  The engine may reject them until their lane implements them.
- [ ] Load migration (schema.ts, like legacyVision): a pre-1.16 `sponsor` becomes the 메인 스폰서 contract, or 지역 후원 before that slot opens in its country (→T050), keeping amounts and end. Wages, terms and delegation stay as they were.
- [ ] Intervention levels (ProgressControls.tsx, →WEB-45): `contracts` is delegated at levels 2–4, `manager` at level 4; new clubs delegate contracts (→STAFF-13).
- [ ] schema.contract.test.ts: a 1.15 world with a sponsor loads with that sponsor as its slot's contract; the new fields round-trip; unknown keys are still refused.
- [ ] `pnpm run typecheck && pnpm run test:unit && pnpm run test:contract` pass. Only the contract test's new cases are required; goldens are left to T062.
