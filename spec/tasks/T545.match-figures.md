## goal
Live observation and archived replay draw every player as a posed figure in the recorded kit, with number tags and the carrier cue, at the same positions, clock and outcomes as before.

## acceptance
- [ ] `Pitch.tsx` draws each player with `createFigurePainter().draw` (T544) instead of `painter.draw` markers, at the interpolated recorded position, with `radius = markerRadius(width)`. Positions, the ball path, the clock mapping, seeking, the dead-ball beat and goal holds are unchanged (MATCH-12, WEB-32/94).
- [ ] Outfield players wear `look.sides[side].kit` and keepers `keeperKit` (T542 `matchLook`). Unrecorded matches use the stand-ins and keep the "유니폼 미기록" notice (KIT-12).
- [ ] Poses come from `poseAt` with `figureActionWindows` and `gaitDistances` (T543), computed once per playback (`useMemo`). The same presented instant draws the same pose after speed changes, seeks, replays or tab switches (MATCH-37).
- [ ] With `reducedMotion()` figures hold still stances and key poses (WEB-46).
- [ ] Number tags come from `placeNumberTags`/`drawNumberTag` with the existing player numbers. The carrier cue (WEB-95) and the inspection selection stay visible and do not hide the number tag or the ball.
- [ ] An archived match without motion samples stands its figures in the existing fixed shape, facing the opponents' goal.
- [ ] `pitchFigures.ts`: `figureInputs(sample, next, mix, …)` builds T543's `FigureInput` for every player: screen-space velocities from the canvas mapping, `velocityBefore` from interpolation at `time − FIGURE_POSE_CONFIG.hipLag`, interpolated `distance`, `toBall`, `carrier`. Unit tests in `pitchFigures.test.ts`: "velocity converts to screen space", "distance interpolates between samples", "carrier follows the possession cue", "missing next sample holds position".
- [ ] e2e specs updated for figures and listed in result limits for the batch run:
  - `club-identity-observation.spec.ts`: verify worn colours on the figure torso through the shared `FIGURE_TORSO`/`figureShirtColourAt` geometry instead of marker discs.
  - `club-identity-continuity.spec.ts`: adjust its base-colour pixel thresholds.
  - `match-core.spec.ts`, `match-themes.spec.ts`, `mobile-match-presentation.spec.ts` and `live-state.spec.ts`: change any assertion that relied on marker rendering.
- [ ] ARCH-30 task tier passes (typecheck, lint, format:check, changed unit tests) and `pnpm run build`; no browser specs are run in the task (ARCH-30).

## impl notes
- Replace only the player-drawing block of the draw loop (`Pitch.tsx` around the `painter.draw(ctx, isKeeper ? keeperShirt : shirt, …)` call); keep its projection `x(v)`/`y(v)`, the skin tokens and the ball painting.
  - The kit sprite warm-up for markers goes; warm the figure painter's cache for the four worn kits instead.
  - `kitPainting.ts` stays for diagrams and swatches.
- Facing for the fixed-shape fallback: home faces +x, away faces −x in pitch units before the screen conversion.
- Canvas mapping for screen vectors: `fw = width − 2·pad`, `fh = height − 2·pad`, so a pitch-unit vector `[ux, uy]` is `[ux·fw/100, uy·fh/100]` px. Speed in m/s is `hypot(vx·1.05, vy·0.68)` from `PlayerMotion.velocity`, which is in units per second.
- Event times: frame index `i`, event `t` → `i·60 + t` on the presentation clock (T543).
- Keepers come from the existing `keepersBySample`.
- Number tags avoid `[ball x, y, ball radius]` and the carrier cue ring.
- Performance: keep the per-frame path free of allocation-heavy work. Action windows and gait distances are built once per playback. ARCH-28 targets ≥ 30 FPS on the reference mobile viewport, which the batch benchmark checks, not this task.
- The batch runs the e2e specs; record their names in `- limits:`.
