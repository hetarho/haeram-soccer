## goal
On the 방향 board a preset or a saved direction drafts every row, the composer shows every area's rows and saves them, and the founding screen has a 구단 방향 row.

## acceptance
- [ ] tapping a preset drafts its whole board (`presetBoard`): every card, dial, the ticket price and every direction row that differs from the world; 추천 방향 lists the seven presets; the draft bar counts all of them
- [ ] saved directions keep `rows` (policy, ticket, direction) beside `build`; 지금 방향 저장 saves every row in force; applying an entry with rows drafts its whole board, an entry without rows (saved before) drafts only its cards; the library stays valid for older entries (SAVE-15)
- [ ] the composer (방향 만들기 / 방향 편집) shows every area of DIRECTION_AREAS with its rows drawn by DirectionRow, starting from the direction in force (or the entry being edited), and saves them all
- [ ] the founding screen shows a 구단 방향 row under the capital choice: 기본 방향 (selected) and the seven presets as compact chips, the chosen one's idea and the rows it fills in one line below; 클럽 창단 founds with it (`preset` in the founding input); the screen still fits 360x740 without document scrolling (→WEB-15)
- [ ] the entry bundle stays within ARCH-28's budget: the founding row imports only the preset labels, ideas and row summaries (a small module), not the board
- [ ] tests: apps/web/src/ui/board.test.ts (a preset drafts every row; a saved entry without rows drafts only cards), apps/web/src/adapters/profile.test.ts (rows kept; older entries load), tests/e2e/founding.spec.ts new case "founds with a preset as its direction", tests/e2e/strategy.spec.ts updated (seven presets, a preset drafts rows beyond the cards, the composer shows every area); full Chromium e2e passes; `pnpm run benchmark` and `pnpm run benchmark:browser` find the entry within budget

## impl notes
- put the founding view of the presets (id, label, model, a one-line row summary) in a tiny `packages/engine/src/presets-summary.ts` or a web module generated from BUILD_PRESETS at build time — whichever keeps the entry under budget; measure with the benchmark's entry size.
- `withStrategy(w, draft, build, name, rows?)`: with rows, set draft.policy to every key differing from the world, draft.ticket when it differs, draft.direction when it differs; without rows, cards only (today).
- composer state is a whole board ({ build, policy, ticket, direction }); its save writes `build` and `rows`.
- SavedStrategy type (adapters/profile.ts): `rows?: { policy?: Partial<ClubPolicy>; ticket?: number; direction?: Partial<Direction> }`; malformed rows drop the rows, keep the cards.
