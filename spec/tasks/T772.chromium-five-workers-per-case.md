# T772 run local Chromium journeys on five workers, scheduled per case
> st:todo | ssot:ARCH-30 | base:ARCH@34 | dep:- | touches:playwright.config.ts scripts/preview.mjs | lane:gate-e2e

## goal
The release gate's Chromium stage uses the cores the host has instead of half of them, without changing a journey, a timeout or a retry.

## acceptance
- [ ] locally (not CI) Chromium runs `E2E_WORKERS` workers, default 5, with `fullyParallel`; CI keeps three workers and file-level scheduling; Firefox and WebKit keep three workers locally
- [ ] every timeout, `expect` timeout, retry and project setting is unchanged; `pnpm exec playwright test --list --project=chromium` lists the same 348 cases before and after
- [ ] the preview server memoises each compressed response by path, size and modification time, so a rebuilt file is served fresh; headers and status codes are unchanged
- [ ] `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`, `pnpm run build`; the journeys themselves are the release run's (ARCH-30)

## impl notes
