# T725 scan settled fixtures with plain loops when a club has no recent results yet
> st:todo | ssot:ARCH-5 ARCH-30 ARCH-34 | base:ARCH@34 | dep:- | touches:packages/engine/src/recent-results.ts packages/engine/src/recent-results.test.ts | lane:perf-recent

## goal
A career's first matchday no longer pays a generator resume per fixture for every club's first result: `recentClubResults`' fallback scan (451 scans over about 8.6k fixtures on seed perf-261027's day 7, 84–153 ms of CPU by direct timing) runs as plain indexed loops over the same sources in the same order, with every output identical (review/self-improve-local-261109 F8).

## acceptance
- [v] `recent-results.ts` builds the source list once in a helper returning exactly the generator's sources in its order (`w.fixtures`, each cup's fixtures, each European tournament's fixtures, `w.ownMatches`); `recentClubResults` scans it with indexed loops using the same predicate (`f.score` and home/away equal to the club), so the Map gets the same entries in the same insertion order; `retainRecentResults` may use the same helper; nothing else changes
- [v] result-identical: `scripts/perf/ab.mjs` reports `sameHash` true for `--workload day`, `--workload aggregate --procs 4` and `--workload grid --procs 4` at their default reps, and the recent-results tests (engine and web adapter) pass
- [v] measured per ARCH-34 on this machine with its load stated: `--workload day --reps 7 --warm 0 --procs 16` (a career's first week, where the scan runs) and the default 60-day `--workload day`; result records both CPU ratios with their 95% intervals, and claims a speed-up only for a workload whose whole interval lies below 1
- [v] `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`, `pnpm exec vitest run --project unit --changed "$HAERAM_DIFF_BASE" --passWithNoTests` pass

## impl notes
- Profile basis: scout fs09-D's `scripts/perf/profile.mjs` runs (day/aggregate/grid) are flat once samples are weighted by their time gap; this scan is the one engine cost found that is result-identical and measurable by `ab.mjs`. The gain is a one-time cost per career (plus each later first-time club), so the 60-day median is expected to show no difference — record it as measured.
- `ab.mjs --base main` compares against the main checkout's tree; run it from the worker's worktree so the candidate is the worktree.

## result
- outcome: `settledFixtures` (generator) is gone; `resultSources(w)` returns the same list expression it iterated (`w.fixtures`, each cup's fixtures, each European tournament's fixtures, `w.ownMatches`), and `recentClubResults` scans it with two indexed loops under `f.score && (f.home === club || f.away === club)`, so `known` gets the same entries in the same insertion order; `retainRecentResults` walks the same helper with array `for…of` and `if (!f.score) continue` before its unchanged per-club body. Sorting, slicing, `summary` and `recordRecentResult` are untouched. The new test keeps the pre-T725 generator code verbatim as a reference and compares `JSON.stringify` output of both functions on a world with league, two cups, two European tournaments and an own match, including unplayed fixtures, a shoot-out, an own-match payload and same-id fixtures in later lists (last copy wins at its first position); swapping cups and Europe in `resultSources`, or dropping `f.score` from the predicate, fails it.
