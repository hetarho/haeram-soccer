## goal
Owners edit each kit's shorts and socks and one goalkeeper kit, at founding and in 구단 디자인, previewing large and match-scale figures, and preparation states a goalkeeper fallback.

## acceptance
- [ ] Each of 홈/어웨이/세컨 has 하의 and 양말 colour controls accepting any `#RRGGBB` (KIT-3).
  - An unset part shows its starting colour (`startingShorts`/`startingSocks`, T542) and follows named-colour edits.
  - Changing it stores `parts[role]`; a reset action returns it to following.
- [ ] A 골키퍼 tab edits the goalkeeper kit: the eight patterns, shirt base/second/trim colours, and shorts, socks and gloves colours (KIT-8, WEB-86).
  - Without a saved goalkeeper kit, the tab shows a draft from the automatic colour distinguishable from the club's three kits, and the draft stores `goalkeeper` only once the owner changes a control (KIT-15).
- [ ] Apply sends a `normaliseIdentity` result (version 1 when no part, version 2 otherwise).
  - Cancel restores the identity present on entry, and a failed apply keeps the draft (KIT-9).
  - Founding uses the same editor and draft (WEB-2, KIT-14).
- [ ] Previews (WEB-87) draw with the T544 figure painter: a large figure in the selected kit or the goalkeeper kit, and the match-scale pitch preview with the opponent sample and both goalkeepers. Pattern placement agrees with match observation.
- [ ] Match preparation (WEB-88, `FixtureKitSelector`) previews both sides' kits and goalkeepers and states when a fallback colour replaces our goalkeeper kit for this fixture (`keeperFallback`, T542). Clash warnings are unchanged (KIT-7).
- [ ] Controls have names, values, visible focus and selected states and keep the phone layout rules (WEB-86).
- [ ] Unit tests: `clubIdentityDraft.test.ts` ("unset shorts follow named colours", "set socks keep their colour after a named-colour edit", "goalkeeper stays absent until edited", "normalised apply is version 1 without parts"); `identityPreview.test.ts` ("preview shows designed keeper or fallback"); `FixtureKitSelector.test.ts` ("states the keeper fallback"); `identityEditorMarkup.test.ts` (shorts/socks controls and 골키퍼 tab markup).
- [ ] e2e specs updated, then listed in result limits for the batch run: `club-identity-founding.spec.ts` (preview pixels from figures), `club-identity-management.spec.ts` (edit shorts/socks and goalkeeper kit, apply, reload keeps them — SAVE-20), `club-identity-preparation.spec.ts` (fallback notice), `club-identity-helpers.ts`.
- [ ] ARCH-30 task tier passes (typecheck, lint, format:check, changed unit tests) and `pnpm run build`.

## impl notes
- Draft actions extend `IdentityDraftAction` in `clubIdentityDraft.ts`:
  - `{ type: 'part'; role; part: 'shorts' | 'socks'; colour | null }`, where null resets to following.
  - `{ type: 'keeper'; patch: Partial<GoalkeeperKit> | { shirt: Partial<ShirtDesign> } }`.
  - `{ type: 'keeper-reset' }`, which removes the designed kit.
  - `linkedIdentityColours` leaves set parts and the goalkeeper kit untouched.
- Free colour entry reuses `colourInput`; the existing colour control component is used for consistency.
- Use the T542 exports: `wornKit`, `startingShorts`, `startingSocks`, `automaticKeeper`, `keeperAvoiding`, `normaliseIdentity`, `selectMatchKits(...).keepers/keeperFallback`. The goalkeeper draft for a club without a saved kit is `automaticKeeper(keeperAvoiding([identity.kits.home, identity.kits.away, identity.kits.third]))`.
- Large figure sample: a standing pose (`poseAt` with zero velocity facing down-screen) at a fixed large radius; the match-scale preview uses `markerRadius(width)` and `placeNumberTags`.
- Labels are Korean, inline like the existing editor labels: 하의, 양말, 골키퍼, 장갑, 기본값으로.
- The batch runs the e2e specs; record their names in `- limits:`.
