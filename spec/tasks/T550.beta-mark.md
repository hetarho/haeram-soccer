## goal
Until 1.0 the player always sees that the game is a beta: a small BETA mark sits at the top of every screen — beside the club name in the play HUD and beside the game's name on screens without it — and the start and save-slot screens show the game version as `v0.7 BETA`, read from the version T549 sets.

## acceptance
- [ ] One shared BETA mark component (text `BETA`, a label for screen readers, theme tokens for colour so every shipped theme and dark/light reads it) appears in the play HUD beside the club name (→WEB-10) and at the top of every screen that has no HUD (start, founding, save slots, settings, recovery and error screens).
- [ ] The start and save-slot screens show `v0.7 BETA`, built from `CURRENT_ENGINE_VERSION` (major.minor), never a hard-coded string.
- [ ] The mark takes no tap target, does not push the HUD's primary controls below 44 px, and causes no horizontal overflow at 360, 390 and 1280 px (the layout helpers' checks).
- [ ] Every shipped resource skin and theme (→WEB-69) shows the mark legibly; presentation baselines and captures that change are re-recorded with a one-line reason.
- [ ] Tests: a unit test that the version label reads `v0.7 BETA` from the version constant; Chromium e2e "the BETA mark shows on the start screen, the save slots and the play HUD at 360, 390 and 1280 px".
- [ ] ARCH-30 task tier: typecheck, lint, format check and the changed unit tests pass; the named e2e spec passes on Chromium.

## impl notes
- Where the copy lives: the existing presentation locale catalog (`apps/web/src/presentation`) (Korean first, English alongside where the catalog has it); the mark itself is not translated.
- Keep it small and quiet: a pill beside the name, not a banner; no new dependency.
