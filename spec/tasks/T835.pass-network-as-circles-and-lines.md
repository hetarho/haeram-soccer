## goal
The pass network tab shows one side at a time as the owner's reference pictures do: a numbered circle for each player at his average position, bigger the more he passed, and lines between players as wide as the passes played between them with an arrowhead for each direction — readable on a phone and in every theme.

## acceptance
- [ ] the network view (`apps/web/src/features/match-viewer/ui/MatchMaterial.tsx` and its helpers in `entities/match/lib/materialView.ts`) draws from the existing `MatchMaterial.network` rows: circle radius by the player's passes (his row's touches until the helper below exists) between `NETWORK_VIEW.radius.min` and `max`, line width by the pair's completed passes in both directions between `NETWORK_VIEW.line.min` and `max`, an arrowhead at an end only when passes were played toward it, pairs below `NETWORK_VIEW.minPasses` not drawn, the shirt number inside the circle
- [ ] `entities/match/lib/materialView.test.ts` gains `a circle grows with a player's passes`, `a line is as wide as the pair's passes in both directions`, `an arrowhead marks only a direction played`, `pairs under the least count are left out`, `a side with a man sent off still draws ten circles`; the tab's existing cases pass
- [ ] touching a circle names the player and his passes, touching a line the two players and the passes each way; the text summary for assistive technology lists the five busiest pairs; any new copy is message ids with translations in every locale pack and `pnpm run validate:i18n` passes
- [ ] `tests/e2e/match-material.spec.ts` asserts the tab's circles and lines by role and count on the 1.9:1 pitch (confirmed by the batch run); `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`, `pnpm exec vitest run --project unit --changed "$HAERAM_DIFF_BASE" --passWithNoTests`, `pnpm run build`

## impl notes
- The owner's reference (261111): the broadcast pass map — circles at average positions sized by passes, connecting lines whose thickness is the passes between two players, arrows for direction. Nothing in the stored form changes (→MATCH-25): `network` already holds `[avgX×10, avgY×10, touches]` a line and `[from, to, completed]` a pair.
- A player's passes for the circle: the sum of his outgoing pairs' counts (completed passes); keep `touches` for the touch text only.
- `NETWORK_VIEW` is a named constant beside the view helpers: `radius { min: 0.018, max: 0.045 }` of the pitch's drawn width, `line { min: 1, max: 9 }` px at the reference width scaled with it, `minPasses: 3`. Lines are drawn under circles, the thicker over the thinner; colours come from the theme's semantic tokens (→WEB-91), the own side's in its kit's base colour with the contrast ink the scoreboard uses.
- Keep what the tab has today: the 1.9:1 pitch, cell names on touch elsewhere, reduced motion, phone widths (→WEB-17/38).
- This task does not depend on which engine filled the material: it works on today's grid matches and on scripted ones.
