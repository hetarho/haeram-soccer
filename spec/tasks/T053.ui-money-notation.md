## goal
Every amount in the app, the HUD included on every viewport, uses the compact notation, and the exact amount opens on tap or hover.

## acceptance
- [v] A `<Money value code year />` component renders `compactMoney` with the exact `money()` value in its title and an accessible tap disclosure; every UI amount uses it (search `money(` under apps/web/src/ui). FinancialBreakdown's ledger detail sheet stays exact (→WEB-14).
- [v] The HUD shows the compact notation on every viewport; the cashFull/cashCompact split goes (→WEB-10).
- [v] format.test.ts uses the same expected strings as T052's moneyLabel test.
- [v] Affordability checks keep comparing exact BigInt amounts; disabled actions still state why.

- [v] `pnpm run typecheck && pnpm run test:unit` pass.

## result
- outcome: every amount in the app reads in the one notation. `<Money>` prints `compactMoney`, carries the exact `money()` value as its title and in its accessible name, and swaps to the exact amount on tap; inside a control that already answers taps — the bid dialog's fee steps and its send button, a staff candidate's wage and fee, a department dial step's wage — `<Money plain>` keeps the notation with the exact amount as its title. The HUD counts in the notation on every viewport with the exact amount as its title and label. Amounts composed into a sentence, a tooltip or a chart axis carry the same notation as `compactMoney` text, and the records charts drop their own K/M/B spelling.
