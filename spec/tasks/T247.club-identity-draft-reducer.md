# T247 Make identity editing a pure isolated draft reducer

## goal
Centralize colour, preset, composition and shirt edits so later UI tasks cannot accidentally modify applied identities or sibling kits.

## acceptance
- [v] The reducer covers representative palette edits, preset selection, crest part/colour edits, selected-role shirt edits, pattern changes and explicit representative-colour reuse.
- [v] clubIdentityDraft.test.ts cases palette change preserves all shirts, reuse changes only the selected shirt and keeps its pattern, preset preserves colours and all shirts, and editing a draft leaves its entry object unchanged pass.
- [v] Cases selecting plain removes the unused secondary, selecting a patterned design visibly supplies its explicit secondary, and one/two/three representative colours remain valid pass.
- [v] Reset/cancel returns an independently cloned entry value rather than a pointer to a mutated applied value; unknown reducer actions fail at compile-time.
- [v] Every accepted reducer output parses through the strict identity schema; invalid UI text remains an input draft error and never reaches the save command.
- [v] Targeted verification passes: `pnpm exec vitest run apps/web/src/ui/clubIdentityDraft.test.ts && pnpm run typecheck`.

## impl notes
- Read `docs/CLUB-IDENTITY-CONTRACT.md` sections named below; it owns the stable interfaces used in this task.
- Prerequisites: T237. Read their implemented interfaces/results before editing; extend those modules rather than reproducing a prerequisite.
- Read design §7. Export a discriminated IdentityDraftAction union and reduceIdentityDraft(value, action); cloning only changed branches is sufficient, provided no input branch is mutated.
- Implement explicit reuse exactly as documented: primary=representative[0], patterned secondary=representative[1] ?? primary, trim=representative[2] (plain: [2] ?? [1]), with unused fields removed.
- Keep selected UI role/expanded composer outside ClubIdentity. No localStorage, GameClient, world revision, navigation or RNG is imported by this reducer.
- Use frozen input fixtures and snapshots of sibling roles to catch aliasing; checking only that the chosen new colour appears does not protect the essential cancellation and isolation policies.

## result
- outcome: completed. New `apps/web/src/ui/clubIdentityDraft.ts` imports only the contract identity leaf (no zod, engine, storage, GameClient, revision, navigation or RNG). It exports the discriminated `IdentityDraftAction` union, `reduceIdentityDraft(value, action)`, `cloneIdentity` and `colourInput`. Actions: representative colours: `colour` (set index 0–2), `add-colour` (up to three), `remove-colour` (index 1/2), which change only `colours` while the crest and kits keep their objects; crest: `crest-preset` (one of the six `CREST_PRESETS`, copying its parts in the crest's current primary/secondary/accent), `crest-part` (shape/pattern/emblem), `crest-colour` (primary, or secondary/accent where null removes them as negative space); shirts: `shirt-pattern` (plain drops the secondary, while entering a pattern keeps the shirt's own secondary, else supplies `colours[1] ?? colours[0]` explicitly), `shirt-colour` (primary, a secondary only on patterned shirts, trim where null removes it), `shirt-reuse` (대표색 적용 exactly as §7: primary=[0], patterned secondary=[1] ?? [0], trim=[2] or for plain [2] ?? [1], unused fields omitted, pattern and other roles kept); `reset`, which returns a field-by-field deep copy of the entry. Each action rebuilds only the branch it changes, through builders that omit absent optional keys. An action that cannot apply returns `value` itself: an invalid `#RRGGBB` colour, a null for a required region, a secondary on a plain shirt, a fourth or a missing representative colour, an unknown preset index, or a part/pattern outside the catalogue. A typed caller cannot send an unknown action (exhaustive `never` switch); untyped code that does gets a thrown error. `colourInput` turns editor text (`#RRGGBB` or six digits, trimmed) into a draft colour or null, so invalid text stays an input error. New `clubIdentityDraft.test.ts` (11 cases) runs on a deep-frozen entry with mixed-case spellings and a structured-clone snapshot. Siblings are checked by reference (`toBe`) and by value against the snapshot. Every accepted output is checked with `clubIdentitySchema.parse` and for no undefined-valued keys. Three `@ts-expect-error` calls (unknown action, removing the crest primary, a crest field pattern as a shirt pattern) plus one for a null patterned-shirt secondary also check the runtime refusal.
