## goal
Use immutable recorded appearance for real engine-driven player markers, scoreboard crests and kit legends, including safe legacy fallback.

## acceptance
- [v] Outfield markers on the actual live Canvas visibly contain the chosen pattern and colours; keeper colours come from the same recorded snapshot and actual on-pitch keeper identity.
- [v] Current world identity edits cannot change an ongoing or archived recorded match’s crest, shirt, trim or keeper colours. Position/motion, substitutions, red cards, numbers, seek and 1.9:1 geometry remain intact.
- [v] matchAppearance.test.ts cases resolves recorded appearance without current-world fallback and missing appearance stays explicitly unknown pass.
- [ ] club-identity-observation.spec.ts checks actual Canvas pixels for stripes/checks at phone scale, freezes appearance across a management edit while playback is paused, and labels old imported records 유니폼 미기록.
- [v] Charts retain distinct labelled/dashed analytical series and actual kit swatches; lifting a chart line for contrast never repaints players or a saved snapshot.
- [v] The existing mobile-match-presentation and match-core journeys still pass; there is no loop hard-coded to eleven permanent slots or slot-zero keeper after the grid work.
- [v] Targeted verification passes: `pnpm exec vitest run apps/web/src/ui/matchAppearance.test.ts apps/web/src/ui/matchCharts.test.ts && pnpm run typecheck && pnpm run build`; `tests/e2e/club-identity-observation.spec.ts`, `tests/e2e/mobile-match-presentation.spec.ts` and `tests/e2e/match-core.spec.ts` are written or updated here and confirmed by the batch Chromium run before the push (ARCH-30), named in `- limits:`.

## impl notes
- Read `docs/CLUB-IDENTITY-CONTRACT.md` sections named below; it owns the stable interfaces used in this task.
- Prerequisites: T242, T245, T246, T252. Read their implemented interfaces/results before editing; extend those modules rather than reproducing a prerequisite.
- Read design §§5 and 7 plus the completed grid playback contracts. Resolve from playback.record.appearance once per record; do not call crestOf(currentWorld) or the old kits() helper to decide historical colours.
- Use current motion IDs to look up the whole matchday roster, then position/state to identify the keeper. Preserve the grid renderer’s onPitch filtering and substitution behavior.
- Replace only the marker fill with the shared cached painter. Keep current interpolation, selection-ring/intent drawing and ball animation; never run kit selection or texture construction inside rAF.
- For a missing snapshot show generic clearly labelled side markers and placeholder crest with unrecorded text. Do not backfill a snapshot or present today’s identity as historical fact.
- Browser pixel assertions should sample a paused known player marker and compare against its expected configured colour regions or a bounded local screenshot; a styled DOM legend alone is not evidence.
