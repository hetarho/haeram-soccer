## goal
Introduce a normalized retained career registry and identity-safe role/employment operations.

## acceptance
- [ ] A player, later coach and later manager resolve one person ID/name/birth year; a concurrent player/coach pair is one person with two roles, not two birthdays or career totals.
- [ ] The registry retains fixed qualities, career intention/encouragement state, separate coaching/manager learned values, current affiliation/status, dated employment and dated mentor exposure without duplicating full player snapshots each day.
- [ ] Role operations preserve genuine own-player totals and historical names/dates. Unknown pre-start or NPC appearances/honours remain unavailable rather than zero-filled.
- [ ] Schema/reference validation rejects orphan person/club links, duplicate active occupations of a single post, impossible reversed intervals and a manager holding a concurrent coaching post.
- [ ] person-careers.test.ts covers enter/leave/re-enter roles, overlapping player/coach roles, identity collision rejection and idempotent employment closure.

## impl notes
- Keep the existing player ID as the person's canonical identity. Add a World registry keyed by that ID; Staff/Manager records link to it instead of minting an unrelated retiree identity. Existing ordinary generated staff/managers need no invented playing history.
- Use dated intervals with explicit club/post and optional end. Store components and separate learned coaching/manager values once per retained person; actual current playing objects remain owned by their existing player/squad paths.
- Put create/resolve/open/close helpers in person-careers.ts so later hires, transfers and retirement cannot each maintain divergent copies. Plain serializable records only; no Maps/Sets/Date/BigInt in save DTOs.
