## goal
Identities and match appearances carry each kit's shorts and socks and an optional designed goalkeeper kit; selection judges shirts on the figure torso and falls back per fixture when the goalkeeper kit is not distinguishable.

## acceptance
- [ ] `ClubIdentity` accepts version 1 (unchanged shape) and version 2 (with `parts` and/or `goalkeeper`); `clubIdentitySchema` rejects a version-2 identity without either field and a version-1 identity with one; `assertVersion` treats versions above 2 as a newer game (`SaveCompatibilityError`).
- [ ] `MatchAppearance` accepts version 1 and version 2; version 2 requires `shorts`, `socks` and `keeper` on both sides; versions above 2 raise `SaveCompatibilityError` in `assertAppearanceFormatVersion` and `readAppearances`.
- [ ] `kit-wear.ts` resolves `wornKit(identity, role)` and `wornKeeper(...)` by the KIT-3 starting rule and KIT-8; `kit-wear` and `kit-patterns` are listed as read leaves in `scripts/lib/architecture.test.ts` and pass it.
- [ ] `selectMatchKits` samples visible shirt colours over the figure torso (`insideFigureTorso`), keeps a distinguishable designed goalkeeper kit, falls back per fixture otherwise, and returns `kits`, `keepers` and `keeperFallback` beside the existing fields.
- [ ] `appearanceForFixture` writes version-2 appearances (shorts, socks, keeper, `keeperFallback` when it happened); recorded version-1 appearances stay readable and are never rewritten.
- [ ] `applyClubIdentity` and founding accept a valid version-2 identity and normalise it (`normaliseIdentity`); an invalid one fails without changing the world.
- [ ] `matchLook` keeps `shirt` and `keeper` and adds `kit`, `keeperKit` and `keeperFallback`; version-1 records derive shorts/socks/keeper by the starting rule from the recorded shirt and goalkeeper colour (KIT-12); unrecorded matches use stand-ins.
- [ ] Unit tests: `kit-wear.test.ts` ("starting shorts follow second colour, then trim, then contrast ink", "set parts win over the starting rule", "automatic keeper kit is plain with contrasting gloves"); `kit-selection.test.ts` ("designed keeper kept when distinguishable", "designed keeper falls back only for this fixture", "automatic colours avoid a designed keeper", "pairing samples the figure torso"); `match-appearance.test.ts` ("version-2 appearance records worn kits and fallback"); `identityPacking.test.ts` ("round-trips version-1 and version-2 appearances", "version 3 is a compatibility error"); `identity.contract.test.ts` v1/v2/v3 cases; `matchAppearance.test.ts` ("version-1 record derives shorts and socks from its shirt"); `identity-operations.test.ts` ("applies and normalises a version-2 identity").
- [ ] ARCH-30 task tier passes: `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`, `pnpm exec vitest run --project unit --changed "$HAERAM_DIFF_BASE" --passWithNoTests`, plus `pnpm exec vitest run --project contract packages/contracts/src/identity.contract.test.ts`.

## impl notes
- Types (`packages/contracts/src/identity.ts`). Keep `ShirtDesign` and `kits: Record<KitRole, ShirtDesign>` exactly; add, without renaming anything:
  - `KitParts { shorts?: string; socks?: string }`: a part the owner set; an absent part follows the starting rule (KIT-3 "until set they follow").
  - `GoalkeeperKit { shirt: ShirtDesign; shorts: string; socks: string; gloves: string }` (KIT-8: any pattern, free colours).
  - `WornKit { shirt: ShirtDesign; shorts: string; socks: string }` and `WornKeeper { shirt: ShirtDesign; shorts: string; socks: string; gloves: string }`: what a figure wears, always complete.
  - `ClubIdentity.version: 1 | 2`, `parts?: Partial<Record<KitRole, KitParts>>`, `goalkeeper?: GoalkeeperKit`. Version 2 exactly when `parts` (non-empty) or `goalkeeper` is present. Old builds then read a v2 save as a newer game rather than as corruption; existing v1 saves and prepared fixtures stay valid untouched.
  - `AppearanceSide` adds `shorts?`, `socks?`, `keeper?: WornKeeper` and `keeperFallback?: true`. `goalkeeper: string` stays and holds the keeper shirt's base colour. `MatchAppearance.version: 1 | 2`, with version 2 exactly when the sides carry `shorts`/`socks`/`keeper`.
  - `KIT_WARNINGS` is unchanged; the fallback is the `keeperFallback` flag, not a warning.
- Schema (`identitySchema.ts`): a `z.union` of strict v1 and strict v2 objects for identity and for appearance sides. Add `normaliseIdentity(identity)`: it drops empty `parts` entries, sets the version from the rule above and returns a copy. `CURRENT_IDENTITY_VERSION = 2`, used by `assertVersion`.
- New read leaf `packages/engine/src/kit-wear.ts`. It imports only contracts and `kit-patterns.ts`, plus colour helpers moved or duplicated into a leaf if `identity-legacy.ts` is not one. Exports:
  - `contrastInk(hex)` returns '#ffffff' or '#111111' by relative luminance.
  - `startingShorts(shirt)` = `shirt.secondary ?? shirt.trim ?? contrastInk(shirt.primary)`, and `startingSocks(shirt)` = `shirt.primary`. This is KIT-3's starting rule and KIT-12's derivation for v1 records; KIT-4's linked second colour reaches patterned shirts as `secondary` and plain ones as `trim`.
  - `wornKit(identity, role)` returns the shirt plus `parts?.[role]` over the starting rule.
  - `automaticKeeper(colour)` returns a plain shirt of that colour, shorts and socks in that colour, and `contrastInk` gloves.
  - `designedKeeper(identity)` returns `identity.goalkeeper` or undefined.
  - UI tasks T544–T546 import these by name.
- Figure torso geometry (`kit-patterns.ts`, shared by selection and painting, MATCH-36/KIT-7). Torso unit square: x runs across the shoulders from the player's left (0) to right (1); y runs from chest (0) to back (1). Export:
  - `FIGURE_TORSO = { aspect, cornerRadius, sleeveTrim, collar: { cx, cy, rx, ry, band }, head: { cx, cy, r } }`, with these values defined here: aspect (width/depth) 2.5, cornerRadius 0.45 of the depth, sleeveTrim 0.07 of the width at each end, collar ellipse centred on the head with a 0.05 band, head circle cx 0.5, cy 0.42 and r 0.2 of the width in torso-x units.
  - `insideFigureTorso(x, y)`: inside the rounded rectangle and outside the head circle, i.e. what is visible from above.
  - `figureShirtColourAt(shirt, x, y)`: trim on the sleeve bands and the collar band, otherwise the pattern colour from `shirtPatternRegions` in the same unit square.
  - Existing marker functions stay, because the tactical diagrams keep markers (MATCH-36).
- Selection (`kit-selection.ts`):
  - `visibleColours` samples `figureShirtColourAt` at the 16×16 points inside `insideFigureTorso`.
  - Keepers, home side first:
    1. A side with a designed kit keeps it when its visible colours' weighted nearest distance to every visible outfield colour of both selected shirts is at least `KEEPER_DISTANCE_MIN`. When both sides keep designed kits that are closer than `KEEPER_DISTANCE_MIN` to each other, the away side falls back.
    2. Sides without a kit, or that fell back, take `keeper()` avoiding the outfield colours, the grass and every keeper colour already chosen (designed kits first).
    3. `keeperFallback[i]` is true only for a designed kit replaced in this fixture.
    4. The `goalkeepers` warning keeps its existing distance rule over the final keepers.
  - Export `keeperAvoiding(shirts: readonly ShirtDesign[]): string`: `keeper()`'s colour avoiding those shirts' visible torso colours and the grass. T546 uses it for the editor's goalkeeper draft (KIT-8: a new draft starts from an automatically chosen colour distinguishable from the club's own three kits). Test: "keeper draft avoids the club's three kits".
  - Expectations that move because torso sampling replaces disc sampling are updated in their tests and listed in this task's result.
- `match-appearance.ts`: each side records `shorts`/`socks` from `wornKit` and `keeper` from the selection, with `goalkeeper = keeper.shirt.primary`; the appearance is version 2. `captureAppearance` still freezes only on first settlement.
- `identityPacking.ts`: no stream format change; version checks accept 1 and 2 through the schema.
- `matchAppearance.ts` (UI read model): `SideLook` adds `kit: WornKit`, `keeperKit: WornKeeper` and `keeperFallback: boolean`, and keeps `shirt` and `keeper` so `Pitch.tsx` still compiles. For a v1 side, `kit` comes from `startingShorts/Socks(side.shirt)` and `keeperKit = automaticKeeper(side.goalkeeper)`. `UNRECORDED_LOOK` gains matching stand-ins.
- Do not touch UI components; T544–T546 consume these exports.
