## goal
Draw the dead interval before a corner, free kick or goal kick — the ball being placed and the players walking to their places — in about 1.5 real seconds at every speed, with routes scaled by one factor and nothing else on the timeline changed.

## acceptance
- [ ] `presentationClock.ts` derives the preparation intervals from frame data both models already carry: for each restart event (`kind: 'restart'`, `restart` corner, freeKick or goalKick) the running-time span from the ball going dead to that restart's kick. A test on one fixture of each model asserts where a corner's interval begins and ends.
- [ ] The presentation clock's state is running match seconds. Running play advances `speed × 60 / WATCH_MINUTE_MS` seconds per real ms; inside a preparation of D seconds it advances at the larger of that rate and `D / SET_PIECE_PREPARATION_MS` (new export, 1500). Seeking (WEB-23), speed changes and the goal hold (WEB-94) keep their behaviour in match time.
- [ ] `presentationClock.test.ts` cases: "a 32 s corner preparation takes 1.5 real s at 1x and 2x"; "at 16x a preparation shorter at running speed keeps running speed"; "throw-ins, kick-offs and penalties keep running speed"; "a speed change inside a preparation keeps the match second"; "seeking into a preparation lands on that match second"; "frames, samples and ball times are read, never changed".
- [ ] Goal feedback and the possession cue read the running-seconds clock; their existing cases pass with the new clock.
- [ ] `set-piece-defence.spec.ts` and `stable-controls-and-pacing.spec.ts` assert the compressed preparation (players still travel, no position jump) for the batch run.
- [ ] Task checks (ARCH-30): typecheck, lint, format:check, `vitest run --changed`, `pnpm run build`.

## impl notes
- Presentation only (MATCH-7, MATCH-12): no engine, record, frame or seed change, and the presented clock simply runs through the preparation faster; the added time and settled facts stay the engine's.
- The ball going dead is the end of the last event before the restart (where `holders` turns '' or the samples' phase turns 'restart'); the kick is the restart event's own time. On the pre-feature path one trace step holds the whole preparation (for example a corner's 32 s dead and 3.2 s kick), on the candidate the participants arrive and wait; both compress the same way.
- Replace `presentationLength` and `clockAt`/`runningSeconds` by running-second functions where callers need them; the progress bar and seek map running seconds directly.
- Keep `SET_PIECE_PREPARATION_MS` the only number for the preparation; the owner reviews it in play before any further dead-ball compression (ideation/match-viewing-pace-and-freedom).
