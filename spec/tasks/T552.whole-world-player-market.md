## goal
Make the whole simulated player world browsable and approachable independently of scouting recommendations.

## acceptance
- [ ] All represented active club players and scout/free-agent offers are discoverable; external candidates are not restricted to the scout shortlist and own players cannot be re-signed.
- [ ] Bounded worker query pages expose result total and stable identity, club/league provenance, name/recommendation/league/team/position/line/fit filters and ascending/descending name/age/OVR/potential/fee/wage sorts with stable ID tie breaks; query/filter changes reset/clamp page and retain valid task context.
- [ ] Actual recruitment, loan and negotiated bids from a non-recommended club player preserve player identity, source affiliation, fee, registration/cash/window checks and duplicate/stale-target protection; existing index-based scout commands and saved pending bids keep working.
- [ ] Unit tests exercise pagination boundaries, filter and sort combinations, cross-country players, no mutation on reads, stale-world queries, non-scout approaches, move continuity and legacy bid compatibility.
- [ ] Ordinary worker views remain bounded to the existing shortlist; a world query never publishes all rosters/previews. Only current-page/detail candidates get expensive recruitment previews.
- [ ] Run changed/affected isolated unit tests, typecheck, lint, format check and the web build; update relevant browser journeys but leave browser execution to the coordinator batch gate.

## impl notes
- Build a dedicated world-market module over existing continuousSquad/npcSquad and club records, plus generated scout/free-agent offers. Reuse existing value/wage, transfer, signing, registration and person-continuity machinery. Do not replace the legacy transferOffers generator or invalidate pending bids.
- Add a typed paged runtime request/reply and client method, following manager-history/league-fixtures query patterns; include active world identity and reject stale requests/replies. Keep ordinary View.transfers as the legacy shortlist so calendars do not ship all players.
- Extend recruitment/bid target handling with a stable player/source-club reference resolved on the engine. Do not translate filtered row/page offsets into legacy candidate indexes. Pin the actual offer terms as existing TransferBid.offer does. Revalidate source, ownership and availability at settlement and never permit a player to remain in both clubs.
- The UI RecruitmentDesk can own the complete market and negotiation boards. Give clear filters, total/page controls, a selected-player detail, sorting direction and a reset action; use theme tokens and retain comparison/selection context by ID. Approach affordances explain real eligibility rather than hiding non-scout players.
- Use small deterministic fixtures to test the query and transfer rules; do not add full-season simulations to unit checks. Touch declarations may be expanded only for necessary directly-related contracts/tests; keep Rich.tsx, App.tsx, Operations.tsx and policy areas owned by the places-office lane.
