## goal
A club nobody owns takes its match context from its own named manager on the own club's formula (MATCH r32), so a manager counts the same for every club; it ships as match-model revision 3, which careers on revisions 1 and 2 take prospectively (ideation own-club-match-edge, choice C, part B).

## acceptance
- [ ] `MATCH_MODEL_REVISIONS` lists `continuous-aggregate-3` after 1 and 2 and `MATCH_MODEL_REVISION` is 3, which `MATCH_MODEL_RELEASE` names; the tests that name `continuous-aggregate-3` as an unknown future revision name `-4`.
- [ ] `prepareMatch` reads the model it plays (the world's active model, or the grid setup's test-only `model`): on revision 3 a club nobody owns adds `(clubManager(w, club).ability − 50) / 4` and morale 0 (neutral 60); revisions 1 and 2 and the pre-feature model keep the flat 4. The own club's terms (manager ability, morale, style strength, home strength) are unchanged on every revision. Both paths read the same context (the aggregate's `summaryMatch(prepareMatch(...))` and the grid setup).
- [ ] `clubManager` draws nothing new: the manager a club shows in the market (STAFF-17) is the one whose ability plays, and no generation, recruitment or finance stream moves.
- [ ] A world on revision 2 moves to revision 3 through the existing activation writer at the next safe boundary (T435's path): tracking boundary and coverage kept, settled records keep their revision, only unsettled fixtures play revision 3.
- [ ] Tests (`packages/engine/src/match-model.test.ts`): "revision 3 gives a club nobody owns its manager's context" (two NPC clubs whose managers differ in ability: the prepared strength gap moves by the ability difference / 4, morale contributing 0), "revisions 1 and 2 keep the flat 4" (same fixture, strengths equal to the pre-change values), "a revision-2 world moves to revision 3 at the safe boundary"; pass under the default and the release-on vitest config.
- [ ] The facts digests of `grid-throughput.test.ts` and `full-model-throughput.test.ts` that move are re-recorded with the old values in their history comments and a one-line reason (revision 3's context); positions digests move only where an NPC side's strength changed.
- [ ] `full-model-throughput.test.ts`'s fixture-time case still holds ARCH-31's 1 ms median; if `clubManager`'s cache misses show in the profile, name the cost in the result rather than skipping clubs.
- [ ] Task checks (ARCH-30): typecheck, lint, format:check, the changed unit tests (`vitest run --changed`) under both configs, `pnpm run build`.

## impl notes
- `prepareMatch(w, f, math)` currently builds `context` as `ownSide === side ? ownStrength(side) : 4` (match.ts ~284). Pass the playing revision in (an optional argument or read `activeMatchModel(w)` with the grid setup's override) and gate with `matchModelNumber(revision) >= 3`; keep the home 3 as it is.
- Keep revision 1's aggregate stream names on revision 3 too (as T435 did for revision 2), so the only football change is the context term.
- Manager styles stay own-only (STAFF-14); a club nobody owns adds no style strength.
- The own-edge probe (`scripts/own-edge-probe.ts`) and the outcome-curve read follow in T467; no calibration here.
