## goal
The release knows what an own match costs and has taken the cheap wins: settling an own match (record, script, material) and staging one match minute are measured against the grid on the same machine, and the writer's search and the staging's hot paths are made faster wherever the output stays identical.

## impl notes
- What is known (T822, measured 261111 on this host under load): the prototype's writer about 250 ms a match, its staging about 8 s for ninety minutes; the grid plays an unobserved own match in about 0.7 s and an observed one in about 1.2 s with its frames. The watched match no longer waits for the whole staging (T834), so the two numbers that matter are the settlement of a skipped own match and the staging time of a match minute against the 0.75 real seconds a match minute lasts at 16x (→WEB-32).
- Order of work, one change at a time, the log in the report:
  1. the writer's search: the next touch is the cheapest of every floating touch of the match, scanned in full each step. Index the floating touches by side and start cell and visit cells in ascending table distance from the ball's cell, stopping when no nearer cell can hold a cheaper touch; ties must break exactly as the full scan does (row id) so the script is byte-identical.
  2. the writer's per-minute bookkeeping (quotas, the pace terms) recomputed from scratch each step.
  3. the staging's per-tick allocations: `Vec` tuples created and dropped a player a tick, repeated `nominalSpot` for the same ball within a tick, the marking assignment recomputed each tick when nothing it reads moved.
  4. `stageFrames`' sampling and the frame's arrays.
- `scripts/perf/profile.mjs --workload <name>` shows where the time goes; profile before each step.
- The staging's floats must give the same frames to the last bit for a change to count as result-identical: reordering float additions is a change of output — keep the order.
- No absolute target exists (→ARCH-34): faster than the baseline on this machine beyond the noise is the success, and the grid's numbers are context for the release's report.
