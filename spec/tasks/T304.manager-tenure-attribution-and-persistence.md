## goal
Preserve exactly who managed each newly tracked own-club result without inventing old attribution or changing football outcomes.

## acceptance
- [ ] Add stable own-club tenure facts with retained manager/person identity where known, name, interim status, exact known appointment/departure boundaries, known earlier service year and explicit tracking coverage. Reappointments and same-day replacements are distinguishable; renewals and tactic changes do not split service, and an interim with no match remains a real tenure.
- [ ] Cover founding, direct/delegated appointments, replacement, resignation, retirement and contract expiry through shared helpers. Freeze the actual tenure on every newly settled own match and on the source of each settled final league finish, cup title and promotion, before later personnel/season changes. A group reassignment is not promotion; actual country/tier/group and division moves remain identifiable.
- [ ] Duplicate settlement, repeated save/load and season closure leave the same unique sources and tenure links. Cup-final credit stays with its responsible manager even if he leaves before season close; the league final table and actual promotion use their own settlement boundaries. Existing match scores, money, random state, career dates, appointments and contract effects remain unchanged apart from the new attribution facts.
- [ ] New careers track from founding. Supported earlier careers start only at a validated writer-activation boundary, retaining their existing records and known earlier service year. Missing old match links remain absent; never infer them from names or saved prose. Defer activation until any queued/revealed own-match playback completes, and preserve read-only and failed-write/export recovery behavior.
- [ ] Validate and compact all new facts, source/date precision and references losslessly. Keep prior supported checkpoint readers and full-model metadata; the new declared manager-history container is refused by an older reader and is never silently written as a pre-feature container. Reject dangling tenure links, duplicate source keys and malformed compact metadata before activation.
- [ ] Add focused cases in `manager-history.test.ts` for `renewal keeps a tenure`, `reappointment and same-day interims keep separate identities`, `duplicate fixture keeps one attribution`, `cup winner keeps its manager after replacement`, `season close credits final table and promotion before departures`, and `tracking leaves seeded football and finance unchanged`. Use shared cached/simulated worlds for setup and simulate only the transition being checked.
- [ ] Add contract/packing/persistence/runtime cases for `old world stays untracked until writer activation`, `known service year is not the tracking date`, `queued playback delays attribution activation`, `read only does not upgrade`, `round trip preserves missing and present links`, `invalid reference and source duplication refuse activation`, `new container refuses an older reader`, and `failed activation keeps the previous checkpoint`. Tests use small synthetic facts rather than generating a century.
- [ ] Run task-tier type/lint/format/changed-unit checks and production build under ARCH-30. Leave browser execution and the complete century capacity measurement to the final batch/T306; no whole suite or browser spec runs in this task.

## impl notes
- Put shared fact types and their narrow validators in `packages/contracts/src/manager-history.ts`, used by the world schema and codec. Use optional `World.managerHistory` with a tracking boundary, monotonically allocated tenure IDs, tenure facts and unique outcome-source attribution; add optional `MatchRecord.managerTenure`. Retain `SeasonArchive.manager` and all existing event text as historical facts.
- A tenure fact carries a stable ID, manager ID, optional person ID, display name, interim flag, tracked-from date, optional exact appointed/ended dates and known-since year, plus departure information when recorded. Allocate deterministic IDs from the club and a retained serial without consuming the simulation RNG; names and date strings are not identities. Preserve ordering when several tenures begin/end on one day.
- Outcome attribution uses a discriminated source key: own `league-finish` by season and country/tier/group, `cup-title` by season and competition, and `promotion` by season and club. Store the responsible tenure and actual settlement date; promotion also retains its structured from/to division. Read ranks, winners and competition names from their authoritative live/archive source instead of persisting a second set of summary totals.
- `packages/engine/src/manager-history.ts` owns `ensureManagerHistory`, `recordManagerTenureChange`, `attributeManagerMatch` and `attributeManagerOutcome`. Instrument both installation and interim paths in `ops-staff.ts`, the common own-match settlement in `season.ts`, domestic/continental title settlement and final table/promotion settlement. Include retained Super Cup titles even where ordinary prize/news handling excludes them. Reuse existing career-date and knockout/league facts; never parse event prose to find a manager.
- Keep supported-career preparation pure until the existing host writer-upgrade path commits it. Tracking activation is independent of the full-match-model release switch; do not turn that model on/off or change its metadata. Omit the new heavy fact arrays from ordinary world projections immediately, before the detail query exists.
- Define `MANAGER_HISTORY_CHECKPOINT_SCHEMA` in `versions.ts` as the next distinct container after `FULL_MODEL_CHECKPOINT_SCHEMA`; use that constant throughout selection/validation. A world carrying manager facts uses it whether the full model is active or not. Preserve recognized earlier containers and reject cross-container feature mismatches.
- `managerHistoryPacking.ts` owns lossless fact/link packing and validation, called by the existing pack/unpack path; no separate save, upload or persistence store. Reconcile latest shared settlement/activation changes from ongoing full-model work before implementation; overlapping touches must not be edited concurrently, and none of that work's existing task contracts are changed here.
