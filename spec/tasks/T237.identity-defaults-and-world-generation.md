## impl notes
- Read `docs/CLUB-IDENTITY-CONTRACT.md` sections named below; it owns the stable interfaces used in this task.
- Prerequisites: T235, T236. Read their implemented interfaces/results before editing; extend those modules rather than reproducing a prerequisite.
- Read design §§2–3. createIdentityDraft depends only on country/seed/color; the own ID is country + :club. Use its documented six preset compositions and fixed default shirts, not Math.random or a sporting RNG.
- createWorld currently calls createBase then prepareSeason, which creates representatives. Install missing identities after initial representative creation, then copy the optional explicit own identity. Validate that explicit identity and its primary before constructing the canonical world.
- For adoption, compute the full legacy map before assigning any identities. Missing identity.colours=[club.color, legacyCrest.secondary], its crest is the exact legacy copy, and shirts use those representatives; keep existing club.color values. The own founding/edit primary is synchronized only where the contract says so.
- Ensure ensureRepresentatives installs identities for newly appended clubs without overwriting any existing one. Export leaf APIs without forcing the UI to import the engine barrel.
- This task does not activate missing identities from disk; that is the supported-career activation task. Update the old new-world uniqueness test only where deliberate custom own designs invalidate that old assumption; keep exact legacy/NPC stability assertions.
- After the new producer is correct, run the repository golden updater and inspect the diff: expected cosmetic fields may change; sporting totals or random player changes are a failure.
