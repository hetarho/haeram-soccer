## goal
Add match-kit selection and automatic reset without applying a stale choice to a different fixture.

## acceptance
- [ ] The command is {type: match-kit, fixtureId, role: home|away|third|null}; bridge and handler share the exact role vocabulary.
- [ ] identity-operations.test.ts cases chooses for a league/cup/continental next own fixture, null restores automatic selection, stale/missing/settled/NPC fixture leaves the world unchanged, and choice does not edit saved shirt designs pass.
- [ ] A manual role that clashes is accepted; the selector reports the warning independently. The engine must not turn the warning into a mandatory decision event.
- [ ] The handler resolves nextOwnFixture at execution time across all competitions, not from the UI’s cached fixture list. Success increments revision only through operate.
- [ ] host.test.ts verifies duplicate and stale request protections for this command; ordinary owner-decision autosave remains in effect.
- [ ] Targeted verification passes: `pnpm exec vitest run packages/engine/src/identity-operations.test.ts apps/web/src/runtime/protocol.test.ts apps/web/src/runtime/host.test.ts && pnpm run typecheck`.

## impl notes
- Read `docs/CLUB-IDENTITY-CONTRACT.md` sections named below; it owns the stable interfaces used in this task.
- Prerequisites: T240, T239. Read their implemented interfaces/results before editing; extend those modules rather than reproducing a prerequisite.
- Read design §§2 and 5. Match the payload ID to nextOwnFixture(w).id before any write. A null role clears that named upcoming choice; otherwise store a copied {fixtureId,role}.
