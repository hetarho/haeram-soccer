## goal
The game in play commits a large checkpoint safely: the committed generation is copied to IndexedDB as the recovery predecessor, the candidate replaces the single active localStorage copy, the manifest switches last.

## acceptance
- [ ] Limits (SAVE-4): `CHECKPOINT_LIMIT = 3 MiB`, `TOTAL_LIMIT = 3.5 MiB` (unchanged), import file cap 8 MiB everywhere it is enforced (`persistence.ts`, `protocol.ts`, `GameSlotScreen.tsx`, `App.tsx`), inflate limit 32 MiB (`compression.ts`).
- [ ] `previousStore.ts`: `IndexedDbPreviousStore` on database `haeram-soccor`, object store `checkpoints`, key `previous`, `available()`, `read()`, `write(raw)` (write then read back equal), sharing the existing `haeram-soccor` database opener with the parked-games store (bump the DB version and create the new store in `onupgradeneeded` without touching `games`).
- [ ] `SaveRepository.commit` (SAVE-3): 1) if a committed generation exists, copy the raw active checkpoint to the previous store and verify; 2) `setItem('haeram-soccor:slot:a', candidate)` and read back; 3) write the manifest (`{ generation, key: 'slot:a' }`); a failure at 1 or 2 leaves the committed generation loadable and reports the typed error (quota → the existing message).
- [ ] `load` (SAVE-3): manifest generation from slot:a; else the newest valid of slot:a and the previous store; corrupted active → recover the previous copy with the existing `이전의 정상 체크포인트로 복구했습니다.` notice.
- [ ] Fallback without IndexedDB: two localStorage slots a/b (today's protocol) while `2 × checkpoint ≤ TOTAL_LIMIT`, otherwise commit to slot:a only and add once the notice `이 브라우저에서는 복구용 이전 저장본을 둘 수 없어요 — 내보내기로 따로 보관하세요.`
- [ ] Existing two-slot layouts (slot:b present) still load (the newer valid slot) and are migrated to the new layout on the next commit (previous copy written to IndexedDB, slot:b removed after the manifest switch).
- [ ] Tests: `repository.test.ts` cases `keeps the committed generation in IndexedDB before replacing the active copy`, `recovers from IndexedDB when the active copy is corrupt`, `falls back to two slots without IndexedDB`, `refuses a candidate over 3 MiB`, `migrates a two-slot layout`; existing persistence tests updated; e2e `recovery.spec.ts` passes.
- [ ] typecheck, lint and unit tests pass.

## impl notes

- Total budget check counts only localStorage keys (the IndexedDB copy is not part of TOTAL_LIMIT).
