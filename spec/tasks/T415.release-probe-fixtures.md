# T415 Explicit test releases and a release-on unit probe

## goal
Give tests an explicit disabled release and a unit run with the release switch on, so the T286 prerequisite lanes can make their files pass under both switch states before the switch flips.

## acceptance
- [v] `tests/fixtures/worlds.ts` exports `DISABLED_RELEASE` (`{ ...MATCH_MODEL_RELEASE, enabled: false }`) beside `ENABLED_RELEASE`, and `simulatedWorld(input, span, release)` takes an optional release (default `MATCH_MODEL_RELEASE`) that it passes to `createWorld` and adds to its cache id.
- [v] The shared world cache key (`cached` in `tests/fixtures/worlds.ts`) includes the effective default release (`MATCH_MODEL_RELEASE.enabled`), so a world built with the switch off is never served to a run with it on.
- [v] `vitest.release-on.config.ts` merges `vitest.config.ts` and adds the setup file `tests/setup/release-on.ts`, which turns `MATCH_MODEL_RELEASE.enabled` on before any test file runs; `package.json` gains `"test:unit:release-on": "vitest run --config vitest.release-on.config.ts --exclude '**/*.contract.test.ts'"`. Production code never reads the probe.
- [v] `tests/fixtures/worlds.test.ts`: "simulatedWorld pins the release it is given" (a `DISABLED_RELEASE` world carries no `matchModel` and an `ENABLED_RELEASE` world carries one, whatever the default) and "the world cache separates the default release" pass under `pnpm exec vitest run tests/fixtures/worlds.test.ts` and `pnpm exec vitest run --config vitest.release-on.config.ts tests/fixtures/worlds.test.ts`.
- [v] Task checks (ARCH-30): typecheck, lint, format:check, `vitest run --changed`.

## impl notes
- The probe mutates the exported release object (cast away `readonly` in the setup file only); `createWorld`'s default parameter and the host's `options.release ?? MATCH_MODEL_RELEASE` read that same object at call time, so both follow it. Keep the object unfrozen; do not add an environment read to engine or web code.
- Lanes T416–T419 and T420 run their files with `pnpm exec vitest run --config vitest.release-on.config.ts <files>` (no environment prefix, which worker sessions cannot run).
- `DISABLED_RELEASE` is for tests whose subject is the pre-feature path, which careers whose rules never activate keep playing (→SAVE-23); a test about what a new career plays uses `ENABLED_RELEASE` or `withCandidateModel`.
- Do not run the whole release-on tier here; the lanes measure their own files and T420 measures the tier.
