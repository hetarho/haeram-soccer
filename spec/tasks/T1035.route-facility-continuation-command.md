## goal
Let an owner save an explicit per-part checkbox change through the existing game command path.

## acceptance
- [ ] Deterministic, task owner/unit. A validated `facility-auto-upgrade` command changes only the named part's setting. Enabling an idle part arms the next completion without starting work, charging cash or changing an existing work. Disabling clears eligibility and leaves active work intact. Duplicate setting requests do not add duplicate records. Maximum parts cannot be armed.
- [ ] Deterministic, task owner/unit. A successful manual start during a fund wait consumes the pending authorization and leaves the setting armed. A stale quote or insufficient funds preserves the pending state. Use the existing manual quote evidence and add compact command coverage for the uncovered state changes.
- [ ] Deterministic, task owner/unit. The worker boundary accepts only a known part and a boolean with no extra fields. Run `vibe check --tier task` once before committing. Hand off the ordinary command acknowledgment, projection and durable save journey to the shared host for integration coverage.

## impl notes
- Add `{ type: 'facility-auto-upgrade'; part: FacilityPart; enabled: boolean }` to the shared Command union and to the strict runtime command schema. Use explicit set semantics so a confirmed retry can never invert a checkbox. Keep the existing revision and owner-command path through `operate` and `investmentCommand`. An owned career setting is separate from preferences and triggers the ordinary decision save. No host progression branch is needed.
- Reuse T1033's state shape. Set armed when enabling a previously off part below the maximum, preserve awaiting-funds on repeated enable, and remove only the named part when disabling. Never authorize an idle part just because it was enabled again. Use the existing maximum and part helpers.
- Add a club event for an actual setting change using T1034's canonical resource IDs with the facility name. Use a setting event kind distinct from paid work and a neutral command outcome title. Keep the existing financial and construction ledger entry points tied to work starts. The event need not create new news.
