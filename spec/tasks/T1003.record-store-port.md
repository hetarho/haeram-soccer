## goal
The engine-facing `RecordStore` port, the versioned SQLite save schema and a SQL implementation over a small driver interface exist, with a `node:sqlite` in-memory driver that tests and tools use.

## acceptance
- [ ] `packages/contracts/src/record-store.ts` defines the synchronous port (no SQL, no SQLite import): `RecordStore`, `StoredRow`, `TableName`, and `attachRecordStore(w, store)`, `recordStoreOf(w)` (a `WeakMap`), `cloneWorld(w)` (= `structuredClone` + re-attach the same store).
- [ ] `apps/web/src/adapters/saveSchema.ts` holds `SAVE_SCHEMA_VERSION = 1` and the DDL below; `sqlRecordStore.ts` implements `RecordStore` over `SqlDriver` and creates the schema on an empty database (`PRAGMA user_version = 0`), and opening a database whose `user_version` differs throws `SaveCompatibilityError` (SAVE-11).
- [ ] `tests/fixtures/node-sqlite.ts` exports `nodeSqliteDriver(path = ':memory:')` (over `node:sqlite` `DatabaseSync`) and `memoryRecordStore()`.
- [ ] Unit tests (node driver): put/get/has/keysWithPrefix/range by index and seq order, `write` is one transaction (a throwing write leaves the database unchanged), cold flag filter, schema-version refusal.
- [ ] Task stage, owner implementer: `vibe check --tier task` passes; the architecture/lint rules still forbid SQLite imports in `packages/engine` and `packages/contracts`.

## impl notes
- Port (contracts, synchronous):
  - `type TableName = 'meta' | 'world_field' | 'person' | 'squad' | 'player_record' | 'own_match' | 'season_archive' | 'event' | 'news_bucket'`.
  - `interface StoredRow { table: TableName; key: string; seq: number; cold: boolean; data: string; year?: number; opponent?: string; kind?: string; id?: string }` — `data` is the JSON text of one record.
  - `interface RecordStore { get(table, key): StoredRow | undefined; has(table, key): boolean; keysWithPrefix(table, prefix): string[]; rows(table, filter?: { cold?: boolean; year?: number; opponent?: string; kindPrefix?: string; seqFrom?: number; seqTo?: number; limit?: number; descending?: boolean }): StoredRow[]; count(table, filter?): number; write(changes: { put: StoredRow[]; delete: { table: TableName; key: string }[]; meta?: Record<string, string> }): void; meta(): Record<string, string>; close(): void }`. Every multi-row read is ordered by `seq` (ARCH-36).
- Schema v1 (every record table: `key TEXT PRIMARY KEY, seq INTEGER NOT NULL, cold INTEGER NOT NULL DEFAULT 0, data TEXT NOT NULL`, plus): `own_match` + `id TEXT, year INTEGER, opponent TEXT` (indexes `(year, seq)`, `(opponent, seq)`, unique `id`); `season_archive` + `year INTEGER`; `event` + `year INTEGER, kind TEXT` (indexes `(year, seq)`, `(kind, seq)`); `news_bucket` + `year INTEGER`; every table indexed on `(cold, seq)`. `meta(key TEXT PRIMARY KEY, value TEXT NOT NULL)`. `PRAGMA user_version = SAVE_SCHEMA_VERSION`. `WITHOUT ROWID` is not needed.
- `SqlDriver` (in `sqlRecordStore.ts`): `{ exec(sql: string): void; run(sql: string, params?: unknown[]): void; all<T>(sql: string, params?: unknown[]): T[]; get<T>(sql: string, params?: unknown[]): T | undefined; transaction<T>(fn: () => T): T; close(): void }`. Prepared statements may be cached per SQL string.
- `keysWithPrefix` uses `key >= ? AND key < ?` with the prefix and prefix + `'￿'`.
- The engine never imports the adapter; tests reach it through `tests/fixtures/node-sqlite.ts` (engine testkits already import `tests/fixtures`, e.g. `season.testkit.ts:15`). Node 24.22.1 ships `node:sqlite` without a flag (SQLite 3.53.4; `DatabaseSync#serialize` exists).
- Nothing calls the store yet; T1004 maps the world onto it.
