# T043 One day order for every progression mode
> st:todo | ssot:LEAGUE-11 WEB-5 ARCH-5 | base:LEAGUE@5 WEB@48 ARCH@7 | dep:- | touches:packages/engine/src/season.ts packages/engine/src/calendar.test.ts packages/engine/src/season.test.ts | lane:day-order

## goal
A round step or a season run lives through the same days in the same order as day steps, so every progression mode records identical facts.

## acceptance
- [ ] `advanceRound` plays its round by stepping days with the same per-day function `advanceDays` uses: midweek ties on their own day before the round's league matches; a league match day plays the matches, then the round's settlement, then that day's club business (clubDay).
- [ ] `closeSeason` records the close on day SEASON_END_DAY + 1 whichever path calls it.
- [ ] calendar.test.ts "every progression mode records the same facts": for two seeds (ENG `haeram-demo`, one more country) over 1.5 seasons, (a) `advanceDays(w, 1)` repeatedly, (b) `advanceRound` with `closeSeason` once `w.round === 46` (as the host's advance and season commands do), (c) `simulateSeason` then days — `canonical(world)` equal after normalising `revision` and `receiptIds`.
- [ ] The seed `haeram-demo` ENG week of day 32 (cup) / day 35 (league) now plays the cup first in every mode (covered by the test above).
- [ ] `pnpm run typecheck && pnpm run test:unit` pass.

## impl notes
- Split the per-day body of advanceDays into an internal `stepDay(w, capture, observe)` without the critical/bankrupt guard. advanceDays keeps its guards and range check and loops stepDay. advanceRound(w, settlement, observe) loops stepDay until `w.round` grows by one or the club is bankrupt; like the old round step it ignores `w.critical`, so simulateSeason and portable fixtures never stall; the host still breaks on critical after a round.
- Rename the current round body (league fixtures → settleTraining → due ties → settleRound → snapshots → manager market refresh → revision++) to an internal `playRound`, called only by stepDay on a league match day.
- Do not touch apps/web/src/runtime (host.ts, client.ts) or index.ts: they call advanceRound/closeSeason/simulateSeason, whose behaviour changes underneath; another session edits apps/web/src/runtime concurrently.
- closeSeason: if currentDay is below SEASON_END_DAY + 1, move the calendar there first, matching advanceDays, which closes on that day.
- A whole-round command from a saved mid-week day continues from the next day; nothing to migrate.
- Revision still counts commands and days differently per mode; it is a counter, not a fact (→ARCH-6), hence the normalisation.
- Keep a season under ~1.2 s in Node (measured 261012: 1.0–1.2 s on either path).
- Goldens change; leave them to T047. No version bump.
