## goal
Round-trip complete current-season aggregate records and prospective model metadata without loss or save-limit relaxation.

## acceptance
- [v] Implement the container declared by T273 with exact compact streams for NPC team/player aggregates, participant identity/contributions, competition indexes, tracking boundaries and model metadata. Reconstruct the canonical DTO exactly, preserving ordering and optional presence.
- [v] Supported older containers/4.0.0 worlds remain readable with genuinely absent historical counters. Future/unknown containers, invalid widths/counts/references, duplicate ledger keys and truncated streams fail before activation with the appropriate typed error.
- [v] Preserve current active/previous-save commit ordering, raw failed-write data and export recovery. Stored own records retain all advanced values, material and actual kit/crest appearance fields.
- [v] Tests cover `round trips full aggregate and coverage metadata exactly`, `distinguishes missing from zero`, `preserves departed and transferred contributors`, `reads supported identity-era checkpoints`, `refuses a future model container`, and `keeps current and previous on failed writes`.
- [v] Add compact boundary/property fixtures for large counts, empty competitions and malformed indexes; do not prune fields or increase limits. The full century workload is reserved for T286.
- [v] Update SAVE-FORMAT and the portable fixture only for the declared compatibility surface. Task checks and build follow ARCH-30.

## impl notes
- `docs/MATCH-MODEL-CONTRACT.md` stays with the grid stream (T274) while the streams run in parallel: read it, do not edit it, and list any contract-document gap in the result's limits for T286's final documentation pass.
- Use T273's exported DTOs/container constant and existing identity packing. This task owns `matchModelPacking.ts`; the general packer delegates to it rather than encoding another private copy.

- No runtime activation is performed here. The supported-writer transformation belongs to T286 after the accuracy/throughput gates.

## result
- outcome: Container 3 now has a codec and is used. `checkpointSchemaFor` writes container 3 for exactly the worlds where `carriesMatchModel` is true (metadata, NPC season or a record `model`) and keeps container 2 for every other world. `SUPPORTED_CHECKPOINT_SCHEMAS` is [1, 2, 3]. No activation is performed. The new `apps/web/src/adapters/matchModelPacking.ts` is the only encoder, and `pack`/`unpack` delegate to it. It writes one optional section, `model`: `version: 1`, a literal `revisions` table, a `state` row (activation date/revision, tracked boundary, coverage), record-model runs and `season`. `season` holds a header plus four sparse tables (competitions, club rows, player rows, per-club contributions), in original order, with string refs into the shared `dict`. Each column is stored either as a plain bit column or as 0/1 presence bits plus its nonzero values, whichever needs fewer bits. A stored zero stays zero, an empty competition keeps its row, and an absent field stays absent. `matchModel`/`npcSeason` are removed from `compact1.world`, and a payload that carries them inline fails to decode. The reader checks every width, count, ref, run and stream, and requires each one to be read to its end. It also refuses duplicate ledger keys (competition, club, player, player-club pair) and unused revisions. `readCheckpoint` runs `readMatchModelFormat` before `unpack`, so a section version above 1 or an unknown revision is a `SaveCompatibilityError`. If the declared container and the payload disagree (model data in container 1/2, or container 3 without any), that is also a `SaveCompatibilityError`: the file is kept and never recovered over. `recognizedLegacy` is false for container 3. Commit ordering, previous copies and export are unchanged, and container-1/2 worlds load with their counters genuinely absent. Measured on a synthetic set (8,406 players, 467 club rows): the encoded checkpoint grows from 96,487 to 189,250 characters.
