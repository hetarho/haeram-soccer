# T999 Checkpoints are always gzip, with no Brotli or CJK text codec

## goal
Every checkpoint and export is written as `gzip-base64`; the pure-JavaScript Brotli fallback, the `brotli` dependency and the CJK/BMP text encodings are gone, so no autosave can fall onto the minutes-long codec.

## acceptance
- [v] `encodePayload(bytes)` always gzips and returns `{ codec: 'gzip-base64', payload }`; it takes no budget predicate and never imports Brotli. `decodePayload` accepts only `gzip-base64`.
- [v] `SAVE_CODECS` is `['gzip-base64']`; a checkpoint whose codec is `gzip-cjk14`, `brotli-bmp127` or unknown is refused as a `SaveCompatibilityError` (kept, exportable, never overwritten — existing SAVE-11 path), covered by a unit test.
- [v] `dense.ts`, `bmp127.ts`, `recognizedLegacy` and their tests are deleted; `brotli` is removed from `package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml` `patchedDependencies` and `patches/brotli@2.1.0.patch`.
- [v] Task stage, owner implementer: `vibe check --tier task` passes.
- [v] Integration/CI handoff: affected e2e specs are updated or deleted as listed in impl notes; record them in result limits as not run locally (ARCH-30).
