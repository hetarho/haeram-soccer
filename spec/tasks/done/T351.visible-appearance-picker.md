## goal
Let the owner see each theme or language change take effect on the page instead of behind an opaque menu sheet.

## acceptance
- [v] The menu shows separate theme and language entries with the current choice; each closes the menu and opens a small centered picker for that preference over a light dim at every width.
- [v] Founding and slots open the same centered picker with both preferences. Retry, session-only and error feedback, focus trapping and the theme reveal are preserved.
- [v] Presentation journeys and web unit cases pass with typecheck, lint, format, presentation validation and build.

## result
- outcome: `Dialog` gains a `picker` mode (centered, 360px, light dim, no bottom-sheet slide). The settings context remembers which preference to open; `AppMenu` rows call it. Single-preference pickers hide the duplicate visible label.
- verified: 10 Chromium presentation journeys; 677 web unit cases; typecheck, ESLint, Prettier, presentation validation, build; 390px/1380px captures of menu, picker and the pixel switch. business.spec:67 (older operations addresses) fails identically on main without this change.
