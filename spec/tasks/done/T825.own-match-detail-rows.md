## goal
From any aggregate match — substitutions, dismissals, injuries, penalties, extra time and shoot-outs included — the engine can list every recorded action as one row with who made it, how it ended and who won the ball, and count those rows back to the match's record exactly, so the script writer has a complete and checked input.

## impl notes
- This is `scripts/export-settled.ts`' expansion (`expandGroup`, `swapOffsides`, the shots' sources, the fouls) moved into the engine and completed. Keep its fixed rules — rows in ascending line order, completed first, the failed ones taking their results in the listed order — so the same match always gives the same rows; `swapOffsides` is needed only for a revision-10 trace (revision 11 pairs offsides in the trace, T824).
- `MatchDetail` (engine-internal; integers only, →ARCH-9) keeps the row layouts and code lists of `scripts/match-proto/core/settled.ts` (`EVENT_KINDS`, `SET_PIECES`, `EVENT_RESULTS`, `SHOT_KINDS` + `'penalty'`, `SHOT_OUTCOMES`) with engine cells (0–39, the acting side's attack frame, no prototype remapping) and engine role ids, and adds:
  ```ts
  export interface MatchDetail {
    version: 1; id: string; length: 90 | 120; added: number[] /* minutes a period */; score: [number, number];
    sides: [DetailSide, DetailSide];            // tactic, lines in record order: { id, slot, role, position }
    stints: number[][];                         // [side, line, slot, fromMinute, toMinute]
    events: number[][];                         // …the prototype's ten columns, then period (0 regulation, 1 extra)
    shots: number[][];                          // …the prototype's twelve columns; kind may be penalty; source -1 or an event id
    fouls: number[][];                          // [fouledSide, cell, fouler, fouled, cardMinute or -1, penalty 0|1, period]
    incidents: number[][];                      // [minute, side, kind, line, otherLine or -1, reason or -1] in time order: yellow, secondYellow, red, sub, injury
    shootout: number[][];                       // [side, line, scored 0|1] in kicking order; empty without one
  }
  export function matchDetail(match: AggregateMatch, rosters: [Player[], Player[]], trace: AggregateAttributionTrace): MatchDetail;
  /** The record the rows count back to: team and player rows in the record's own layout. */
  export function recordOf(detail: MatchDetail): Pick<MatchRecord, 'score' | 'metrics' | 'detail' | 'players' | 'xg' | 'incidents' | 'regulation' | 'shootout'>;
  /** Structural problems: a row outside its actor's stint's period, an unknown line, a source that is not a completed attempt of its passer, a booked foul without its card. */
  export function detailIssues(detail: MatchDetail): string[];
  ```
- `recordOf` must not re-derive counters by hand: rebuild each side's ledger groups and per-line splits from the rows and run the ledger's and attribution's own counting (`aggregate/ledger.ts`, the credit code of `aggregate/players.ts`; export what is needed) so a definition has one home (→MATCH-13).
- What the aggregate path must hand over beyond T819's trace, added behind the optional trace so untraced calls cost and return what they do today: the shoot-out's kicks (takers in order and each outcome — `aggregateShootout` already walks them and returns only the score), each incident's line, and for a penalty which foul it is. Minutes of substitutions, cards and injuries are `participation.incidents`'.
- A stint bounds a player's rows by period only (the ledger gives moves no minute); the writer (T826) places them inside the stint's minutes.
- No match is skipped any more: the exporter's `skipReason` stays in `scripts/export-settled.ts` for its ten files only.
- Not in this task: writing a script (T826), calling this from match settlement (T833).
