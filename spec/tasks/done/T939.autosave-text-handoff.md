## goal
Measure whether posting the autosave world to the codec worker as one JSON string, which the worker parses, shortens the engine thread's stall at every autosave (SAVE-8) against posting the world object, and keep the change only if it does.

## acceptance
- [v] Engine-thread measurement (deterministic; worker, task stage): a script under artifacts/benchmarks/lifecycle-perf-261117/T939/ loads the stored 1950 world (`/tmp/claude-2378/-home-deep-haeram-haeram-soccor/df2135f9-ba36-4023-bb25-ee99a520d827/scratchpad/scout-play/world-1950.bin`) and times, in at least 12 interleaved pairs, the sending thread's real cost of each hand-off (`v8.serialize` and `MessagePort.postMessage` of the world object against `JSON.stringify` plus the string) beside the `structuredClone` round trip, reporting median ratios with intervals in a JSON file beside it.
- [v] The text hand-off is kept only when the sending-cost interval is below 1. Otherwise production code stays at the base, and the candidate patch (host and codec text job, codec units proving text and object checkpoints identical and failures answered) is kept beside the measurement; the result records the ratios without a speed claim (deterministic; worker, task stage).
- [v] ARCH-30 task-tier checks pass through `vibe check --tier task`; integration, contract and build stay with the coordinator's final batch gate (handoff only).

## result
- outcome: not kept, no speed claim; production code is as at base. On the stored 1950 world (26.3M JSON chars, 15 interleaved pairs, `node --expose-gc`) the acceptance proxy favours the text: `structuredClone(world)` against `JSON.stringify` plus `structuredClone(text)` has median ratio 0.627 with interval [0.598, 0.643] (order statistics 4 and 12 of 15, 96.5% coverage; medians 697 ms against 432 ms). `structuredClone` also deserializes, which a `postMessage` leaves to the receiving codec worker. Timing only what the sending (engine) thread pays, the text is slower: `v8.serialize` 1.306 [1.294, 1.335] (288 ms against 375 ms) and a real `MessagePort.postMessage` call 1.303 [1.278, 1.318] (284 ms against 369 ms). Kept, it would lengthen every autosave stall by about 30% (about 85 ms on this world), so F6's premise (1155-1299 ms of engine-thread clone) does not hold. `artifacts/benchmarks/lifecycle-perf-261117/T939/handoff.mjs` and `handoff.json` hold the measurement; `text-handoff.patch` keeps the unlanded change (host and codec text job, host.test types, a new codec.test.ts) for the record.
