# T832 post-match material from the script

## goal
An own match's shot map, heat maps, pass network and tactical report are read from its record and script — the same numbers whether the match was watched or skipped, in the stored form the game already keeps — so the map and the match seen cannot disagree.

## acceptance
- [v] `packages/engine/src/script/material.ts` exports `scriptMaterial(detail, script, own): MatchMaterial`; it fills the existing `MatchMaterial` rows through `MaterialTally` (`packages/engine/src/grid/record.ts`), whose layout, caps and schema do not change
- [v] `script/material.test.ts` (unit, the fixtures of T826 and hand-built scripts): `the pairs are the completed passes the script plays` (for every own pair, `network`'s count equals the script's completed pass beats from one to the other, restart deliveries that are recorded passes included, linking carries and heavy touches never), `the pairs sum to the own side's completed passes of the record`, `a player's average position is the mean of his scripted touches`, `the heat map holds a touch for every action a player starts and every pass he receives`, `the shot map has every recorded shot of both sides at its scripted point inside its recorded cell with its xG, outcome and header`, `the same detail and script give the same material`, `the rows pass the save schema's caps`
- [v] `script/material.report.test.ts` (unit): each of the tactical report's 30 slots a side is either counted from the record and script — attacks by lane and band, box and front-of-box entries, regains and losses by third, set-piece shots and goals, counter-attacks and their shots (the script's `counter` phase), duels won (tackles, take-ons) — or, when neither holds the fact, left 0 and named in the test's `unsupported` list, which is pasted into the result
- [v] `material.ts` uses the platform-stable arithmetic of T826 (the source scan of `script/portable.test.ts` covers it); `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`, `pnpm exec vitest run --project unit --changed "$GUSTA_DIFF_BASE" --passWithNoTests`

## impl notes
- Read `MatchMaterial` and `MATERIAL_LAYOUT` (`packages/contracts/src`), `MaterialTally` and `REPORT_SLOTS` (`grid/record.ts`), `packages/engine/src/material.ts` (decoding, `reduceSeasonMaterial`) first. `MaterialTally` is driven by calls (`touch`, `received`, `shot`, `aerial`, `regain`, …): walk the script's beats in order and make the calls a beat stands for — an action start is a `touch` at the beat's `from` with its phase, a completed pass a `received` at its `to`, a shot a `shot` with the detail row's xG and header, a tackle, interception or recovered loose ball a `regain` for the winner's side at the beat's end. Export from `grid/record.ts` only what is missing; do not change what the grid tallies.
- `own` is the own club's side; lines are the record's (the tally maps roster indexes to lines as it does today).
- A heat map is touches, an average position their mean, a pair the completed passes between two players (→MATCH-25): nothing is read from staged positions, so a skipped match has the same material.
- Report slots the new source cannot fill (aerial duels are the likely case: the record counts headers taken, not duels) stay 0; say which in the result so T839 can decide what the report shows for them.
- Not in this task: attaching the material to the record at settlement (T833), the pass network's drawing (T835).
