## goal
Use fast lossless gzip for IndexedDB checkpoints and exports when the complete candidate fits the portable budget, preserving compact fallback writes and fail-safe recovery.

## acceptance
- [x] The encoder accepts a fast gzip candidate only when the complete serialized envelope fits the chosen store's UTF-16 budget and the unchanged actual 8 MiB portable-file limit. Otherwise it keeps the existing quality-11 Brotli fallback; canonical compact facts, checksum input and codecs stay unchanged.
- [x] One IndexedDB availability decision in GameClient supplies the selected budget through validated worker requests and codec jobs, including writer upgrades. LocalStorage saves retain the existing compact path, per-checkpoint and two-copy limits. File exports may use the fast portable path.
- [x] The writer accepts larger IndexedDB active/previous copies only within both new bounds, preserves previous/active/manifest ordering and quota-failure behavior, and still rejects oversized fallback writes before modifying the committed save. Larger portable imports into fallback-only stores use compact re-encoding and preserve the old save on failure.
- [x] Add small independent compression-selection and exact-envelope/file-budget unit cases, protocol bounds and both storage-layout boundaries; update host/codec/persistence and browser coverage for the coordinator. Run affected units, typecheck/lint/format and build; the coordinator owns final integration/Chromium execution.
- [x] Re-measure the actual 84-season source using the production fast path: record file/checkpoint size, full encode/validate time and complete original-fact/news/stat round-trip equality. Compare against the recorded quality-11 baseline, without a universal mobile or 100-season capacity claim.

## impl notes
- From T675 measurement: a local rules-4.0.0 export at 2034 has 3,943 own matches and 16,145 events. Quality-11 encode/validate took 469 s without new summaries and 589 s with them; the gzip prototype took 1.10 s, generated 4,076,076 UTF-16 bytes / 6,113,492 actual UTF-8 bytes, and restored identical compact bytes. Quality 6 and 9 Brotli exceeded the old 3 MiB budget. This supports a separate IndexedDB limit, not removing original facts or weakening checks.
- Define INDEXED_CHECKPOINT_LIMIT and PORTABLE_FILE_LIMIT beside the existing CHECKPOINT_LIMIT and TOTAL_LIMIT in adapters/repository.ts. Keep CHECKPOINT_LIMIT as the fallback limit for existing consumers. The app's import-size check and worker payload checks reuse the portable constant.
- encodePayload receives an optional candidate acceptance predicate; without it the established compact path stays unchanged. encode builds one checksum and tests the exact complete envelope before choosing fast gzip. Clients that can store IndexedDB supply its budget through the request/codec boundary; fallback clients omit it. Export chooses the portable IndexedDB-size budget independently of local storage availability.
- No new package, database backend, save-codec vocabulary, gameplay version, retention expiry or clock policy. Existing unsupported versions and invalid saves retain protection. The new optional request budget is bounded and never authorizes exceeding storage/recovery checks.
- Preserve both source worlds and benchmark exports. Keep generated long measurements under .tmp during fixed-source verification, and record their final values in the session report.
