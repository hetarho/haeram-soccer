## result
- outcome: on the production build of 35d0a4bc (T516–T521, T524, T525; build f9962dfc3506e8ac), two reps at 1280×800 in headless Chromium on an M1 Max (10 logical CPUs, `navigator.hardwareConcurrency` 10, load 1.9–4.4 before each run) show the pace exactly and never stall. x10: 365 shown days (1950-08-02 → 1951-09-12) at 10.0 days a second, 0 stalls, gaps p50/p90/p99 100–101/107/111 ms, worst 113 ms. x1/x2/x5 over 30 days: 1/2/5 days a second, 0 stalls, worst 1019/519/216 ms. No main-thread long task in any run (the observer reports a 200 ms task in a probe page, so it works). Both fixture helpers were created in every run and none was terminated, so the fallback path never ran. The only calendar jump is the season close, 1951-06-19 → 08-01 (42 days in one step), the engine's close into the next season (→WEB-18: a season close is not a stop), not a clock skip. Against the Node simulation (x10 about 10 stalls, 8.9 days a second at depth 7) the browser on this machine does better: every x10 step lands inside its 100 ms interval with seven days of depth. No gap to explain. Render cost stays under the long-task threshold. The simulation's stalls came from a slower host's match days, which the M1 Max computes within the depth.
