## impl notes
- One line flips the model (`packages/contracts/src/match-model.ts`); the work is what assumed the old one. Find it by running the unit tier, then the integration files that play own matches (`tests/config/test-tiers.ts`, `tests/config/cold-costs.ts` names the heavy ones): each failure is either a test of the grid engine (pin it to `'continuous-aggregate-10'` through an explicit release — the grid stays in the tree until T844) or a test of the game (move its expectation to the scripted model: material from the script, no frames in the playback, `stagedPlayback` where frames are needed).
- `tests/fixtures/worlds.ts`' cached worlds rebuild by themselves (their identity includes the engine's sources); expect the first run to be slow.
- The host: nothing to change beyond T834 — it hands over whatever playback the engine returns. `apps/web/src/runtime` appears in touches for tests only.
- Activation is the existing prospective path (`activatesMatchModel`, `Host.adoptModel`): no save boundary, no migration, no resimulation; a playback under way in memory finishes on the model that settled it.
- Accuracy is reported, not a gate (→MATCH-28, →ARCH-31): the calibration read is T840's.
- T834's worker is the only way frames are made for a released own match; `buildFrames` is no longer reached by a released career and is removed with the grid in T844.
- If the capacity benchmark fails, that is a blocker for this task: say which limit and by how much; do not raise a limit or drop material to pass (→SAVE-23).
