## goal
Unify remaining CSS-built controls and visual indicators through portable theme resources while reducing image transfer and decoding costs.

## acceptance
- [v] Theme packs expose validated UI resources, dimensions and nine-slice metadata in JSON; shared consumers resolve tokens and URLs without theme-ID branches.
- [v] Inputs/buttons/tabs, facility steps, player attributes and position maps, cup status and manager notices share themed image materials/frames while retaining live semantic content and accessible controls.
- [v] Facility steps remain readable at phone widths, and all four themes preserve layout, status meanings and pixel sharpness.
- [v] Compressed UI resources and responsive facility artwork have reproducible encoding, hashes and enforceable byte/dimension budgets; only needed icon variants are staged.
- [v] Theme/resource unit tests, typecheck, lint, formatting, presentation and spec validation pass; browser visual review covers the captured surfaces in all themes.

## impl notes
- Extend optional pack UI tokens and image resources; retain compatibility with resource-only third-party packs without UI metadata. Use one resolver for URL, dimensions and slice tokens.
- Reuse approved frame/material art; compact frame borders with independent tile fills avoid full-size backgrounds. Keep text and all game-driven geometry live.
- Move root visual declarations from pack stylesheets into JSON and consolidate repeated per-view rules. Keep only art-specific exceptions in pack stylesheets.
- Encode facilities at 960×320 plus 480×160, preserve per-era/stage artwork, and declare variant overrides for offices. Update generation manifests rather than keeping original deployment copies.
- Measure before/after bytes in an artifact. Add a deterministic optimizer/checker and validation for declared UI resources and facility variants; keep pixel rasters lossless and unscaled.
- Stage shared UI skins and mounted semantic icon/scene needs; keep inventory validation exhaustive without downloading unseen trophy variants at runtime.

## result
- outcome: Shared image skins cover controls, native choices, tabs, facility steps, player meters/position maps, cup results and manager notices. Theme JSON owns common visual tokens, image dimensions and per-resource nine-slice insets. Deployed image bytes fell from 79,165,922 to 40,902,344 (48.3%) including 276 new responsive representations; smooth UI resources fell substantially while pixel rasters stayed lossless and unscaled. Preparation, budgets, hashes and native adaptation are documented in apps/web/design/RESOURCE-SKINS.md; measurements are in artifacts/benchmarks/design-resources-261027.json.
