# T470 Publish large view parts as the changes inside them
> st:done@261026 | ssot:ARCH-6 | base:ARCH@22 | dep:- | touches:apps/web/src/runtime/protocol.ts apps/web/src/runtime/host.ts apps/web/src/runtime/client.ts apps/web/src/runtime/protocol.test.ts apps/web/src/runtime/host.test.ts | lane:- | explore:-

## goal
A day step's view delta carries a large changed part (`world.clubs`, `world.discipline`, …) as the entries that changed inside it rather than whole, so an own match day posts tens of KB to the main thread instead of 0.6–1 MB (measured 261026: all 732 clubs re-sent at ~400 KB while only `cohesion`, `elo` and `fans` change, ~5 KB; `discipline` re-sent at 40–190 KB while a few hundred yellow entries change), with the client's rebuilt view unchanged.

## acceptance
- [v] `ViewDelta` gains `patches`: for a changed part whose published JSON is at least `VIEW_PATCH.minChars`, the host sends a structural patch against the base view's part (objects by key, arrays by index with their new length, `VIEW_PATCH.depth` container levels, leaves whole) instead of the whole value, unless the patch's JSON is larger than `VIEW_PATCH.maxShare` of the part's; every other part is sent as today.
- [v] The patch is computed from the base's published text, never from live world objects, so later mutation cannot change what was compared.
- [v] One shared `applyViewDelta(base, delta)` in `protocol.ts` rebuilds the view; the client's `viewOf` and the host test use it. Unchanged objects keep their identity (copy-on-write along changed paths only).
- [v] Behaviour unchanged: the rebuilt view is canonically equal to the host's whole view (existing host and client delta tests pass, rebuilt through `applyViewDelta`).
- [v] `protocol.test.ts` cases: "a patch of an id-keyed array changes only the changed fields", "an appended array entry and a removed object key round-trip", "unchanged sub-objects keep their identity"; `host.test.ts` "an own match day sends clubs and discipline as patches no larger than VIEW_PATCH.maxShare of the whole and rebuilds the same view".

## impl notes
- From the 261026 x10 match-day measurement (ideation/save-storage-and-fast-pace). Behaviour-preserving refactor within ARCH-6's "publish bounded UI projections/deltas"; no SSOT change.
- `VIEW_PATCH = { minChars: 8192, depth: 2, maxShare: 0.8 }` in `host.ts`. Patch type in `protocol.ts`: `{ v: unknown } | { o: Record<string, ViewPatch>; d?: string[] } | { a: [number, ViewPatch][]; n: number }`.
- Diff against `JSON.parse(previous.texts.get(key))`; leaves compare by `JSON.stringify`, the same text `partText` already compares.

## result
- outcome: a changed view part of at least 8,192 JSON characters goes as `ViewDelta.patches[key]` (objects by key with removed keys, arrays by index with their length, two container levels, leaves whole) when the patch is at most 0.8 of the part; `applyViewDelta` in protocol.ts rebuilds the view copy-on-write for the client and tests. Measured on the 1950 ENG founding (Node, 120 days): match-day deltas 586–1,003 KB → 77–202 KB; `world.clubs` 402 KB → 34 KB, `world.discipline` up to 360 KB → 14–64 KB, `world.tables` 55 KB → 24–38 KB.
