## goal
Serve T304's summaries through the worker and mount T305's prepared view with contextual season navigation.

## acceptance
- [v] Add the bounded manager-history read and client method using T304 DTOs/config/query and T306 canonical facts. Return compact tenure/legacy-event pages and source-season links, never a career's match archives; read all retained own-match facts in the worker rather than the UI's short match window.
- [v] Follow existing read-request session/correlation behavior, including reads between queued simulation steps and read-only game access. A read creates no revision, command receipt, clock step, RNG draw, storage write or unsolicited world projection. Reject invalid/stale sessions/cursors and ignore cross-world/superseded responses.
- [v] Mount T305's component in the manager records tab, preserving existing current-manager and readable appointment/departure information. Refresh on actual world/settlement/personnel changes without issuing a query per frame; year/round alone is not a freshness key. Keep manager fact arrays and any cache out of ordinary world projections.
- [v] Opening a completed accomplishment selects the corresponding own-club season/competition; a named return and browser back restore manager tab, inspected tenure, loaded page/cursor and scroll. Existing season-to-league navigation and game-switch reset behavior remain intact; no viewing action changes game facts.
- [v] Protocol/host/client/state tests cover bounded multi-page and legacy-only records, queued-step reads without receipts/projection, read-only access, current-tenure updates within one league round, stale response isolation, preserved manager return context and cross-world reset. ## impl notes
- Add `{ type: 'manager-history', cursor?: string }` to the existing request union, `managerHistory?: ManagerHistoryPage` to replies and `client.managerHistory(cursor?)`. Reuse archive request/session handling; bridge protocol version stays unchanged. Import/export T304's definitions rather than creating another schema or page-size setting.
- `useManagerHistory.ts` maps the active World to the on-demand request/cache lifecycle and T305 props. Cache pages only within the current game/session, preserve them across a source-season detour and invalidate all affected summaries after a true fact change. Reuse existing app presentation services available on the implementation branch without changing their registries/resources.
- Adapt canonical facts to T304's explicit `ManagerHistorySource` in the host. Preserve stable legacy event-order keys and do not parse names to invent links. Any memoisation is transient and must not leak into checkpoints or ignore same-round cup/personnel changes.
- Extend world-scoped records memory in `state.ts` with the originating tenure/page/scroll and selected accomplishment. Reuse existing season-selection/return machinery; do not replace the season-list/table journey or duplicate the pure formatter/query inside React.

## result
- outcome: Protocol (`protocol.ts`): the request union gains `{ type: 'manager-history', cursor?, world? }` (strict; cursor 1–2000 chars, the query owning its meaning), `Reply.managerHistory?: ManagerHistoryPage`, and `ProjectedWorld` now omits `managerHistory` by type; the bridge protocol version is unchanged and T304's DTOs/page size are imported, not redefined. Host (`host.ts`): `manager-history` joins the reads answered at once between queued steps, through the existing session check, with no revision, receipt, clock step, RNG draw, codec post or view. `managerHistorySource(w)` adapts the live world to T304's `ManagerHistorySource`: the facts; every retained own match at its fixture day, ordered by its place in `ownMatches`; one snapshot per closed season (final table in the division played, the domestic cup winner from `champions`, every continental winner by tournament key, and a promotion only when the next season's division (or the club's own for the last closed one) is a higher tier); this season's decided cups and, once a league match is played, its provisional place; the current manager; and `manager-hire`/`manager-departure` events from before the tracking boundary as legacy rows keyed `event:<index in the event log>` with that index as their order (none for a career tracked from its founding, all for an untracked one). Names are never parsed and nothing is memoised. A read naming another career, a stale session or an invalid, truncated or foreign cursor fails, changing nothing. Every view carries `managerHistoryKey`, built from the facts' boundary, serial, tenure and outcome counts, the own-match count, closed seasons, the manager in charge and the provisional place; it moves on an appointment, a settled match, a cup final or a close within one round, but not on a date alone. Client: `client.managerHistory(cursor?)` sends the shown career's ID and refuses a reply if the tab has moved to another career meanwhile. State (`state.ts`): world-scoped `ManagerRecords` in task memory (`key`, every page read so far, the in-flight first-read key, the inspected tenure, scroll and the season opened with its tenure row). Helpers: `mergeManagerPage`; `readManagerPages`, which rereads as many rows as were on screen; `beginManagerRead`/`acceptManagerPage`, which drop superseded first reads, a next page whose rows were replaced and another career's reply; `rememberManagerSeason`; `returnedToManagers`; `leaveManagerSeason`. `useManagerHistory.ts` maps the client, the career and the view key to T305's props: it reads only while the tab is shown, keeps loaded rows on screen through a refresh, reports loading or a failure only for the latest request, and retries a failed next page from its cursor. `RecordsRoom.tsx` mounts `ManagerHistory` above the existing 감독들이 남긴 계절 panel, which is unchanged. An accomplishment or a tenure's season opens our season record through the existing `openSeason`, which now saves the season-list scroll only from that list. While a manager-opened season is shown it has a named `← 감독 이력으로 · <manager>` return. That return or browser back restores the manager tab (address `?view=managers`) with the same pages, the inspected tenure and the scroll, once. Any tab switch, the season-list button or an external season request drops the return. The season-to-league/cup buttons and game-switch reset (`activate`) are unchanged.
