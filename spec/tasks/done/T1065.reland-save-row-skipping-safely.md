## goal
T1061 (b2b0b80ef) made owner-decision saves 0.115× (1930) and 0.21× (2000) by reusing committed row text for world fields a command was listed as not changing, but an independent review (Codex, fs24 261124) found two ways it writes a database that differs from the full-world diff, so fs24d reverted it before release. Re-land a save that skips encoding unchanged rows only where completeness does not rest on a hand-kept list of what each command changes, keeping SAVE-3's full-diff parity.

## acceptance
- [v] Both review cases are regression tests that fail on b2b0b80ef and pass on the candidate (deterministic; worker, unit):
  - Array-family archives whose row key comes from the family's `columns` (history archives with `historyBase` below the oldest warm archive, e.g. a 1950 career with `historyBase: 1949`, `careerReads.history: 1951` and warm 1948/1949 archives): the held text is looked up under the same key the row is written with, and a second save keeps each archive's own season (b2b0b80ef: `worldRows.ts:107` looked up `String(absolute)` while the row was written under its column key).
  - A side effect outside a command's listed fields (an owner decision such as `club-ticket` whose news refresh sets a previous season's Ballon d'Or podium player's `playerRecords` entry to `linked: true`): the next save writes the changed row (b2b0b80ef: `host.ts:176` left `playerRecords` out of the dirty list).
- [v] Completeness does not depend on a per-command list of fields: either changes are detected from the records themselves (for example a structural fingerprint per family or per record compared with the committed one) or every engine write site marks what it changes and a debug parity check proves it. A parity mode that also runs the full diff and asserts equality runs in the integration project on the host, save-round-trip and long-career suites (deterministic; worker, unit/integration).
- [v] Paired measurement on the same machine: decision and stop saves on the 1930 e2e start and the 2000 takeover, faster than baseline beyond noise, with identical reopened databases, replies and world hashes; a variant with no difference is not kept (deterministic; worker, unit).
- [v] Run the ARCH-30 task tier once on the finished edits before committing with `vibe check --tier task`, plus the affected integration files named in T1061's limits (`worldRows.world.test.ts`, `coldPeople.integration.test.ts`, `saveRoundTrip.test.ts`, `host.test.ts`).
- [v] exit: At the 2 h limit, record completed samples, paired intervals, parity evidence and the remaining cost. Keep only a variant that met the speed and parity bars; otherwise land the regression tests alone and leave the measured costs in result.
