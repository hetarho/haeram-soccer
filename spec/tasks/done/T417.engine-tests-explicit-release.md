Make the grid, summary and portable-math tests independent of the release switch, so they pass identically with it off and on.

## acceptance
- [v] Each touched file builds its worlds with an explicit release: `DISABLED_RELEASE` (from `tests/fixtures/worlds.ts`, T415) where the case is about the pre-feature path's mechanics, `ENABLED_RELEASE` or `withCandidateModel` where it is about what a new career plays; no expectation or recorded digest changes for a pinned case.

- [v] Task checks (ARCH-30): typecheck, lint, format:check, `vitest run --changed`.

## impl notes
- Test-only change: no engine source edit. If a case can pass on neither release without a source change, stop that case, leave it pinned to `DISABLED_RELEASE` and name it in the result's limits for T420.
- Prefer pinning: the pre-feature path stays the football of careers whose rules never activate (→SAVE-23), and the candidate already has its own cases (T274–T278, T321–T411). Move a case to the candidate only when its subject is new-career behaviour.
- Use `simulatedWorld(input, span, DISABLED_RELEASE)` for shared worlds, not inline season loops.

## result

The release-on probe on the twelve files went from 55 failed / 112 passed (exactly the listed per-file counts) to 167 passed; the default run also passes 167.
