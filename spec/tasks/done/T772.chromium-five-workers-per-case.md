# T772 run local Chromium journeys on five workers, scheduled per case
> st:done@261110 | ssot:ARCH-30 | base:ARCH@34 | dep:- | touches:playwright.config.ts scripts/preview.mjs | lane:gate-e2e

## goal
The release gate's Chromium stage uses the cores the host has instead of half of them, without changing a journey, a timeout or a retry.

## acceptance
- [v] locally (not CI) Chromium runs `E2E_WORKERS` workers, default 5, with `fullyParallel`; CI keeps three workers and file-level scheduling; Firefox and WebKit keep three workers locally
- [v] every timeout, `expect` timeout, retry and project setting is unchanged; `pnpm exec playwright test --list --project=chromium` lists the same 348 cases before and after
- [v] the preview server memoises each compressed response by path, size and modification time, so a rebuilt file is served fresh; headers and status codes are unchanged
- [v] `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`, `pnpm run build`; the journeys themselves are the release run's (ARCH-30)

## result
- outcome: `playwright.config.ts` reads `E2E_WORKERS` (default 5, invalid or empty → 5, below 1 → 1); locally the run has max(3, that) workers, Chromium is limited to that many with `fullyParallel`, Firefox and WebKit are limited to three each; on CI the run keeps three workers and Chromium keeps file-level scheduling (no project `workers`/`fullyParallel`), so `--shard` still splits by file. Timeouts, `expect` timeouts and retries are untouched. `scripts/preview.mjs` gzips a file once per (path, size, mtimeMs) and re-stats on every compressed request, so a changed file is recompressed; identity responses still read the file each time. A config probe (tsx import under local default, `E2E_WORKERS`=3/8/1/junk, CI, CI+`E2E_WORKERS`=8) printed workers 5/3/8/3/5/3/3, Chromium 5/3/8/1/5 with `fullyParallel` locally and neither on CI, Firefox/WebKit 3, timeouts 30000/150000, expect 5000/30000, retries 0/0 local and 1/2 CI, WebKit 90000/300000. A preview probe against the built dist ran the new and the previous server side by side: 18/18 responses equal in status, headers (less Date/Connection) and bytes — the 2.78 MB worker bundle gzip twice (171 ms, then 18.9 ms memoised), identity, HEAD, `/` twice, an SPA path, a missing asset twice (404), JSON, `_headers`, a path escaping the root (400) — then the bundle served fresh after its content changed (decompressed equals the new bytes) and after a same-size touch, restored afterwards.
- at: 48432e5d (with this commit's `playwright.config.ts` and `scripts/preview.mjs` uncommitted on top while checked)
- verified: `pnpm exec playwright test --list --project=chromium` (348 tests in 68 files before and after, sorted lists identical); `pnpm run typecheck`; `pnpm run lint`; `pnpm run format:check`; `pnpm exec vitest run --project unit --changed 48432e5d --passWithNoTests --maxWorkers 2` (no unit file selected); `pnpm run build`; node config probe (scratchpad `gate-e2e/config-probe.mjs`); node preview probe (scratchpad `gate-e2e/preview-probe.mjs`)
