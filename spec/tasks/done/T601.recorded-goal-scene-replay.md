## goal
Let the owner replay an already seen live goal or retained archived goal from its build-up through the finish, then resume the original viewing instant without changing gameplay.

## acceptance
- [v] Offer a reachable explicit 골 장면 다시보기 action after a presented live goal and for retained archive goals; select individual goals by retained order/identity, including multiple goals in one minute. Never expose an unseen live goal, scorer or running score.
- [v] Replay the retained positions, actions and ball path from a short build-up through the selected goal and its existing goal-feedback hold. Show a clear 다시보기 state, ordinary speed choices and an explicit return; finishing the clip returns automatically. Do not just seek to the scored frame or play the whole remainder of the match.
- [v] Restore the original match, viewing instant, running/paused state and speed on finish or return. Reset elapsed-wall-time bookkeeping so return does not catch up. Do not replay the original cue a second time, call onPlaybackStart/onFinish for the clip, notify match completion twice, reveal a live result or advance the game date.
- [v] Replacing/unmounting playback clears the clip safely. Hidden documents suspend clip/hold time; reduced motion keeps static readable feedback. Phone widths and every theme retain readable touch/keyboard controls, the existing pitch ratio and normal primary actions.
- [v] Minute-only records keep existing seek navigation and explain that scoring footage is unavailable; never fabricate motion or simulate another fixture. Shootout conversions are excluded, and worn historical kits remain those of the retained appearance. Add no persisted fields, footage, library dependency or save migration.
- [v] Add meaningful pure unit cases for clip selection/window boundaries, distinct same-minute goals, unseen-goal exclusion, absent motion and restore/cancel/replacement state. Preserve goalFeedback.test.ts and existing moment navigation semantics.
- [v] Add tests/e2e/goal-replay.spec.ts for a real live goal clip, manual/automatic exact return, archived selection and no gameplay/date mutation; cover a phone viewport and unchanged existing goal feedback. Prepare the scenarios for the coordinator's final Chromium run and all-browser CI, not a task-level browser run.
- [v] Run affected unit tests, typecheck, lint, format and build. List all deferred browser/integration checks in result limits and preserve existing tests' assertions rather than weakening them.

Do not add a second renderer or an engine import that breaks ARCH-4.
- Define GOAL_REPLAY_CONFIG.leadSeconds = 15 in the helper and use WATCH speed 1 on clip entry; reuse the existing goal-feedback hold configuration. End at the selected goal after its hold, never progress into an unseen later goal. Keep settings named in code, not repeated literal numbers.
