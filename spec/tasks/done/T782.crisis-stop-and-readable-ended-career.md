# T782 stop the automatic clock once when a 파산 위기 begins, and keep every menu readable after a career ends

## goal
Automatic play no longer runs unattended past the start of a 파산 위기: the clock stops once behind a warning dialog and stays stopped until the owner starts it. After a career ends, home shows the game-over page while every other menu (records, season, team, office) can still be opened to read the career.

## acceptance
- [v] the day the club's first round in debt (`insolvent` 0→1) or the owner's `ownerCrisis` begins stops a running automatic clock once it is shown, nothing is computed past it, and the stop's reason names the crisis as the money band does
- [v] the warning dialog names the crisis, what remains of its count and that automatic play is paused; closing it leaves the clock stopped until the owner starts it
- [v] the same crisis going on (`insolvent` 1→2…) never stops the clock again; 퇴진 압박 and manual mode never stop for or open it; a clock the office or a watch stopped is not resumed by leaving them once a crisis began among its days
- [v] a career that ended shows the game-over page on home and opens it on the day it ends; the other primary menus render their views; progression controls and event cards stay hidden
- [v] all new copy is a message ID in source-messages.ts and every locale pack; `pnpm run validate:i18n` passes
- [v] `pnpm exec vitest run apps/web/src/runtime/progression.test.ts apps/web/src/runtime/progression.runahead.test.ts`; `pnpm run test:unit`; `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`

## impl notes
- detection lives in `ProgressionController.shown` and `stopsAt` by comparing the held day's before/after worlds; only automatic play reveals held days, so manual mode is excluded by construction
- the dialog follows AwaySummary: a progression store field (`crisis`) read by a widget mounted in App.tsx
- an ended career's commands are still refused by the host (→OWNER-16); the views are for reading
- the bankruptcy e2e journey (business.spec.ts) opens 기록 from the game-over page and returns home
- the club warning reuses the 파산 위기 inbox item's words through `clubCrisisDetail` in runtime/progression.ts, so the widget imports no engine module (the UI→engine exception list in scripts/lib/ui-engine-exceptions.ts only shrinks)

## result
- outcome: `crisisBegan(before, after)` names the club's first round in debt or the owner's `ownerCrisis` starting; `stopsAt` holds nothing past such a day and `shown` stops a running (or draining) clock with the crisis's money-band name, clears every resume flag (events, office, watch) and publishes `crisis`; a clock already stopped keeps that reason. `CrisisAlert` (widgets/cash-alarm) opens on `crisis` with the club's inbox wording or the owner's status detail and `copy.CrisisAlert.paused`; closing it calls `clearCrisis` and leaves the clock stopped. App.tsx no longer swaps every view for GameOver: home shows it in place of the dashboard, the other views render, EventCenter and ProgressControls stay hidden, and the day a career ends opens home.
