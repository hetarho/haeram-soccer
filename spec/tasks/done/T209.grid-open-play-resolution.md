# T209 Duels and the xG model

## goal
Every chosen action is settled by a duel between named players on their attributes, and every shot by a place-and-situation xG and the shooter against the keeper.

## acceptance
- [v] `grid/resolve.ts` exports `DUEL_CONFIG`, `SHOT_CONFIG`, `bend`, `chanceXg`, `resolvePass`, `resolveCross`, `resolveCutBack`, `resolveTakeOn`, `resolveCarry`, `resolveHoldUp`, `resolveClearance`, `resolveAerial`, `resolveShot`, `resolvePenalty` (design §7.1, §7.4) returning the `Outcome` union below; it imports the existing `finishing`, `goalChance`, `targetChance` (export them from `match.ts` if they are not exported) instead of copying them.
- [v] `resolve.test.ts` cases:
  - `prices chances like real football` (`chanceXg` open play: penalty spot 0.23 ±0.03, 20 m central 0.068 ±0.02, 6 m central 0.52 ±0.06, 30 m central < 0.03; header × 0.55; cut-back × 1.25)
  - `completes passes from the cell's real rate for equal players` (10 000 short passes in `central.oppMiddle` between 60-rated players with no lane risk: completion within ±0.03 of `passCompletion`)
  - `rewards the better passer and the better marker` (monotonic in each)
  - `splits lost passes into interceptions, loose balls and balls out by DUEL_CONFIG`
  - `lets a better dribbler beat his man more often and fouls about a fifth of failed take-ons`
  - `resolves a cross: claim, aerial duel, header or clearance`
  - `scores penalties about 78% between equal players`
  - `blocks about a quarter of missed shots with defenders in the lane`
  - `records xG for the level's average finisher and keeper` (recorded xG = chance xG × level factor)
- [v] Pure functions: no state mutation except through returned values; `pnpm run typecheck`, `pnpm run lint`, the test file pass.

## impl notes
- `Outcome` (one discriminated union, kept small):
  ```ts
  export type Outcome =
    | { kind: 'complete'; to: [number, number]; receiver: number }
    | { kind: 'intercepted'; by: number; at: [number, number] }
    | { kind: 'tackled'; by: number }
    | { kind: 'loose'; at: [number, number]; winner: [0 | 1, number] }
    | { kind: 'out'; at: [number, number]; lastTouch: 0 | 1; over: 'touch' | 'byline' }
    | { kind: 'foul'; by: number; at: [number, number] }
    | { kind: 'held'; by?: number }            // keeper claims, hold-up success keeps the ball
    | { kind: 'shot'; result: 'goal' | 'save' | 'block' | 'miss'; xg: number; recordedXg: number; then?: 'corner' | 'loose' | 'hold' | 'goalKick'; by?: number };
  ```
  Indexes are roster indexes of the side the field belongs to (`by` = opponent).
- Skills come from `skill(s, side, idx, attr)` (T205); the opponent for a pass is the opponent nearest the pass segment; for a take-on the nearest opponent in front within 4.6 m; for a shot the blocker is the nearest opponent within 2 m of the shot line, the keeper is slot 0.
- Probabilities follow design §7.1/§7.4 literally, every constant in `DUEL_CONFIG`/`SHOT_CONFIG`.
- `chanceXg(p, { header, cutBack, pressure })` uses `goalDistance`/`goalAngle` (T204) and `sigmoid(z) = 1/(1+exp(−z))`.
- Level factor: `finishing(levelShooting, levelKeeping)` computed once per match from the setup (mean 슈팅 of both sides' FW-line starters, mean 선방 of both keepers), same as the old duel chain did; pass it in through a `ShotContext` argument.
- Loose-ball winner: among the 2 nearest players of each side to the landing point, pick with weights `1/(distance+1)`; one `r()`.
- Out of play for a lost pass: continue the pass line past the target until it crosses x = 0/105 or y = 0/68; report the crossing point and `over`.
- Each function takes `r` and draws in a fixed order documented in a comment (determinism, design §1.1).

## result
- outcome: `grid/resolve.ts` settles every chosen action by a duel between named players — `resolvePass`, `resolveCross` (delivery, keeper claim, aerial duel, header), `resolveCutBack`, `resolveTakeOn`, `resolveCarry`, `resolveHoldUp`, `resolveClearance`, `resolveAerial`, `resolveShot`, `resolvePenalty` — and prices shots with `chanceXg` (penalty spot 0.23, 20 m 0.068, 6 m 0.52); it reuses the existing `finishing`, `goalChance`, `targetChance` and `bend` (now exported from `match.ts`, no behaviour change).

- verified: `pnpm exec vitest run packages/engine/src/grid` 56/56 pass (9 in `resolve.test.ts`, sampling 6000–20000 draws per case); typecheck, lint and prettier clean.
- limits: Offside is checked by the caller before a pass resolves (T210). A hold-up/take-on without an opponent in range completes without a draw. The block test checks the model with one defender on the lane (block share 0.22–0.34) and none (0); the 24–29% real-football band holds for typical lanes with one or two defenders only approximately and is left to T215 calibration.
