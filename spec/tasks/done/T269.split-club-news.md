## goal
`clubNews` becomes a set of small builders with their own tests, and every event text `eventNews` parses is pinned by a test against the code that writes it, so a reworded line fails a test instead of printing "약 0주 결장".

## acceptance
- [v] `clubNews(w)` keeps its signature and output; its body (110-917) is split into named functions following its section comments (past records and runs, the result line, club records and milestones, runs, home and away, possession/first goals/xG, season highs and lows, player lines, selection of kept items), none longer than 150 lines, sharing one context object built once per call.
- [v] Candidates are pushed in the same order as today (the selection breaks weight ties by push position), so the kept items and their `order` values do not change.
- [v] `packages/engine/src/news.test.ts` gains: one case per builder on hand-made `MatchRecord`s (result line, a milestone streak, home/away run, possession and xG line, a player's hat-trick or clean sheet), and one case per parsed event text — an injury event written by the real producer yields its week count (not 0), a 새로운 도전 transfer yields the club name, a retirement (은퇴) and a 4강 통과 event yield their news.
- [v] Equivalence: the canonical JSON of `clubNews` for seeds 1–3 after one season and after two rounds of the next is identical before and after the split (computed in the session; the hashes go in the result, not into a committed test).
- [v] Existing tests pass: `pnpm exec vitest run packages/engine/src/news packages/engine/src/adaptation` (runtime/host.test.ts also compares news; it is not in touches and must still pass in the batch run).
