# T1012 The read-only game state is removed

## goal
`readonly` no longer exists in client state, store guards or UI; every control that was disabled or badged for a read-only tab behaves as for the playing tab, because a non-playing tab never shows the game.

## acceptance
- [v] `ClientState.readonly`, `gameActionsBlocked`'s read-only term, the client guards (`mutate`, `autosave`, `saveOnce`, `generate`, `activate`, `checkpoint`, `forget`), `ReadonlyBadge` and its CSS/messages (`shell.readonly`, `shell.readonlyNotice`) are removed.
- [v] Every UI reader of the flag listed in impl notes no longer takes a `readonly` prop or branch; behaviour for the playing tab is unchanged.
- [v] `rg -i "readonly|read-only" apps/web/src --glob '!*.test.*'` finds no game read-only state (TypeScript `readonly` modifiers excepted).
- [v] Unit tests and fixtures that set `readonly` are updated; e2e specs using the 읽기 전용 label are updated (maintain only, CI).
- [v] Task stage, owner implementer: `vibe check --tier task` passes.

## result
- outcome: `readonly` is gone from `ClientState`, the store's `gameActionsBlocked`, every client guard (`mutate`, `generate`, `saveOnce`, `autosave`, export/import/switch/save/delete/recover), `GameSlots`, the progression controller, `ReadonlyBadge` with its CSS, and each UI reader (`GameSlotScreen`, `App` start/feedback, `OwnerOfficeView`, `ClubDesignView`, `FixtureKitSelector`, `MediationReview`, `PlayingCoachReview`, `ownerFigures`, `placeActivityChoices`, `watch`, `ProgressControls`, design-system client). `StartFlow`/`ClubListing` keep a `locked` prop for the failed-load replace guard (WEB-62), not a read-only state. A non-playing tab (`PlayingTab` not playing, or no Web Locks) no longer calls `load()`: it settles idle with `elsewhere` set, or the Web Locks error. Thirteen message IDs (shell.readonly, shell.readonlyNotice, slots.readonly and ten copy.* ids) are removed from the source resource and all 12 locale packs.
