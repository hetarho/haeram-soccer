# T774 record local Playwright traces without the screencast
> st:done@261110 | ssot:ARCH-30 | base:ARCH@34 | dep:- | touches:playwright.config.ts | lane:gate-e2e-trace

## goal
Local journeys stop spending CPU on a trace filmstrip nobody reads unless a case fails, so the CPU-bound Chromium stage of the release gate gets faster, while CI's traces and every journey stay as they are.

## acceptance
- [v] locally (not CI) `use.trace` is `retain-on-failure` without screenshots (DOM snapshots, network, console and sources kept); CI keeps `retain-on-failure` with screenshots
- [v] no other config value changes: workers, scheduling, timeouts, `expect` timeouts, retries, reporters and projects byte-identical; `pnpm exec playwright test --list --project=chromium` lists the same 348 cases
- [v] the resolved config is printed once for local and once with `CI=1` to show both trace settings
- [v] `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`; the journeys themselves are the release run's (ARCH-30)

## result
- outcome: `playwright.config.ts` sets `use.trace` to `CI ? 'retain-on-failure' : { mode: 'retain-on-failure', screenshots: false }`, with a comment giving the reason and the A/B. Playwright 1.63 fills the object's other trace options from its defaults (`snapshots`, `sources`, `attachments` true; `workerProcessEntry.js` `startIfNeeded`), so a failing local case still keeps DOM snapshots, network, console and sources; network and console are always in a trace. A tsx config probe (fixed `BROWSER_TEST_PORT`) printed `T774 local: use.trace = {"mode":"retain-on-failure","screenshots":false}`, `T774 CI=1: use.trace = "retain-on-failure"`, and for the eb21c1ef config `"retain-on-failure"` both ways. Comparing the whole resolved config with eb21c1ef's: locally only `use.trace` differs; with `CI=1` the two are identical. So workers, scheduling, timeouts, `expect` timeouts, retries, reporters, projects and webServer are unchanged.
- at: eb21c1ef (with this commit's `playwright.config.ts` uncommitted on top while checked)
- verified: `pnpm run typecheck`; `pnpm run lint`; `pnpm run format:check`; `pnpm exec playwright test --list --project=chromium` (348 tests in 68 files; the sorted case list is identical to one from a copy of the eb21c1ef config); node driver + tsx config probe (scratchpad `t774/driver.mjs`, `t774/probe.mts`)
- limits: no journey ran here (ARCH-30). The release run's `pnpm run verify:batch` confirms that all Chromium cases still pass and that the Chromium stage takes less wall time. `pnpm run lint` does not cover root `*.ts` files, so `playwright.config.ts` is only checked by typecheck and format. Locally `--trace <mode>` now changes only the mode and keeps `screenshots: false`, because Playwright merges a CLI mode into an object trace. A local filmstrip needs a config edit; `CI=1` is not a substitute because it also changes workers and timeouts.
