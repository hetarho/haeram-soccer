# T121 The HUD never leaves the top
> st:done@261015 | ssot:WEB-10 | base:WEB@68 | dep:- | touches:apps/web/src/ui/App.module.css tests/e2e/mobile.spec.ts | lane:- | explore:-

## goal
The HUD sometimes vanished in play (owner's report 261015). With warning bands (cash alarm, manager gone) a low screen's column outgrew `main`, which had `overflow: hidden` — still scrollable by code — so `scrollIntoView` (the remedy's board row, the training and cup views) and focus moves scrolled `main` and pushed the HUD up, by 17–31 px measured at 844×390 and off screen once the overflow passes the HUD's height.

## acceptance
- [v] `.layout` and `.main` clip instead of hiding overflow, so no code scrolls them
- [v] tests: e2e at 844×390 with both bands: scrolling the view's last element into view and 25 Tab presses leave `main` at scrollTop 0 and the HUD at top 0 (fails before the change: HUD −31)

## impl notes
- `overflow: hidden; overflow: clip;` keeps the old value where clip is unknown.

## result
- outcome: `.layout` and `.main` use `overflow: clip` (after `hidden` as a fallback), so scrollIntoView and focus moves scroll only the view scroller
