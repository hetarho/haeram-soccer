The prototype's staging runs inside the engine on engine scripts: it performs every beat of a script without replacing a scripted player, produces positions tick by tick in bounded steps, and brings its own measures of the picture — the naturalness and fit lines — so every later change to it is judged by numbers.

## impl notes
- Source: `scripts/match-proto/stage/` (all of it), `core/types.ts`' frame and event types, the `stage`, `motion`, `shape` (already ported, T823) and `limits` blocks of `core/config.ts`, `check/metrics.ts`, `check/fit.ts`, as they stand on the task's base — the owner's fixes made after T822 (a man who takes the ball in stride instead of stopping, an opponent beside him engaging) included. Port, do not redesign; keep comments that state a rule.
- Bound only: the engine stages nothing but fitted scripts, so `resolveCut`'s and `performCarryLost`'s re-casting branches and the grammar-only handlers go; `late` and `stretch` stay as measured flags (→MATCH-39).
- Inputs are the engine's; `StagingPlayer` and `StagingSide` live in `packages/contracts/src/match-script.ts` beside the script, since the staging worker receives both (T834): `MatchScript` (T826/T827 kinds; `penalty`, `stoppage`, `shootoutKick` and beats carrying incidents are performed as a plain dead ball here and get their scenes in T830) and
  ```ts
  export interface StagingPlayer { line: number; slot: number; role: RoleId; pace: number; anticipation: number; discipline: number; pressing: number; freedom: number }
  export interface StagingSide { tactic: Tactic; players: StagingPlayer[] /* record line order */ }
  export function createStaging(script: MatchScript, sides: readonly [StagingSide, StagingSide]): Staging;
  /** Performs beats until the staged clock reaches `untilSeconds` or the script ends; returns the frames and events produced. */
  export function advance(staging: Staging, untilSeconds: number): { frames: StageFrame[]; events: StageEvent[]; done: boolean };
  ```
  `anticipation` replaces the prototype's `iq`; `discipline`, `pressing` and `freedom` are carried and first read in T829 (use the neutral 50 for the fixtures). `StageFrame` and `StageEvent` are the prototype's `Frame` and `StageEvent` with `(side, line)` ids; they are engine-internal — the game's frame contract is T831's.
- The motion stream is `${script.seed}:motion` through `primitives.ts` `random`; nothing else is random. Floats and `Math.hypot` are fine here (→ARCH-9: the staging is presentation); no wall clock.
- `staging/measure.ts`: `stagingMetrics(frames, events, script, sides)` (the 31 metrics with their limits from `STAGING_CONFIG.limits`) and `fitLines(frames, events, script, detail)` (`fit.exact`, `fit.performed`, `fit.recast`, `fit.stretch`, `fit.late`, `fit.links`, `fit.linkMetres`, `fit.miscontrols`, `fit.connectiveRestarts`, `fit.orphans`, `fit.stagedSeconds`, `fit.clockRatio`); pure, no timing inside. A small CLI `scripts/staging-read.ts --fixture sNN` printing both is welcome but not required.
- Staging a whole match takes seconds: whole-match cases are integration tier, unit cases stage at most five match minutes.
- Not in this task: the four formations' behaviour and tendencies (T829), incident scenes (T830), the game's frames (T831), speed (T837).
