## goal
A checked-in catalog gives the lab page each tunable value's path, default, comment and group without the page importing engine execution code.

## acceptance
- [v] `pnpm run lab:tunables` writes apps/web/src/lab/tunables.json: `{ groups: [{ name, file, comment, leaves: [{ path, value, comment, loadTime }] }] }`, one group per `GRID_TUNABLES` entry in source order.
- [v] Each leaf's comment is its nearest JSDoc/line comment on the property (or the enclosing object's when the leaf has none); `loadTime` is true for paths in `LOAD_TIME_LEAVES`.
- [v] tunables.test.ts "catalog matches the engine": every `tunableLeaves()` path and value appears exactly once in the JSON and vice versa — a stale catalog fails with the regenerate command in the message.
- [v] typecheck, lint, format:check and the affected unit tests pass.

## impl notes
- scripts/lab-tunables.ts: TypeScript compiler API (`typescript` 5.9 already in devDependencies) over packages/engine/src/grid/*.ts (not tests); walk each `export const X_CONFIG = { … }` object literal, collecting `ts.getJSDocCommentsAndTags` / leading comment ranges per property assignment. Values come from importing `tunableLeaves()` (runtime truth), comments from the AST; write with prettier-compatible 2-space JSON so format:check passes.
- The JSON is data the page imports (no engine import); keep it under the page's own chunk (T575 imports it only from lab code).
- Add `"lab:tunables": "tsx scripts/lab-tunables.ts"` to package.json scripts.
