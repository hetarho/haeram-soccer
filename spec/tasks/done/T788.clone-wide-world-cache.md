# T788 share the test-world cache across a clone's worktrees
> st:done@261110 | ssot:ARCH-21 | base:ARCH@38 | dep:- | touches:tests/fixtures/json-cache.ts tests/fixtures/json-cache.test.ts | lane:world-cache

## goal
Every local worktree of the clone (the owner's checkout, `.tmp` gate worktrees, worker worktrees) reads and writes one world cache under the Git common directory, so a gate or task check in a fresh worktree reuses worlds already built for the same fingerprint; CI keeps its per-job path.

## acceptance
- [v] with `HAERAM_WORLD_CACHE` unset and not on CI, the cache base is `<git common dir>/haeram/worlds` (resolved once per process with `git rev-parse --git-common-dir`, absolute); on CI (`CI` set) it stays `node_modules/.cache/haeram-worlds`; `HAERAM_WORLD_CACHE` (including `off`) still overrides both; if the Git lookup fails the old path is used
- [v] keys, file layout below the base, locking, temp-then-rename writes and pruning (`maintainDirectory`) are unchanged; two worktrees building the same entry at once still produce one file
- [v] a unit test covers the base resolution (env override, CI, Git common dir, fallback) without touching the real cache
- [v] a probe: build one small cached world in worktree A, read it from worktree B (a temporary detached worktree) without rebuilding; record the paths and timings
- [v] `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`, `pnpm exec vitest run --project unit tests/fixtures --maxWorkers 2`

## result
- outcome: `json-cache.ts` takes its base from the exported `cacheBase(env, commonDirectory, fallback)`: `HAERAM_WORLD_CACHE` whenever it is set (`off` included, read per call as before), the per-checkout `node_modules/.cache/haeram-worlds` when `CI` is set (`!!CI`, as `playwright.config.ts` and `tests/e2e/global-lock.ts` read it) or when Git gives no answer, otherwise `<git common dir>/haeram/worlds`. `gitCommonDirectory(root)` runs `git rev-parse --git-common-dir` in the repository root, resolves the answer to an absolute path and returns `undefined` on any failure; it is memoised in the module and only asked when neither the override nor CI has decided, so CI and `off` never spawn Git. A caller's `options.directory` still wins. Keys, the `<base>/<16-hex scope>/<id>-<key>.json` layout, `.lock` files, `.<pid>.tmp` + rename writes and `maintainDirectory` are untouched; the dependency fingerprint already hashes repository-relative paths, so every worktree at the same source computes the same file names. `json-cache.test.ts` adds two cases: the resolution order with an injected lookup (clone store, lookup asked once and not on CI or under the override, CI path, override path and `off` beating CI, fallback when the lookup answers nothing) and the real lookup (absolute common dir holding `HEAD`; a missing checkout directory gives `undefined`); neither writes a cache file. Probe (scratchpad `probe/t788-probe.mts`, `simulatedWorld()` = the default `careerWorld`, host load average ≈ 15): worktree A (this one) found the store empty, built `d8dd727f549c4e97/sim_0_0_revision_continuous-aggregate-10_enabled_true_-da6b2ef12f60294060d1.json` (2,379,349 bytes) under `/home/deep/haeram/haeram-soccor/.git/haeram/worlds` in 3,490 ms; worktree B (`.tmp/t788-probe`, `git worktree add --detach` at aeb2c618 with this task's two files copied in, own `pnpm install`) resolved the same base, listed that file before the call, returned in 2,414 ms and left its mtime unchanged (no `node_modules/.cache/haeram-worlds` in B); interleaved in B, shared reads 1,996/2,075 ms against `HAERAM_WORLD_CACHE=off` builds 2,814/3,244 ms (about 2 s of each is the dependency fingerprint, paid either way).
