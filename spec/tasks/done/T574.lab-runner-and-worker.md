## goal
A lab run of N matches between two lab sides with a set of overrides plays off the main thread, reports progress, can be cancelled, and returns a deterministic summary.

## acceptance
- [x] protocol.ts defines the page↔worker messages: `run { runId, runSeed, sides: [LabSide, LabSide], overrides, from, count }`, `cancel { runId }`, `probe` → `reads { paths }`, `generate { side, seed, tactic, average, spread }` and `setOvr { side: LabSide, index, ovr }` → `side { side: LabSide }`, `progress { runId, done }`, `samples { runId, from, results }`, `failed { runId, message, rejected? }`.
- [x] runner.ts `playLabMatch(world, sides, runSeed, index)`: match `index` (0-based) has the left side at home when index is even, fixture id `lab:${runSeed}:${index}` as its seed, year `LAB_CONFIG.year`, league round 1, model `MATCH_MODEL_REVISION`; returns a `MatchSample` with sides re-mapped so side 0 is always left.
- [x] summary.ts `summarizeRun(samples)`: outcome (left wins/draws/right wins, each side's goals a match), the MATCH-23 rows from `buildTargetReport(samples)` (value, interval, band, real range, verdict), and the side table (LAB-5's list, left and right means with 95% intervals from `record.metrics`/`detail`); a 1-match run adds score, scorers with minutes, cards and team stats.
- [x] pool.ts runs `count` matches across `min(4, hardwareConcurrency - 1, count)` workers (at least 1) in contiguous slices, merges by index, so the summary is identical whatever the worker count (runner.test.ts "same run seed same summary with 1 and 3 slices").
- [x] Cancel terminates the run's workers and resolves as cancelled with nothing kept; overrides that fail `applyOverrides` reject the run before any match with the rejected paths.
- [x] runner.test.ts "left home on even matches", "override changes the result, defaults restore it"; summary.test.ts "outcome counts", "side table intervals", "single-match details".
- [x] typecheck, lint, format:check and the affected unit tests pass.

## impl notes
- Starting draft (typecheck and lint clean, no tests yet): protocol.ts, runner.ts (`playSlice`, `probeLabReads` over all four tactics, `labWorld`), summary.ts (`summarizeRun`, `estimate`, `beyondNoise`) and worker.ts exist; pool.ts and the tests do not. Engine-side lab fixtures live in packages/engine/src/lab/match.ts (T572: `createLabWorld`, `playLabMatch`, `leftAtHome`), so worker.ts uses those instead of building the world from CORPUS_CONFIG. summary.ts imports scripts/lib/match-parity.ts, which reaches engine modules — the page never imports summary.ts at runtime: the pool sends the merged samples back to worker 0 as `summarize { runId, samples, sides }` and gets `summary { runId, summary }` (already in protocol.ts). Measured: lab world 0.4 s, one lab match ~0.47 s on this host, so a 600-match run is ~5 min on 1 worker and needs the pool.
- worker.ts is a module worker (`new Worker(new URL('./worker.ts', import.meta.url), { type: 'module' })` like runtime/client.ts). On first message it builds one world: `createWorld` with the founding of `CORPUS_CONFIG.conditions[0].params.world` and seed `lab-world`, and picks two tier-0 ENG clubs other than the player club as hosts; the lab squads replace theirs through `buildGridSetup`'s `lab` option (T572). Per run: `applyOverrides(overrides)` then play its slice, `restoreDefaults()` after (also on failure).
- Samples cross the channel trimmed to what summary.ts reads (record metrics/detail/incidents/score events, diagnostics' possessions/shots/directions/ballInPlay); keep `players` only for the 1-match run.
- `probe` plays one 1-match default run inside `probeReads` and returns the read paths (T575 hides unread leaves by default).
- summary.ts imports `buildTargetReport`/`TARGET_BANDS` from scripts/lib/match-parity.ts; update that file's header ("nothing under apps/ or packages/ imports this file") to name the lab worker as the one app importer. Only lab worker code imports it, never game UI or the game worker. Note `MATCH-23`'s per-team rows already average both sides.
- Interval for side means: mean ± 1.96·sd/√n (0 width for n=1). Equal-sides note: flag when the sides' starter averages differ by more than 2.
- Rows the grid records no data for show `missing`; never report missing as pass.

- limits: deviations from the acceptance wording: (1) cancel needs no `cancel` message: a worker plays its slice synchronously and cannot read one, so the pool terminates the run's workers, which also fails requests waiting on worker 0. (2) The engine's `playLabMatch` (T572) and runner.ts's `playLabSample` keep the fixture's home/away sides and record `leftHome`; summary.ts maps them so side 0 is always left. A flipped `MatchSample` would mislead every shot point, since those stay in the attack frame. runner.test.ts plays 10 real lab matches (about 5 s); it stays in the unit tier like grid/tunables.test.ts. The pool runs on in-process fake workers in pool.test.ts; real browser workers are first exercised by T575's page and its e2e spec. Integration/e2e are left to the batch run.
