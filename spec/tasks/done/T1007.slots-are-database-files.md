## goal
Each occupied slot is its game's database file: switching saves and closes the game in play and opens the next, a new game creates its file, deleting removes it, and the parked-envelope IndexedDB store is no longer used.

## acceptance
- [v] `slots.park/continue` = `save` + `close-game`, then `open-game` of the next game ID; a failed open leaves both files untouched and reopens the previous game (SAVE-14).
- [v] Starting a new game in a slot creates `/game-<gameId>.sqlite3` through `create-game` after the takeover; replacing an occupied slot (after its confirmation) deletes the old file first.
- [v] `delete-game {gameId}` deletes the game's database (and, once T1010 exists, its backups) only after the existing confirmation (WEB-62); deleting the game in play reloads onto the slot screen as today.
- [v] At startup a `list-games` answer (file names in the pool) makes slot-index entries without a file read as empty (SAVE-29); the IndexedDB `games` store is neither read nor deleted.
- [v] Task stage, owner implementer: `vibe check --tier task` passes (`games.test.ts`, slot tests updated to the new flow); slot e2e journeys are a CI handoff.

## result
- outcome: Slots are database files. `GameSlots.continue` = the client's `switchTo(gameId)`: `save`, `close-game`, then `open-game` of the next game ID; a failed open (missing file, unsupported version) leaves both files untouched and reopens the previous game. `GameSlots.prepare(slot)` saves the game in play and records the occupied slot's game as replaced; the old file is deleted (`delete-game`) in the first save after the takeover, just before `create-game` creates `/game-<gameId>.sqlite3`. `slots.remove` deletes the file through `delete-game` (the game in play leaves the page and the app reloads onto the slot screen as before). New protocol messages `close-game`, `delete-game {gameId}`, `list-games` (reply `games`), implemented in the host through an injectable `GameFiles` (default: OPFS pool `listFiles`/`deleteFile`); the game ID must match `/^[A-Za-z0-9:_-]{1,100}$/` (`checkedGameId`, and the protocol schema). At startup the client lists the files once and `GameSlots.read/display` read an index entry without a file as an empty slot (SAVE-29); `GameIndexStore.hasGames` no longer reads the commit manifest. `IndexedDbParkedStore`/`ParkedStore`, `resolveEngines` and the client's `forget`/parked path are gone; the IndexedDB `games` store is neither read nor deleted.
