# T1014 People without a current role leave memory when the game saves
> st:done@261119 | ssot:SAVE-32 SAVE-3 SAVE-13 ARCH-5 ARCH-36 | base:SAVE@72 ARCH@52 | dep:T1013 T1010 | touches:packages/engine/src/person-careers.ts apps/web/src/adapters/coldMovers.ts apps/web/src/adapters/rowSaver.ts apps/web/src/runtime/host.ts packages/contracts/src/schema.ts | lane:- | explore:- | run:claude/opus@high

## goal
At each save, people without a current role are written as cold rows in the same transaction and, after it commits, removed from `w.people`; opening a game loads only current people; outcomes are identical however often the game saves.

## acceptance
- [v] `hasCurrentRole(w, p)` in `person-careers.ts` is true exactly when: `playing !== 'retired'`; or an employment entry has no `to`; or a mentor entry has no `to`; or `coaching` is set; or `management` is set and `w.year - born < 70`; or `loan` is set; or the id is referenced by `w.manager.person`, any `w.staff[].person`, any `w.staffMarket.free[role][].person`, or a `playingCoachProposals` key.
- [v] `coldMovers.ts` `moveColdPeople(w, saver)` marks the person rows of every in-memory person without a current role cold in the save's single `store.write`; only after the commit are they deleted from `w.people` (remaining key order unchanged) and the `peopleOf` cache cleared. A failed write removes nothing.
- [v] `restorePerson(w, id)` brings a cold person back for a write (rebuilding `w.people` in stored `seq` order) and every person writer (`openEmployment`, `closeEmployment`, mentor/coaching/management writers, `wartime.ts:52`) calls it first when the person is not in memory; a unit test hires a cold person through it.
- [v] `open-game` loads only `cold = 0` person rows; world validation (`schema.ts`) accepts person references that resolve through `hasPerson`.
- [v] Determinism (ARCH-5), unit/integration test with the node store: from a multi-season world, one season played with a save and cold move after every day and the same season played without saves end with equal `worldFacts` (T1004); the helpers-vs-no-helpers equality test also passes with cold people.
- [v] Task stage, owner implementer: `vibe check --tier task` passes; run the affected integration test files named in result verified (`vibe check -- pnpm exec vitest run --project integration <files>`).

## impl notes
- Score 9: the save path, the engine registry and validation must agree on one predicate, and any slip changes outcomes only after a save — the determinism test is the guard.
- The predicate comes from the people inventory (261119): writers that touch a person after retirement are `openEmployment`/`closeEmployment` (person-careers.ts:195-260), coaching-market.ts:36,101-106, wartime.ts:85-89 (open jobs), economy.ts:33-38, coaching-entry.ts:59-67, manager-entry.ts:66, ops-staff.ts:363-364, managerMarket.ts:531-546, staff.ts:456-459,927-931, wartime.ts:52 (stale `loan` on a retired person — hence `loan` in the predicate).
- `careerCandidates` (managerMarket.ts:237) keeps registry order with no id tie-break: every candidate has `management` and age < 70, so it is in memory and its relative order is the stored `seq` order.
- Trial clones (`cloneWorld`) never move people; only the host's save does.
- The mover API in `coldMovers.ts` is shared by T1015–T1018 (`moveColdPlayerRecords`, `moveColdOwnMatches`, `moveColdEvents`, `moveColdNews`, `moveColdArchives`); the host's save calls them in that order after `moveColdPeople`, then one `RowSaver` write.
