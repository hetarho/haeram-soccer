# T1006 The engine worker opens and saves the game in play in its database

## goal
The game in play lives in its SQLite file: the engine worker opens it, validates it and saves only changed rows between simulation steps; the codec worker, the world hand-off clone and the per-save envelope are gone.

## acceptance
- [v] Protocol messages `open-game {gameId}`, `create-game {gameId}` (after a takeover, writes every row) and `save` (writes changed rows, answers `{ revision }` after the transaction commits) exist; `CodecJob`/`CodecResult`, the `codec` control message, `host.codec`, `runtime/codec.ts` and the client's codec worker, `builds` map and `CODEC_TIMEOUT_MS` save use are removed.
- [v] `open-game` loads `rowsToWorld(store, { includeCold: false })`, applies the checks `decode` applies today (versions, catalog pin and hash, currency, relevelled-money refusal, `validateWorld`), the writer upgrade of SAVE-10, attaches the store (`attachRecordStore`) and primes a `RowSaver` with the loaded rows so the next save writes only changes. An unsupported schema/version is a typed `SaveCompatibilityError` and leaves the file untouched.
- [v] Autosave cadence and rules of SAVE-8 are unchanged in `client.ts` (30 s running clock, stop/hide/close, owner decisions at once, one save at a time, newer request replaces a waiting one); the client's saved revision/time come from the `save` answer.
- [v] `Host` takes an injectable `openStore(gameId): RecordStore` (default: the OPFS pool of T1005); host unit tests use `memoryRecordStore()` and show: create → save → one day → save writes < 10% of rows → reopen equals the in-memory world (`canonical`).
- [v] Task stage, owner implementer: `vibe check --tier task` passes; browser save/reload journeys are an integration handoff (CI), recorded in result limits.

## result
- outcome: The engine worker owns the game in play's database. `open-game {gameId}` opens the game's store (no file ⇒ `opened.found: false`, an empty slot), checks its metadata (schema version, rules version supported or `SaveCompatibilityError` earlier/newer, catalog pin and hash), loads `rowsToWorld(store, { includeCold: false })` through `validateWorld` (field order kept as stored), the world/metadata/currency match and the relevelled-money refusal, applies the writer upgrade (now one `Host.writerUpgrade` shared with `inspect`), attaches the store and primes a `RowSaver` (`prime(w)`: the store's `seq`, the opened world's text) and commits an upgrade at once; a failed check closes the file untouched. `create-game {gameId, replace?}` writes every row after a takeover (an occupied file is refused unless `replace`, used by activated imports/parked games, which primes against what the file held so the save also removes stale rows). `save` commits the changed rows in the command queue (never mid-day) and answers `saved: { gameId, worldId, revision }` only after the transaction commits; a failed write is an error reply and the next save writes the same changes. `CodecJob`/`CodecResult`, `saving`, the `codec` control message, `host.codec`, `runtime/codec.ts` and the client's codec worker, `builds`, `built`, `savedCheckpoint` and `CODEC_TIMEOUT_MS` are gone (`STORAGE_TIMEOUT_MS` 600 s bounds open/create/save/export). The client opens the slot index's active game ID at startup, gets a UUID game ID at takeover (listed by `slots.sync`), saves through `create-game` until the worker holds the database and `save` after, keeps the SAVE-8 cadence and takes saved revision/time from the answer; export/park encode the current world through `export`. `Host` takes `openStore(gameId, { create })` (default: the T1005 OPFS pool via `poolStore`). Measured (host unit test, 1930 takeover world): create writes 2,504 rows; the first day after the takeover 420 (every club's season business), ordinary days 3–14 rows; reopening equals the in-memory world by `canonical` and its first save writes 0 rows.
