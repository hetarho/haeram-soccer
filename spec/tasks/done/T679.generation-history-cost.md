## goal
Know whether a later decade's generation stays within 5 s a season played on the reference trace with the history view on, and what the view adds to the generation time.

## acceptance
- [v] `scripts/generation-budget.ts` (T667) measures 1970 and 2000 with the view on the preview build, process-wide 4x and unslowed, and records seconds a season played beside T667's figures in `artifacts/benchmarks/T679-generation.json`.
- [v] the view's cost: the same machine and run order alternating with and without the digest (Node `generateHistory` 1970 with and without `seasonDigest` in the callback, three runs each), reported as a percentage with its spread; the browser run's per-season time against T667's 2000 figure.
- [v] exit: after 1 hour record what was measured (figures, host load average beside each, commands) in the result and an inbox line for ARCH-28's measured note; if the view adds more than 10% or a season takes more than 5 s on the reference trace, name the hotspot and propose the fix or the gusta-update-ssot in limits — no tuning beyond a fix under 50 lines.

## impl notes
- Run every measurement in the foreground of the session and wait for it; a background read ends with the unit.
- This host is shared: note `uptime`'s load average with each figure; a speed difference counts only beyond the spread of the runs (same machine, alternating order).
- T667's figures for comparison: 1930 3.8 s, 1970 131.9 s, 2000 322.0 s on the reference trace; 1.9 / 33.0 / 68.2 s unslowed (2000: 63 seasons played, 5.1 s a season).
