## impl notes
- from review/match-engine-split-261110 F1
- Follow T791's chain rules; nothing outside `scripts/match-proto/` and `artifacts/match-proto-261110/` changes. `artifacts/` is not linted or formatted; a push touching only it and `spec/` starts no CI (→ARCH-30), but this task also changes `scripts/match-proto/core/config.ts`, so its commit is a code commit.
- What the numbers are for: the prototype answers one question — can a script with named actors be staged so it reads as football. The metrics are that question in measurable form; the owner's eyes are the final judge. Passing them is not the goal of the chain; knowing which of them a script-then-stage design holds easily and which it does not is.
- Order of work inside the timebox (keep a short log with clock times in the artifacts README):
  1. baseline reports (first acceptance item); note the time — the two hours start here.
  2. hard failures first, because they are bugs rather than tuning: `duration`, `kinematics.maxStep`, `kinematics.outside`, `ball.maxSpeed`, `score.consistent`, `offside.consistency`. Find the frame or event (`--json` output and `playback.json`), reproduce it in a unit test with a short hand-written script, fix the handler.
  3. contact metrics: `events.reception`, `events.contest`, `events.recastRate`, `events.stretchRate`, `ball.ownerDistance`, `stage.pressVisible`. Levers, by name: `stage.maxExtraHold`, `stage.receiveSlack`, `stage.shadowAt`, `stage.shadowOff`, `stage.cutSlack`, `stage.jockey`, `stage.tackleGrace`, `stage.lunge`, `stage.pressVisible`, `shape.press.standoff`, `shape.press.tight`, and the script's casting (`castOpponentNear` picks the nearest nominal defender — a high recast rate usually means the nominal and the staged defender places disagree, so compare them for the recast events before touching numbers).
  4. shape and roles: `shape.swarm`, `shape.spacing`, `shape.teamLength.*`, `role.*`. Levers: `shape.ip.*`, `shape.oop.*`, `shape.mark.*`, `shape.press.coverGap`, the `ROLE_SHAPE` rows of the three showcase roles, `motion.jogWithin`.
  5. script volumes and the showcase (`grammar.weights`, `grammar.p`, `grammar.hold`, `grammar.showcase.withinSeconds`): keep every showcase quota met for `demo` on the performed beats (`produce.ts` prints them).
  6. delivery files and README, leaving at least fifteen minutes for them.
- Sanity ranges for script volumes of the performed beats (both teams together, per ten staged minutes; they are wide on purpose and come from real football's order of magnitude, not from this prototype): passes 80–350, pass completion 72–94%, shots 2–12, goals 0–4, offsides 0–3, corners 0–4, throw-ins 1–10, tackles + interceptions 4–40, each team's share of beats 30–70%.
- One change at a time, five seeds each time; record the summed pass count over the five seeds as the round's score. Do not tune on `demo` alone.
- If a metric cannot pass without breaking the design's rule that staging never changes a beat's outcome, actor or receiver, leave it failing and say so: that is a finding about the architecture the owner needs.
- The page is not opened in a browser by this task and no browser automation is run (→ARCH-30); say so in the result.
- If the criteria themselves need changing (a limit, a quota, a new rule for what staged football must hold), that is a planning change for the owner, not something to decide here.
