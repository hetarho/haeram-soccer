# T848 revision 11's pairs are men on the pitch together, held over whole matches
> st:done@261112 | ssot:MATCH-16 MATCH-27 MATCH-38 ARCH-5 ARCH-21 | base:MATCH@62 ARCH@40 | dep:T833 | touches:packages/engine/src/aggregate tests/config/test-tiers.ts | lane:- | explore:-

## goal
Revision 11's attribution already matches the two men of every two-man action over the playing time they share (T833's `pairParticipants`, →MATCH-16 r62). This task holds that rule where it is made — on the attribution's own trace over whole matches with substitutions — so that a regression is named at the attribution rather than found later as a script that cannot be played.

## acceptance
- [v] `aggregate/players.pairs.test.ts` (integration, registered in `tests/config/test-tiers.ts`): over 8 placed 2008 fixtures (at least one of 120 minutes) traced through `players.testkit.ts`, `every pair is on the pitch together` — every `wins`, `recoveries`, `offsidePairs` and foul `pairs` entry names two lines whose playing spans in the group's period share more than zero minutes (`commonSpan` as attribution and detail use it), while the same fixtures hold at least 5 couples of an own and an opposing line sharing no minute of a period (asserted, so the case is not vacuous) and none of those couples appears in a pair
- [v] same file, `pairs add up to the trace's counts`: per traced move the pairs' second men summed by line equal `won` / `recovered` / `offside`, per foul row `fouler`, and each pair's first man is one of the group's failed attempts (offside passers and losers never counted twice)
- [v] `aggregate/timeline.test.ts` (unit) gains `commonSpan` / `pairParticipants` edge cases: overlapping spells, a substitution's minute (the man leaving at 79 and the man coming on at 79 share none and are never paired), a matchable draw consuming no draws, and an unmatched second man drawn only among men sharing the first's spell
- [v] if either integration case finds a pair that never met, the attribution is fixed in `aggregate/` with a unit case naming it; no record is moved after settlement and no check is widened
- [v] `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`, `pnpm exec vitest run --project unit --changed "$GUSTA_DIFF_BASE" --passWithNoTests`; the integration file run once by hand, output pasted into the result

## impl notes
- Revision 11 only (`plan.placed`). Revision 10 and earlier, their pinned digests and every settled record stay as they are; tests only read the trace, so no draw changes unless acceptance 4 finds a bug.
- The trace fields are in `aggregate/types.ts`: `AggregateTraceMove.offsidePairs` (`actor`, `receiver`), `wins` and `recoveries` (`actor`, `other`), `AggregateTraceFouls.pairs` (`actor` fouled, `other` fouler). Spans come from the participation the attribution reads (`playingSpan` per line and period).
- `players.place.test.ts` samples 1964 (no substitutes), where every pair meets trivially; this task's fixtures are 2008 so substitutions occur.
- Supersedes this task's earlier plan (`sharedMinutes` weights, `pairGroups` refit, `settlePairs` removal): T833 implemented the matching rule now in MATCH-16 r62, and the handoff's code has no `settlePairs`.
- Not in this task: shots, key passers, cards, set-piece takers, penalties' minutes (T833 holds them), throughput.
