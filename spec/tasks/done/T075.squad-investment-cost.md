## goal
Squad investment scales each round's operating expenses (×0.9/0.95/1/1.1/1.2 by level), so the dial is a financial trade-off on the operating board.

## acceptance
- [v] policy.ts:
  - `SUPPORT_EXPENSES = [0.9, 0.95, 1, 1.1, 1.2]`, exposed as `operatingFactor` in `PolicyEffects`;
  - the support level summaries name it (e.g. `운영 경비 ×1.1`);
  - `policyPreview` reports the change in yearly fixed costs for a support level.
- [v] Each round's operating-expense booking (ECON-30, ledger 운영 경비) is the season amount per round × the factor in force at that settlement.
- [v] `operatingCosts(w)` uses the current factor wherever it counts operating expenses:
  - fixed costs and runway (→ECON-12);
  - the cash warning (→ECON-20);
  - the bankruptcy threshold (→ECON-24);
  - the affordability checks that read it.
  The cash projection (→ECON-18) carries it forward.
- [v] Level 3 is exactly ×1. A world at the default level books the same amounts as before.
- [v] Tests:
  - finance.test.ts: "squad investment scales each round's operating expenses and the runway"; "the default level books exactly the season amount per round".
  - projection.test.ts: "the projection and a support preview carry the operating-expense factor".
  - policy.test.ts: the support effects table includes the factor.
- [v] `pnpm run typecheck && pnpm run test:unit` pass.

## impl notes
- The season amount (`operatingExpenses`, set at season start) is unchanged. Only the per-round payment and the derived fixed costs are multiplied, so changing the dial acts from the next settlement (→ECON-16).
- Do not touch calibration constants. T078 re-measures with the reference club at the default level, where nothing changes.
