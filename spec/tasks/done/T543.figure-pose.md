## goal
Pure functions turn a playback's recorded samples and events into each player's top-down pose at any presented instant, with no state, randomness or engine change.

## acceptance
- [v] `figureActionWindows(frames)` derives per-player action windows from `MatchFrame.events` and ball tracks: kick (pass, cross, cutBack, clearance, kickoff, shot and kicked restarts), throw-in, header, tackle/slide and keeper catch/dive. It never makes a window for an action the events do not record (MATCH-37).
- [v] `gaitDistances(samples)` returns each player's cumulative distance in metres at every presentation sample.
- [v] `poseAt(input, windows, options)` returns a `FigurePose` covering facing, upper-body lead, lean, stride, joint positions, jump, lying and ball socket. The same arguments always return an equal pose. It imports no React, DOM, engine orchestration or `Math.random`.
- [v] Facing: a moving player faces his screen-space velocity; a slow or standing player faces the ball; the upper body leads and the hips follow the earlier velocity.
- [v] Running: legs and arms swing in opposition, the stride phase advances with distance travelled, and amplitude and lean grow with speed. A standing player holds a ready stance.
- [v] The carrier's ball socket lies ahead of his feet within his stride. A throw-in holds the ball above the head with both hands until release. A keeper catch holds it at the chest.
- [v] With `reducedMotion` the pose keeps position and facing, holds the still stance and shows each action as its single key pose (WEB-46).
- [v] Unit tests in `figurePose.test.ts`: "same input same pose", "faces velocity when moving and the ball when still", "stride amplitude grows with speed", "phase follows distance not time", "reduced motion holds still stance and key pose", "throw-in holds the ball above the head", "carrier socket stays within stride".
- [v] Unit tests in `figureActions.test.ts`: "shot makes a kick window ending at departure", "lost take-on makes a tackle for the opponent only", "slide only beyond standing reach", "saved shot makes a catch or dive for the keeper", "header flag makes a header", "no window without a recorded event".
- [v] ARCH-30 task tier passes: `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`, `pnpm exec vitest run --project unit --changed "$HAERAM_DIFF_BASE" --passWithNoTests`.

- Times are presentation running seconds, the same clock as `PresentationSample.time` (`apps/web/src/ui/presentationClock.ts`). An event of frame index `i` with `t` seconds sits at `i * 60 + t`.
- `figureActions.ts`:
  - `FigureActionKind = 'kick' | 'longKick' | 'shot' | 'throwIn' | 'header' | 'tackle' | 'slide' | 'catch' | 'dive'`.
  - `FigureActionWindow { kind; player; start; contact; end; toward: [x, y] (pitch units); dive?: -1 | 1 }`.
  - `figureActionWindows(frames: readonly MatchFrame[]): ReadonlyMap<string, readonly FigureActionWindow[]>`, each list sorted by `start`.
  - Kick contact is the ball's departure: the last `ballTimes` entry before the event at which the ball lies within `FIGURE_ACTION_CONFIG.contactRadius` units of the event's `from`. Without a track it is the event time minus `FIGURE_ACTION_CONFIG.fallbackFlight`.
  - `longKick` covers cross and clearance and any kick whose `from → to` exceeds `FIGURE_ACTION_CONFIG.longKick` units. A `restart: 'throwIn'` event makes `throwIn`; `header: true` makes `header` instead of a kick.
  - Tackle: only a `carry`/`takeOn` event with `lost` and an `opponent` makes a window, and it belongs to the opponent. It is `slide` when, in the sample before contact, the opponent stood farther than `FIGURE_ACTION_CONFIG.standingReach` metres from `from`, and `tackle` otherwise. A pass with `lost` is an interception and makes no tackle (prototype B NOTES §4).
  - Keeper: `shot` with `outcome: 'save'` and an `opponent`. It is `catch` when the ball's arrival lies within `FIGURE_ACTION_CONFIG.catchReach` metres of him, otherwise `dive`, with `dive` holding the side of arrival relative to his facing.
- `figurePose.ts`:
  - `FigureInput { id; keeper: boolean; time; position: [x, y] (pitch units); speed (m/s); velocity: [vx, vy] (screen px/s); velocityBefore (screen px/s, at time − FIGURE_POSE_CONFIG.hipLag); toBall: [dx, dy] (screen px); ball height; carrier: boolean; distance (m, from gaitDistances) }`.
  - The caller (T545) converts velocities to screen space because the drawn pitch is not isotropic. Playback velocity is pitch units per second: x 100 = 105 m, y 100 = 68 m.
  - `poseAt(input, windows | undefined, { reducedMotion }): FigurePose`. Joint positions are in a local frame scaled so torso width = 1 and +y is forward, and the painter scales them.
  - `gaitDistances(samples: readonly PresentationSample[]): ReadonlyMap<string, Float64Array>` holds cumulative metres per sample index, NaN where the player is absent. The caller interpolates between samples.
  - The stride phase is `distance / FIGURE_POSE_CONFIG.strideMetres` plus a phase offset from a hash of the player ID, so feet do not slide and speed changes cause no phase jump.
- Every tunable lives in `FIGURE_POSE_CONFIG` and `FIGURE_ACTION_CONFIG`, exported from these files. Start the values from prototype B's `CHARACTER_CONFIG`; `standingReach` 1.2 m and `catchReach` 1.0 m are defined here.
- Hash helper: a small local FNV-1a over the ID, no engine import. Both modules are read leaves for ARCH-4: they import only contracts types and `presentationClock.ts` types.

## result
- outcome: `figureActions.ts`: `figureActionWindows(frames)` reads events, samples and the ball track through `presentationSamples` (the same clock as the drawn playback). It makes kick/longKick/shot windows (shot also covers a penalty and anything with an outcome) whose `contact` is the departure, so `start` = contact − wind-up and `end` = contact + follow-through. It also makes throwIn, header, tackle/slide (opponent only, from the sample before contact), and catch/dive for a saved shot, header included. The keeper is placed at the arrival instant by interpolation, and `dive` is +1 his right, −1 his left, relative to the shooter he faces. It also exports `PITCH_METRES`, `FIGURE_ACTION_CONFIG` and `FIGURE_ACTION_LONGEST`. `figurePose.ts`: `poseAt` returns `FigurePose { facing, twist, lean, stride, phase, jump, lying, head, arms, legs, ball?, action?, overhead }`. Every point is in one local frame (torso width 1, +y forward, +x the player's right), with the legs already turned by `twist`; `figureOffset(facing, point, scale)` maps a point to screen px. The ball socket is `{ at, height, hold }`: the caller draws the ball at track + hold·(socket − track), so a kicked or thrown ball eases onto its recorded path. `gaitDistances` gives the drawn metres per sample, NaN while a player is absent. All tunables are in `FIGURE_POSE_CONFIG`, with values started from prototype B and rescaled to the T547 torso (width 1, depth 0.4).
