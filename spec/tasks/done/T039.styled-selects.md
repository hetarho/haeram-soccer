# T039 Shared styled selection controls
> st:done@261008 | ssot:WEB-33 WEB-17 ARCH-18 ARCH-28 | base:WEB@26 ARCH@3 | dep:-

## goal
Replace platform option menus with coherent, touchable dropdowns throughout the app.

## acceptance
- [v] Every visible single-choice select uses the shared styled trigger and list without changing values or domain handlers.
- [v] Named triggers, selected/disabled options, keyboard lookup/navigation, Escape and outside dismissal work in all three supported browser families.
- [v] Long lists and dialog-contained selectors fit desktop and both mobile viewports with 44px touch targets and restored focus.
- [v] Existing selection journeys exercise visible option selection and pass; the production entry and complete asset inventory stay within the existing compressed budgets.

## impl notes
- Use the native Popover top layer with a shared controlled ARIA combobox/listbox and CSS Modules; reuse option declarations and real string handlers. A measured Radix dependency exceeded the conservative asset budget, so preserve the existing budget with a small app-owned primitive.
- Render popup items on demand, preserve disabled empty-value placeholders and optgroup labels, and keep the list within its containing dialog in the DOM while using the native top layer to avoid clipping.
- Add a browser selection helper operating on the visible named combobox and its aria-controls listbox; update journeys that relied on native selectOption/option DOM.
- Keep styling in a shared module; remove obsolete per-view native arrow styling without changing compact layout bounds.

## result
- outcome: All single-choice controls use consistent app-styled dropdowns with selection, keyboard, top-layer positioning and dialog focus handling.
