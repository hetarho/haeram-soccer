# T463 One pinned Node version for Netlify builds
> st:done@261026 | ssot:ARCH-23 | base:ARCH@21 | dep:- | touches:netlify.toml tests/config | lane:- | explore:-

## goal
Netlify production and preview builds run the same Node as CI and local checks. Today `netlify.toml` sets `NODE_VERSION = "24.12.0"` while `.node-version` (read by every CI job through `node-version-file`) and `package.json` `engines.node` require 24.22.1; d8411fa1 raised the latter two and left Netlify behind.

## acceptance
- [v] `netlify.toml` no longer pins a Node version of its own: `.node-version` is the one pin Netlify, CI and local runs read (Netlify reads `.node-version` when `NODE_VERSION` is unset).
- [v] a fast unit test in `tests/config` fails when `netlify.toml` sets a `NODE_VERSION` other than `.node-version`, when `package.json` `engines.node` names a minimum other than `.node-version`, or when a `.github/workflows` setup-node step pins a version instead of reading `node-version-file: .node-version`; it is registered in the unit tier (`tests/config/test-tiers.ts`) if that registry lists files.
- [v] build commands, publish directory and the other `netlify.toml` contexts are unchanged.

## impl notes
- If Netlify's `.node-version` support turns out unusable for this site (the build log is the evidence, not available locally), set `NODE_VERSION = "24.22.1"` instead; the test then requires equality with `.node-version`.
- Parse `netlify.toml` with a small line read of the `[build.environment]` table; no new dependency.
- The production Netlify build only happens after the host's main push; record the deployed build's Node version as a limit if it cannot be read.
