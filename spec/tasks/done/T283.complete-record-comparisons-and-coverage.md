## goal
Use complete settled other-club statistics in existing comparisons without hiding generated metrics or inventing older coverage.

## acceptance
- [v] Existing player/scouting/league statistic queries consume the full aggregate ledger with the same Metrics/TD/PD definitions, competition scope, denominators and appearance semantics as own-club data.
- [v] Full-model counters are ordinary recorded game facts, with no missing/estimate badge caused only by engine choice. Before-activation periods remain unavailable and partial seasons show the actual start and sample size; missing and zero stay distinguishable.
- [v] Query/projection DTOs load detail on request and retain stable person/club/competition attribution across transfers and departures. Navigation, archived scope and current identity designs remain intact; no engine setting or full NPC match archive is added.
- [v] Projection/view-model tests cover `compares own and aggregate rows in the same units`, `shows a real zero separately from unavailable history`, `names partial tracking and samples`, `preserves a transferred contributor`, and `does not mutate or redraw on read`.
- [v] Add a focused responsive Chromium comparison journey for current full statistics and partial-coverage reload/import. Implement it and leave its execution to the ARCH-30 batch run; task checks and build pass.

## impl notes
- Keep projection DTO additions narrow and reuse T273's coverage/model contract. New `fullStatsView.ts` owns presentation mapping shared by the existing views; do not duplicate ratio/coverage policy in each component.
- Preserve existing own-player career links. NPC lifelong identity/history scope remains WORLD/HIST policy; a current-season statistic does not create an invented lifetime archive.
- Use compact settled fixtures from `tests/fixtures/worlds.ts` and synthetic aggregate rows; do not simulate a season to check a label.
- T281's review (P3): `NpcContribution` counts appearances only, while own tallies split starts from substitute appearances (`apps/web/src/ui/playerAnalysis.ts` `sub`). For the same appearance semantics add a `starts` counter (appearances = starts + substitute appearances) to the contract type, the strict schema, the container-3 packing and the reducer. Container 3 is not written in production yet, so change the packing in place without a migration.
- Same review: key the reducer's cached row index on the arrays' identity, not their sizes (`npc-stats.ts` index check), and look up the player before incrementing any club row so a throw leaves the ledger untouched. Build `preserves a transferred contributor` on `tests/fixtures/transferred-scorer.ts`'s real sale path.
- The ledger holds the current season only: close-day settlements (playoffs, Super Cup) fall into the ledger `prepareSeason` replaces, and every country's barrage shares `groupKey: 'promotion'`, so views never read a closed season from it. `trackingBoundary` clamps the round at 46 after the final round; tell the cases apart by the day.

## result
- outcome: The ledger now has the own-record appearance rule: `NpcContribution.starts` (appearances = starts + substitute appearances, a substitute being the `other` of a `sub` incident, as playerAnalysis `appearanceCounts` counts) runs through the contract type, the strict schema (`starts ≤ appearances`, required), the container-3 contribution row (`[club, appearances, starts, metrics, PD]`, changed in place without a migration) and the reducer. npc-stats.ts `settleNpcSeason` resolves every participating line before it touches anything, so a missing participant throws with the ledger (and a new scope) untouched; the cached row index follows the lists' identity, not their sizes. The new pure read `fullStatsRead(w, scope)` returns a copy of one competition of the season in progress, its `trackedFrom` and `untracked` (the competition's fixtures settled before the boundary's day), or nothing when the season keeps no ledger.
