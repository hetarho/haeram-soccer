## goal
Provide locale-independent message and display-formatting services with only the current Korean catalog registered.

## acceptance
- [v] The production locale registry contains exactly one entry, `ko-KR`, marked as its default, pointing to the Korean JSON pack. The pack holds the existing Korean shell/navigation text, presentation-setting labels/status/errors and facility-image descriptions needed by T302; it does not introduce English/Japanese catalogs or claim all feature/engine copy has been extracted.
- [v] `createTranslator` consumes validated locale resources, resolves semantic message IDs and named parameters, chooses plural forms from the selected locale, and returns plain text. Missing optional translated keys fall back to the default pack; absent keys or missing parameters produce a useful development diagnostic and a readable fallback rather than crashing the game.
- [v] `createLocaleFormatters` uses the selected registry locale for display numbers and UTC game-calendar dates. Keep game dates, exact money arithmetic, truncation/precision rules and historical currency units independent of locale; money decisions remain the existing WEB-67 logic.
- [v] Locale identity, self-name and direction come from registry metadata. Adding another registry entry and matching JSON pack requires no change to this module, message-key list, formatter switch or future TSX consumer. Parameter/key validation compares the selected resource with the registered default, without a separate manual catalog of supported languages.
- [v] Unit cases in `locale.test.ts` cover `preserves current Korean shell copy`, `interpolates a named parameter safely`, `selects plural forms from locale data`, `falls back for an absent message`, `reports a missing interpolation parameter`, and `formats a fixed game date without device timezone drift`. Additional locales exist only as in-memory synthetic test resources.
- [v] Task checks follow ARCH-30; the production build confirms no unsupported JSON/module dependency was introduced. Existing saved strings are not read, rewritten, parsed into translation keys or retrospectively translated.

## impl notes
- Reuse T299's `LocalePack`, message validators and resource contracts. Export `createTranslator`, `createLocaleFormatters` and a factory for an immutable loaded-locale snapshot; T302 owns React subscription and browser selection.
- Keep the source catalog as JSON. New locale content belongs in its resource file and registry entry, not in per-language TS/TSX files, additional providers or scattered import declarations.
- Copy current Korean wording exactly into the initial namespaces. Move the shell/settings and facility-description source strings only when T302 binds their consumers. Full feature/engine source extraction is a separate follow-up; saved names, event titles/details and historical prose remain ordinary data.
- Render values as escaped React text. Keep currency/season policy in the existing owning helpers; this task supplies presentation formatters without changing simulation or ECON decisions.

## result
- outcome: Added the sole registered ko-KR JSON catalog, safe named/plain-text interpolation, message-source-locale plural forms and default fallbacks with development diagnostics, registry-derived immutable snapshots, and locale display formatters preserving count rounding, exact integer digits and UTC/Gregorian dates. Fallback English grammar stays English under a French selection; present French messages retain French grammar. T302 binds the services to shell/format/facility consumers while stored prose stays unchanged.
