## goal
Until 1.0 the player always sees that the game is a beta: a small BETA mark sits at the top of every screen — beside the club name in the play HUD and beside the game's name on screens without it — and the start and save-slot screens show the game version as `v0.7 BETA`, read from the version T549 sets.

## acceptance
- [v] One shared BETA mark component (text `BETA`, a label for screen readers, theme tokens for colour so every shipped theme and dark/light reads it) appears in the play HUD beside the club name (→WEB-10) and at the top of every screen that has no HUD (start, founding, save slots, settings, recovery and error screens).
- [v] The start and save-slot screens show `v0.7 BETA`, built from `CURRENT_ENGINE_VERSION` (major.minor), never a hard-coded string.
- [v] The mark takes no tap target, does not push the HUD's primary controls below 44 px, and causes no horizontal overflow at 360, 390 and 1280 px (the layout helpers' checks).
- [v] Every shipped resource skin and theme (→WEB-69) shows the mark legibly; presentation baselines and captures that change are re-recorded with a one-line reason.
- [v] Tests: a unit test that the version label reads `v0.7 BETA` from the version constant; Chromium e2e "the BETA mark shows on the start screen, the save slots and the play HUD at 360, 390 and 1280 px".
- [v] ARCH-30 task tier: typecheck, lint, format check and the changed unit tests pass; the named e2e spec passes on Chromium.

## impl notes
- Where the copy lives: the existing presentation locale catalog (`apps/web/src/presentation`) (Korean first, English alongside where the catalog has it); the mark itself is not translated.
- Keep it small and quiet: a pill beside the name, not a banner; no new dependency.

## result
- outcome: one shared `BetaMark` (`apps/web/src/ui/BetaMark.tsx`, `BetaMark.module.css`). It is a quiet outlined pill: text colour `--accent-text`, border `currentColor`, `--badge-radius`, `--label-size` (12 px in every pack) and `--display`. No theme JSON changed, because every shipped pack already defines those tokens. The visible text is aria-hidden and untranslated: `BETA`, or `v0.7 BETA` with `version`. Beside it, a visually hidden label is read from the locale catalog as `shell.beta` ("베타 버전 {version} · 정식 출시 전까지 게임이 바뀔 수 있어요"); all 12 packs carry it with `{version}` kept. It is a plain span, never a control. The mark goes in four places. The play HUD puts `BETA` after the club name: `.hudClub > div` is now a two-column grid where the name gives way first and the start line spans below, and `<b>` stays a direct child so the image themes' `header > div > div > b` rules still apply. The start HUD puts `v0.7 BETA` after "Haeram Football"; founding, the existing-save loading and recovery path and the no-client error state all share that HUD. The save-slot screen puts `v0.7 BETA` beside "HAERAM FOOTBALL" in its header. The owner office, which hides the HUD (WEB-39), puts `BETA` in its office bar beside the place name (review correction 89252ecc). The mark sits in a centred group next to the `<h2>`, not inside it, so the heading text the office e2e helpers read (`officeTitle`) is unchanged. The bar's grid is now `minmax(max-content, 1fr) minmax(0, max-content) minmax(max-content, 1fr)`: the back button and the cash keep their whole width, and on a short row the place name ellipsizes first. When everything fits, the layout and centring are the same as before. The label comes from `apps/web/src/ui/versionLabel.ts`: `versionLabel()` gives `v${major.minor of CURRENT_ENGINE_VERSION} BETA`, and `isBetaVersion()` makes the mark render nothing from 1.0 (WEB-101 "until 1.0"). Settings (the pre-founding and slot pickers, the HUD menu) are dialogs over screens that already carry the mark; they have no mark of their own. Baselines: the repo has no committed screenshot baselines. The resource-skin captures write to `.tmp/resource-audit/` at run time, so nothing needed re-recording. Theme legibility is checked by the new e2e instead (one test per registered theme, contrast ≥ 4.5).
