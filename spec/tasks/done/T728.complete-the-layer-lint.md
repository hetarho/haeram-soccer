## result
- outcome: new local rule `layers/feature-sliced-imports` in `scripts/lib/layer-rules.mjs` (beside `i18n-rules.mjs`) replaces eslint.config.mjs's seven `no-restricted-imports` pattern blocks and their comment. The rule finds the importer under `apps/web/src/`, resolves each relative specifier against the importer's full path and normalises it, then locates `/apps/web/src/` in the result. So a specifier that climbs above src and comes back (`'../../../../src/entities/…'`, `'../../../../../web/src/pages/…'`) is classified by where it lands; review fix, the first version resolved inside src and ignored those. Resolution uses the path alone, with no file-system lookup, so `--stdin` probes and real files behave alike. It checks `import`, `import type`, `export … from`, `export * from`, `import()` and `typeof import()`. A layer never names a higher layer. Slices of a layer never name each other, except an entity naming `entities/<x>/@x/<itself>`. Outside a slice, a static import names only the index (`index` with or without the file name). A dynamic `import()` names a module file and never the index, which is new (`lazyIndex`). runtime/adapters/presentation name no layer, now also through `import()`/`typeof import()`. A side-effect-only import (`import 'x'`, CSS included, and `export {} from 'x'`) inside the six layers is an error. `typeof import()` is checked for direction and siblings only, because tests type their module mocks with it; it reads typescript-eslint 8's `source` (the deprecated `argument` only as a fallback). The tool entries and `main.tsx` keep the public-API check only. apps/web/AGENTS.md "Source layers" names the rule and the shapes it resolves. It says top-level work in a layer module (a store subscription, a document listener) runs only in a chunk that uses one of its exports, as `shared/routing/state.ts` and `shared/ui/Dialog.tsx` do, and that ESLint rejects side-effect-only imports in the six layers because the build would drop them
