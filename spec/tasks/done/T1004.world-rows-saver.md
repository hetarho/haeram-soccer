# T1004 The world maps to rows and a saver writes only changed rows
> st:done@261119 | ssot:SAVE-2 SAVE-3 SAVE-32 ARCH-8 ARCH-36 | base:SAVE@72 ARCH@51 | dep:T1003 | touches:apps/web/src/adapters/worldRows.ts apps/web/src/adapters/rowSaver.ts | lane:- | explore:- | run:claude/opus@high

## goal
A world can be written into the record store as rows and read back identically, and a `RowSaver` writes only the rows that changed since its previous save, in one transaction.

## acceptance
- [v] `worldToRows(w)` and `rowsToWorld(store, { includeCold })` round-trip: `canonical(rowsToWorld(store, { includeCold: true })) === canonical(w)` for the cached ten-season world (`cachedWorld('ten rich seasons')`) and a fresh `careerWorld`, including object key order of `people` (registry insertion order).
- [v] `RowSaver.save(w)` writes every row on its first call; after advancing the same world one day (`advanceDays`) a second `save` writes only changed rows — the test asserts the written count is below 10% of all rows and that the reloaded world equals the in-memory one.
- [v] A top-level field that becomes `undefined` deletes its `world_field` row; a record removed from memory deletes its row unless that row is `cold` (rows marked cold are never deleted by a diff).
- [v] `meta` carries `schema_version`, `engine`, `catalog`, `catalog_hash`, `world_id`, `revision` and is rewritten each save.
- [v] Task stage, owner implementer: `vibe check --tier task` passes.

## impl notes
- Table per family (seq = position in memory order, absolute index for arrays):
  | World field | Table | key | extra columns |
  |---|---|---|---|
  | `people` (record) | `person` | person id | — |
  | `squads` (record) | `squad` | club id | — |
  | `playerRecords` (record) | `player_record` | player id | — |
  | `ownMatches` (array) | `own_match` | absolute index (`String(i)`) | `id`, `year`, `opponent` |
  | `history` (array) | `season_archive` | year | `year` |
  | `events` (array) | `event` | absolute index | `year`, `kind` |
  | `newsJournal.seasons[year]` | `news_bucket` | year | `year`; the journal without `seasons` is the `world_field` row `newsJournal` |
  | every other top-level field | `world_field` | field name | — |
- Row data is `JSON.stringify(value)`; loading uses `JSON.parse` and inserts records in `seq` order so object key order and array order are restored. Absolute indices: T1016/T1017/T1018 add base counters (`ownMatchesBase`, `eventsBase`, `historyBase`) to the world; this task stores index = position + base where base is `0` when absent, so it is forward-compatible.
- `RowSaver` keeps `Map<string, string>` of `table\u0000key → data` last written; `save(w)` builds rows, compares strings, then calls `store.write({ put, delete, meta })` once. It exposes `markCold(table, keys)` used by the movers of T1014–T1018: cold rows are written with `cold = 1` and dropped from the comparison map so their absence from memory is not a delete.
- `rowsToWorld(store, { includeCold: false })` loads `cold = 0` rows only (used once records can be cold); `includeCold: true` restores the complete world (tests, `worldFacts`).
- Also export `worldFacts(w)` = canonical text of the complete world (memory merged with the attached store's cold rows) for determinism tests and benchmark hashes; until something is cold it equals `canonical(w)`.
- Node-side only here (node driver from T1003); the browser driver arrives in T1005.

## result
- outcome: `worldRows.ts` maps the world to rows (one row per `people`/`squads`/`playerRecords` record, `ownMatches`/`history`/`events` entry and news bucket; every other top-level field one `world_field` row, a family's row holding its empty container so its presence and key position survive) and back (`rowsToWorld`, `worldFacts`); `rowSaver.ts` diffs against the last committed rows and writes puts, deletes and `meta` in one `store.write`. Positional tables keep each surviving record's committed `seq`, so a removed record does not rewrite the records after it; `markCold` rows are written cold and leave the diff; a failed write keeps the saver's memory so the next save retries the same changes. Measured: ten-season world (1960) 27,505 rows (person 16,244, player_record 8,477, event 1,780, own_match 473, squad 450, world_field 71); one `advanceDays` after the first save wrote 200 of 27,525 rows (0.73%), deleting none.
