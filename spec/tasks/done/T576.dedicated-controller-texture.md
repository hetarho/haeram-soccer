## goal
Give the progression controller a genuinely distinct generated bitmap texture instead of another colour over a shared material.

## acceptance
- [v] A new bitmap material is generated with the built-in image tool, visually inspected, stored in the workspace, optimized to a 256px tile within the existing UI budget, and recorded with prompt and asset provenance.
- [v] Every built-in theme binds a dedicated controller-material image role; the controller consumes it without changing sheet, round or table-header textures.
- [v] Existing contrast, touch targets, theme palette and control behavior remain intact; older imported packs retain a neutral compatible fallback.
- [v] uiResources.test.ts verifies that the controller bitmap differs in resource and file contents from existing dark/paper materials; themeTokens.test.ts covers fallback. Browser skin assertions compare actual background images in the batch gate.
- [v] Affected unit tests, typecheck, lint, tracked formatting, presentation validation, art budgets, build and spec lint pass.

## impl notes
- Generate one neutral matte woven/herringbone texture whose visible pattern differs from the existing paper/ink materials; blend it with each theme's existing dark fill rather than filtering text or changing foreground colours.
- Register the resource through images.ui and resolveThemeTokens optional defaults. Preserve pixel rendering and use the semantic role in shared application CSS, not per-theme screen implementations.
- Baseline: 7ca294f0; leave T574/T575 and their existing changes untouched. No commit or push.
