## goal
Represent the existing complete pixel concept as data that shared consumers can replace without new theme-specific components.

## acceptance
- [v] The production theme registry contains only `pixel`, selected by its registry default. Its JSON/optional CSS describes the current typography, palette, surfaces, component shape, image treatment and semantic icons, referencing the existing licensed fonts and image files without generating, copying or renaming new artwork.
- [v] The pack maps stadium/locker/training images using shared era/kind/completed-stage slots. It covers the existing three-era image set and semantic navigation/trophy icons through T299's data contract; future packs may point to entirely different files and icon resources without changing a TSX caller.
- [v] `createThemeResolver` resolves semantic image/icon roles and tokens independently of React and world mutation. The browser adapter installs selected fonts/tokens/optional CSS atomically, cleans up replaced resources, and retains the current usable pack when a requested resource fails. It does not preload other themes or every facility-stage image.
- [v] Required tokens/slots have shared validation; missing required resources reject the candidate, while documented optional roles use an explicit same-role fallback. Defaults come from the registered baseline, not separate hardcoded pixel maps scattered among components.
- [v] Unit cases in `theme.test.ts` and `themeResources.test.ts` cover `resolves the current era and stage paths`, `resolves an unseen theme from data`, `preserves current icon layers and font weights`, `applies image treatment from the selected pack`, `retains the usable theme on a failed resource`, and `releases replaced styles and font resources` using injected installation ports.
- [v] Task checks and build follow ARCH-30. The task produces no second production theme, no new background image set and no changes to pitch drawing, match trajectories, presentationClock, kits or crests.

## impl notes
- Declare ordered representations of the same existing font in shared pack data, with the original WOFF2 preferred and a glyph/metrics-identical WOFF fallback. Try each source in a separate inactive FontFace; first success prepares that required font, while total failure retains the prior theme. Use getFontSources, resolveFontResource and fontSourceCss from presentation/fonts.ts as the shared source interpretation for resolution, installation and validation, preserve license/source notices, and introduce no browser-ID branches or new typeface.
- Reuse T299's validators/URL resolution and export `createThemeResolver` plus `installThemeResources`. T302 owns the shared state, hooks and component adapters; this task packages the current resources without editing their callers yet.
- The registry entry, `pixel.json` and optional `pixel.css` are the complete configuration surface for this pack. Image/font files are separate assets. Existing `/art/scenes/{era}/{kind}-{stage}.webp` paths remain valid, so the current theme does not require a resource relocation.
- Transfer visual constants from App.module.css, FacilityArt.module.css, PixelIcon and TrophyIcon into the pack. Use semantic font aliases and generic token names; changing a pack must not require editing a Galmuri-specific or theme-ID-specific consumer.
- Separate visual values from meanings: icon names, status meanings, era/stage selection, recorded club identity and gameplay remain common. Current layered SVG icons may be described by path layers; a new pack can use image resources through the same adapter, not a new component family.
- Additional theme concepts, their complete image sets and content authoring are outside this foundation. Synthetic alternatives belong in tests only.

## result
- outcome: Packaged this release's sole pixel concept with all 72 existing facility scenes, 31 semantic icon roles, current font weights and appearance tokens. A pure resolver and resource preparation/synchronous commit preserve atomic selection and installed ownership; declared image icons plus current mounted scenes are checked before activation. Shared font helpers resolve every primary/alternative resource into stable semantic aliases. The loader attempts separate inactive FontFaces in declared order, stages the first success and rejects total failure while retaining the previous theme. Pixel prefers the original WOFF2 files and declares glyph/metrics-identical licensed WOFF alternatives, without browser-ID or family-name branches. Shared tests accept resource-only registry additions.
