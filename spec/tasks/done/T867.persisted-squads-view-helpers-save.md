## goal
The 10,000 persisted players of T861 never travel to the UI thread, reach the fixture helpers only as changes, survive a save and a load exactly, and their size and time cost are measured before T862–T865 build on them.

## acceptance
- [v] View: `projection()` (`runtime/host.ts`) and `ProjectedWorld` (`runtime/protocol.ts`) leave `squads` out, as they do `people` and `freeAgents`. A test in `apps/web/src/runtime/host.test.ts` fails when the projected world carries `squads`, and a second one fails when a `World` key not on an explicit allow-or-exclude list is projected (a new top-level field must be classified, never forwarded by the rest spread).
- [v] UI reads: no code outside `apps/web/src/runtime` reads another club's players from the world. `entities/player/lib/teamState.ts`, `entities/player/lib/discipline.ts` and `entities/player/ui/OvrBadge.tsx` (and any other caller `grep -rn "squad(\|rating(\|startingSquad(" apps/web/src` finds for a club that is not ours) read values the worker puts in the view — each club's rating on its row, the names a discipline row shows — or a worker read; their existing tests pass on a view without `squads`.
- [v] Fixture helpers (→ARCH-6): `fixtureReplica` carries squads per club as put/drop changes, as `clubs` and `people` travel now, in place of T861's whole carry, only for the clubs whose players changed since that helper's last patch; a round's patch with no change carries no player. `apps/web/src/runtime/fixtureReplica.test.ts` covers a put, a drop, an unchanged round and a helper that missed a patch.
- [v] Packing: `adapters/packing.ts` packs `squads` in columns (attributes as integer hundredths, ids, names, positions, contracts as columns) with exact restoration; `apps/web/src/adapters/packing.test.ts` proves encode → decode returns every squad player deep-equal, for a founded world and for one whose attributes carry hundredths.
- [v] Load: writer activation of a supported checkpoint without `squads` runs `foundSquads` once (the →SAVE-28 pattern: an adopt step in `host.ts`'s activation chain, never on a read-only inspection) and saves; no other compatibility work.
- [v] Storage share (→SAVE-4/13): `scripts/persisted-size.ts` (new) lives a `historyWorld` 10 seasons and prints the compressed payload bytes `squads` adds under the checkpoint codec, per player and in total. The result records it against `PERSISTED_BUDGET.squads`; over it, an inbox `parked` line names the gap and the three ways out (a tighter packer | a smaller `NPC_SQUAD.size` | SAVE-4's portable limit) and the task still closes — it never passes by dropping fields.
- [v] Save cost: the engine worker's time for one checkpoint post (the structured clone of the world to the codec worker) and the codec's encode time, on that 10-season world before and after `squads`, recorded in result.
- [v] Throughput (→ARCH-34): the paired harness (`scripts/season-throughput.ts`, given a workload of 5 seasons of a world nobody owns if it has none) against the commit before T861 on this machine, recorded as a ratio with its noise. Above 1.25 the profile is read and the hot path cut; if two cuts do not bring it under, the ratio and the profile go to result limits and an inbox `parked` line, and the task closes.
- [v] `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`, `pnpm run build` and the changed unit tests pass.

- `PERSISTED_BUDGET` (new, in `scripts/persisted-size.ts`): `squads` = 500,000 bytes of compressed payload, `records` = 450,000 (T865). Source: the worst century profile (active-management, round 23) is 6,551,024 of SAVE-4's 8,388,608 portable bytes (`artifacts/benchmarks/T286-full-model-storage.json`), 1,837,584 bytes of file or about 1.07 MB of compressed payload left for squads and records together. Unpacked, the same 9,922 players are 6.6–6.9 MiB of JSON and 0.62–0.93 MiB gzipped (measured 261113), which alone would take the whole headroom.
- The throughput ratios are shares of one budget: ARCH-28 allows 5 s a season of generation on the reference trace and today's is 2.06 s, so the whole persisted world has ×2.4 of a season's time. This task takes 1.25, T862 1.6, T864 1.9 and T865 2.1, each cumulative against the commit before T861; T866 reads the reference trace itself.
- `apps/web/src/adapters/persistence.budget.test.ts` mocks packing and compression: it proves the byte-limit predicate, nothing about a world's size. The century profiles are measured by `scripts/benchmark.ts` (T866); this task's probe is the early read.
- The view publisher stringifies every world key on every publish and posts a part whole once its patch passes 80% of it (`viewPublisher.ts`): a `squads` key in the view would be stringified each day and posted whole on growth days. That is why the exclusion has its own failing test.
- Every save structured-clones the live world from the engine worker to the codec worker (`host.ts`); keep that single clone, add none.
- T862's `Club.levels`, T864's `playerRecords` and T865's lines follow three steps for every stored field: a `worldSchema` entry (it strips an unknown key silently, so an unlisted field is lost on load without an error), a packer with a round-trip test, and view exclusion where the field holds other clubs' players.
