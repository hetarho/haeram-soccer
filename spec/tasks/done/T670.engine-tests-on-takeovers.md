## goal
Engine and contracts tests get their career the way the game does — a club taken over in a world nobody owns — through one shared test builder, so the founding can leave the engine (T671).

## acceptance
- [v] `packages/engine/src/career.testkit.ts` exports `careerWorld(input?, release?)`, `CAREER_YEAR` and the `CareerInput` type (impl notes); `career.testkit.test.ts` checks that the same input makes the same world, that it passes `validateWorld`, that `club`/`country`/`tier`/`traits`/`preset`/`cash` reach the world, and that the default club is the first club of the country's lowest professional division
- [v] `historyWorld(seed, release, year)` takes an optional `year` (default `HISTORY_START`); `ownerlessWorld` (`ownerless.testkit.ts`) is `historyWorld(seed, release, CAREER_YEAR)` with no founded club to strip
- [v] every test and testkit under `packages/engine/src/` and `packages/contracts/src/`, and `packages/engine/src/lab/match.ts`, builds its world with `careerWorld`, `ownerlessWorld`, `historyWorld` or `generateHistory`; only the tests named in impl notes' "stays on createWorld" rule still call `createWorld`, each listed in the result for T671
- [v] each test keeps what it verifies: an expectation moves only where the start changed a fact (club id, division, cash, squad, year), never by loosening the rule under test
- [v] digests of the engine's integration files (`calendar.progression-eng`, `calendar.progression-esp`, `calendar.test.ts`, `full-model-throughput`, `grid-throughput` and any other the start moves) re-recorded only because the start changed; the result names each moved digest and why
- [v] unit + `pnpm run typecheck`, `lint`, `format:check` pass; the engine integration files listed in `tests/config/test-tiers.ts` that this task edits are run only to re-record digests and otherwise named for the batch

## impl notes
- Scope split (261103): web, `tests/`, e2e and `scripts/` move in T671, which then deletes `createWorld`; the amateur level is T672.
- `CareerInput` = `{ seed?: string; country?: CountryCode; club?: string; tier?: WealthTier; traits?: OwnerTrait[]; preset?: string; year?: number; cash?: string }`. Defaults: seed `'career'`, country `'ENG'`, club `` `${country}:${last}:0:0` `` with `last = country(code).groups.length − 1` (the lowest professional division, nearest the old amateur start), tier `'oil'` (every club affordable, as the e2e `DEFAULT_START`), traits `[]`, no preset (기본 방향), year `CAREER_YEAR` = 1950 (the old founding year, five seasons before the European Cup).
- `careerWorld` = `historyWorld(seed, release, year)` then `takeOver(w, club, { tier, traits }, preset, release)` (`takeover.ts`), then the club's cash: `input.cash` when given, else `CAREER_FUNDS` (2) × one year of fixed costs — the squad's and the manager's yearly wages, `footballQuote(country, year, 180)` upkeep and `w.operatingExpenses` — written to `w.cash` with no ledger entry. ← a fresh world's books open at cash 0 and an unfunded club goes bankrupt at round 8; 2 years is what the old 쉬움 founding gave, so season-long tests stay solvent
- `historyWorld`'s `year` is for tests and measurements only, like `release`: production always makes its world in 1930 (→WORLD-13); state that in its doc comment.
- Tests that read `FOUNDING_YEAR` read `CAREER_YEAR`; tests that matched the founded club's `${code}:club` id read `w.playerClub`. `professionalStart` (testing.ts) is a no-op on a taken-over club (`w.lower` false); drop its calls where the world now comes from `careerWorld`, and leave the helper for T672 to delete.
- Stays on `createWorld`: a test whose subject is the founding itself (difficulty cash and offsets in `world.test.ts`, the founding squad, the founding identity input in `club-identity.test.ts`/`identity-operations.test.ts`) or the amateur level (the amateur league and its `lower` fixtures, the exchange in `season.exchange.test.ts`/`season.testkit.ts`, amateur gate, expenses or reputation rows). T671 deletes those tests with `createWorld`; T672 deletes the amateur code and adds LEAGUE-16's test.
- Lab (`lab/match.ts` `createLabWorld`): `historyWorld('lab-world')` — the hosts are two top-flight clubs nobody owns and no own club is needed; LAB results that move are re-recorded in `lab/*.test.ts` and named in the result.
- Contracts tests (`schema.test.ts`, `schema.contract.test.ts`, `identity.contract.test.ts`) use `careerWorld`; the contract golden (`tests/fixtures/portable-v1.json`, `scripts/update-golden.ts`) is regenerated by T671, so `schema.contract.test.ts` must not depend on it changing here.
- Shared fixture caches: tests that lived seasons through `tests/fixtures/worlds.ts` `simulatedWorld(Founding…)` keep calling it until T671 changes its input; do not change `tests/fixtures/` here.
