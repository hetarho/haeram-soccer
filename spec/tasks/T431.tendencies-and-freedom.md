## goal
Compute every player's four tendencies in the engine — 자유도 as the freedom his manager gives him, 규율, 압박 성향 and 예측력 from attributes and his stable personality — and show those values in the match inspector, ready for T432–T433 to move players by them.

## acceptance
- [ ] `grid/tendencies.ts` exports `TENDENCY_CONFIG` and `playerTendencies(player, manager, role)` returning `{ freedom, discipline, pressing, anticipation }` in 0–1. 규율, 압박 성향 and 예측력 keep today's `motionTraits` formulas (attributes plus the stable `personality:<id>` draw); freedom follows STAFF-46: manager flexibility / 100 × `TENDENCY_CONFIG.roleCreativity[role]` × (0.5 + 판단력 / 200), mapped through `TENDENCY_CONFIG.freedom.floor` 0.1 and `span` 0.9.
- [ ] `TENDENCY_CONFIG.roleCreativity` has one entry for every role the role catalog names (PLAYER-5, docs/MATCH-BASELINES.md): 0.2 for centre-backs and holding midfielders, 1.0 for trequartista, false nine and free roles, the rest between by how freely media describe the role, each value commented.
- [ ] A founding manager or an interim gives freedom from `TENDENCY_CONFIG.neutralFlexibility` 50; a club nobody owns uses its named manager's flexibility; no owner setting reaches freedom.
- [ ] Nothing in play reads the new values yet: no movement, decision or record changes on any path, and every digest (pre-feature, candidate, release-on) is unchanged; `motionTraits`' 규율, 압박 성향 and 예측력 values stay identical for every player.
- [ ] The inspector (`Pitch.tsx`) shows `playerTendencies` for the selected player (자유도 the manager-given freedom) instead of `motionTraits`, which is removed or delegates to it.
- [ ] Tests in `tendencies.test.ts`: "the same manager gives a trequartista more freedom than a centre-back", "a more flexible manager gives more freedom", "better 판단력 gives more freedom", "a player's personality is stable across fixtures", "the owner has no input to freedom".
- [ ] Task checks (ARCH-30): typecheck, lint, format:check, `vitest run --changed`, `pnpm run build`.

## impl notes
- Manager flexibility is the hire attribute STAFF-1/STAFF-14 band (0–100); read it from the own manager and from each named NPC manager as the engine already stores them, deriving nothing new.
- 예측력 sets when a player reacts, 위치선정 where he stands and 판단력 what he decides (PLAYER-26); keep the formulas apart so T433 does not count an attribute twice.
- No movement change here; T435 stores the values once per match on revision 2, T432 consumes `freedom`, T433 the other three.
- Runs before T286 and T435 (261025): `playerTendencies` is a pure function the inspector calls and T435 later calls from the grid setup, so it needs no revision gate; leave `grid/setup.ts` to T435.
