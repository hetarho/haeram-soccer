## goal
Create the shared metric, condition and measurement registry used to assess both engines without changing production football.

## acceptance
- [v] `scripts/lib/match-parity.ts` exports `METRIC_REGISTRY`, `PARITY_CONFIG`, `CORPUS_CONFIG`, `PERFORMANCE_CONFIG` and report builders covering every Metrics/TD/PD index, participation, incidents and derived denominators, with authoritative target bands and canonical units.
- [v] Reports separate missing/unsupported fields from actual zeros, absolute target errors from path-equivalence errors, and exact invariant failures from statistical uncertainty. Record source/toolchain/machine/seed/condition provenance and distinct calibration/validation partitions.
- [v] `scripts/match-model-baseline.ts` supports `--out`, `--fixtures`, `--seasons` and a smoke mode. It measures preparation, isolated grid/legacy-summary fixtures, settlement and complete season engine time separately; it never changes the production dispatch constant or candidate release switch.
- [v] `scripts/lib/match-parity.test.ts` includes `covers every counter exactly once`, `rejects missing metrics instead of zero filling`, `keeps training and validation seeds disjoint`, `does not call overlap a proof of equivalence`, `reports constant and underpowered variables`, and `separates computation from codec time`.
- [v] Execute a smoke measurement and retain its actual source fingerprint and limits. Mark the release baseline provisional until T273 captures the post-T255 source; no historic cross-machine timing is claimed as a paired result.
- [v] Task verification follows ARCH-30; large calibration and century runs are not unit tests.

## impl notes
- Read `docs/MATCH-MODEL-CONTRACT.md`, especially ownership and measurement. This task owns the shared settings; later tasks import their names rather than copying thresholds or corpus sizes.
- Derive counter indexes and existing target curves from contracts and the existing calibration harness. Represent ratio denominators and rare-event families explicitly. Use deterministic resampling/equivalence intervals; absence or insufficient power stays non-passing.
- The baseline runner must work against the existing public engine API on a source preceding new football changes. Use optional adapter detection for later candidate paths and document how to execute the same runner in an isolated baseline checkout.
- Keep tooling outside the web import graph and preserve existing task files. No application code or active identity work is changed here.
