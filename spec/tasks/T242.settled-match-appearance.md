## goal
Capture the actual home/away appearance once on the existing settlement path and keep it unchanged through later identity edits.

## acceptance
- [v] appearanceForFixture reads the selected identities/role, obtains automatic keepers and deep-copies a version-1 MatchAppearance in home/away order.
- [v] The shared recordMatch path attaches appearance after the duplicate-own-match guard and before storing/capturing an own result; observed and unobserved results obtain the same appearance.
- [v] match-appearance.test.ts cases freezes live and saved appearance across own edits, consumes only the named choice at settlement, duplicate settlement never rewrites appearance, and legacy records remain absent pass.
- [v] League, domestic cup and continental own-result tests prove they reach this shared capture; unrelated NPC matches do not create a new full-world appearance archive.
- [v] Sporting results/counters/unavailability from the grid integration remain identical with or without kit choices after excluding appearance metadata. The grid simulator and timing are untouched.
- [v] Targeted engine tests pass without requiring the not-yet-implemented appearance codec. Golden regeneration and complete codec/contract checks belong to the next packing task.
- [v] Targeted verification passes: `pnpm exec vitest run packages/engine/src/match-appearance.test.ts packages/engine/src/season.test.ts packages/engine/src/cups.test.ts packages/engine/src/europe.test.ts && pnpm run typecheck`.

## impl notes
- Read `docs/CLUB-IDENTITY-CONTRACT.md` sections named below; it owns the stable interfaces used in this task.
- Prerequisites: T241, T239. Read their implemented interfaces/results before editing; extend those modules rather than reproducing a prerequisite.
- Read design §5. Use the actual post-grid recordMatch function, not a copy of the old legacy-duel loop. The returned live playback and the saved own record must carry the same captured values.
- At this boundary the fixture score may already be assigned. appearanceForFixture resolves by record.home/away and the matching named choice; it does not call nextOwnFixture to rediscover an already played fixture.
- Resolve identities and select colours without reading score, xG, incidents or sporting RNG state. Preserve all existing grid record, injury, discipline and material settlement.
- Delete kitChoice only if its fixtureId equals this settled own record. An earlier newly drawn cup tie must not consume a choice for a later named league match.
- Season, cup and Europe settlement tests take worlds already in the needed state from `tests/fixtures/worlds.ts` (`simulatedWorld`/`cachedWorld`) and simulate only the settlement they verify (ARCH-21); where a suite is split into part files, add cases beside the matching part and its `.testkit.ts` helpers.
- Do not add frame/squad persistence or regenerate historical appearance on read. Snapshot cloning and current-identity replacement avoid aliases.

## result
- outcome: completed. New leaf `packages/engine/src/match-appearance.ts` imports only the contract identity/types, `club-identity` and `kit-selection`. It exports `appearanceForFixture(w, fixture)` and `captureAppearance(w, record)`.
  - `appearanceForFixture` resolves both clubs by `fixture.home`/`away` through `identityOf` (the stored identity, or the legacy default it would adopt). It forces our side's role only when `w.kitChoice.fixtureId === fixture.id`, and never calls `nextOwnFixture`. It runs `selectMatchKits`, so the opponent and both automatic keepers come from T239. It returns a `structuredClone`d version-1 `MatchAppearance`, sides home then away, with the selection's warnings. It reads no score, xG, incident or RNG.
  - `captureAppearance` sets `record.appearance ??= appearanceForFixture(...)`, then deletes `w.kitChoice` only when it names this record.
  - `recordMatch` (season.ts) calls it for own matches right after the duplicate-own-match guard, before bans, discipline, Elo, tables and the `saved = { ...m, players }` push. The returned live playback and the saved record therefore carry the same captured snapshot, and a duplicate settlement returns before the capture.
  - League rounds, `resolveTie` and knockout `playFixture` (domestic cups and Europe) all record through this one function. The grid simulator, its timing and all other settlement are untouched.
  - Build sizes: the lazy `settlement` chunk grew 66.80 → 67.26 kB gzip (kit selection and pattern sampling now live there), `index` 119.31 → 119.32 kB gzip, the worker 1,992.49 → 1,996.31 kB raw.
