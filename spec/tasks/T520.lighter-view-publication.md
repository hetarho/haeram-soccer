## goal
Publish each day's view delta with less work on both threads while the deltas and the rebuilt view stay byte-identical.

## acceptance
- [ ] `viewPublisher.ts` compares leaves structurally as their JSON would compare (no per-leaf stringify) and keeps the base's large parts parsed, owned by one published view and patched in place, instead of parsing the base text every day.
- [ ] The worker posts a delta's patches as the JSON text already written to size them (`patchText`); `applyViewDelta` reads it back; a client naming an older base still reparses correctly.
- [ ] The client shares references while applying a delta onto its current view (`shareValue` exported from `store.ts`), skipping the second `shareView` walk.
- [ ] `viewPublisher.test.ts`: over a 49-day fixture run the deltas are byte-identical to the previous publisher's and the rebuilt view is deep-strict equal to the host view every day; `protocol.test.ts` covers `patchText` round trips including an older base.
- [ ] typecheck, lint/format on touched files and `pnpm exec vitest run --project unit apps/web/src/runtime/viewPublisher.test.ts apps/web/src/runtime/protocol.test.ts apps/web/src/runtime/store.test.ts` pass; `client.test.ts`/`host.test.ts` (integration) listed in result limits.

## impl notes
- Port prototype commit `05e8e42d` (branch `perf/c-around-matches`, in `perf/integrated` as `3f2d873e`). Measured on an own match day: publish 30 → 21 ms, transfer clone 11 → 1.4 ms, main-thread apply 10 → 7 ms.
- `patchText` goes through JSON: values JSON cannot carry (`undefined` keys, NaN, Date) must not appear in views; the equality test guards it.
- Not in scope: `cohesion` changing daily marks all ~732 clubs changed; trimming that is a later candidate.
