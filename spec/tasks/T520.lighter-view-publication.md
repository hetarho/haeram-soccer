## goal
Publish each day's view delta with less work on both threads while the deltas and the rebuilt view stay byte-identical.

## acceptance
- [v] `viewPublisher.ts` compares leaves structurally as their JSON would compare (no per-leaf stringify) and keeps the base's large parts parsed, owned by one published view and patched in place, instead of parsing the base text every day.
- [v] The worker posts a delta's patches as the JSON text already written to size them (`patchText`); `applyViewDelta` reads it back; a client naming an older base still reparses correctly.
- [v] The client shares references while applying a delta onto its current view (`shareValue` exported from `store.ts`), skipping the second `shareView` walk.
- [v] `viewPublisher.test.ts`: over a 49-day fixture run the deltas are byte-identical to the previous publisher's and the rebuilt view is deep-strict equal to the host view every day; `protocol.test.ts` covers `patchText` round trips including an older base.
- [v] typecheck, lint/format on touched files and `pnpm exec vitest run --project unit apps/web/src/runtime/viewPublisher.test.ts apps/web/src/runtime/protocol.test.ts apps/web/src/runtime/store.test.ts` pass; `client.test.ts`/`host.test.ts` (integration) listed in result limits.

## impl notes
- Port prototype commit `05e8e42d` (branch `perf/c-around-matches`, in `perf/integrated` as `3f2d873e`). Measured on an own match day: publish 30 → 21 ms, transfer clone 11 → 1.4 ms, main-thread apply 10 → 7 ms.
- `patchText` goes through JSON: values JSON cannot carry (`undefined` keys, NaN, Date) must not appear in views; the equality test guards it.
- Not in scope: `cohesion` changing daily marks all ~732 clubs changed; trimming that is a later candidate.

## result
- outcome: Ported prototype 05e8e42d. `viewPublisher.ts` compares leaves with `sameJson` (structural, JSON's key order, non-finite → null, `toJSON`/class instances/bigint still as text), keeps each large part's parsed JSON in the published view that owns it (handed over when its text is unchanged, patched in place by `patchJson` from the patch's own JSON when patched), and parses the base text only when that copy is gone (an older base, a part first patched); `forPosting` swaps a delta's `patches` for the `patchText` written while sizing them and `worker.ts` posts through it. `applyViewDelta` reads `patchText` back and takes an optional `ShareValue`; the client rebuilds a delta on its published view with the exported `shareValue` and skips the `shareView` walk (an empty delta yields the base itself). One fix over the prototype: when a patch adds a key to an object the parsed copy is not kept, since the patch does not say where the key sits among the unchanged ones and a later removal's `d` order would differ (`["record","captain"]` vs `["captain","record"]`); the 49-day test fails without this guard (checked by disabling it).
