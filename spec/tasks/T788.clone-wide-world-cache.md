# T788 share the test-world cache across a clone's worktrees
> st:todo | ssot:ARCH-21 | base:ARCH@38 | dep:- | touches:tests/fixtures/json-cache.ts tests/fixtures/json-cache.test.ts | lane:world-cache

## goal
Every local worktree of the clone (the owner's checkout, `.tmp` gate worktrees, worker worktrees) reads and writes one world cache under the Git common directory, so a gate or task check in a fresh worktree reuses worlds already built for the same fingerprint; CI keeps its per-job path.

## acceptance
- [ ] with `HAERAM_WORLD_CACHE` unset and not on CI, the cache base is `<git common dir>/haeram/worlds` (resolved once per process with `git rev-parse --git-common-dir`, absolute); on CI (`CI` set) it stays `node_modules/.cache/haeram-worlds`; `HAERAM_WORLD_CACHE` (including `off`) still overrides both; if the Git lookup fails the old path is used
- [ ] keys, file layout below the base, locking, temp-then-rename writes and pruning (`maintainDirectory`) are unchanged; two worktrees building the same entry at once still produce one file
- [ ] a unit test covers the base resolution (env override, CI, Git common dir, fallback) without touching the real cache
- [ ] a probe: build one small cached world in worktree A, read it from worktree B (a temporary detached worktree) without rebuilding; record the paths and timings
- [ ] `pnpm run typecheck`, `pnpm run lint`, `pnpm run format:check`, `pnpm exec vitest run --project unit tests/fixtures --maxWorkers 2`
