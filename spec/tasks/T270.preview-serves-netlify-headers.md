## goal
Browser tests run against exactly the headers Netlify serves, because the preview reads them from the built `_headers` file instead of hard-coding its own copy.

## acceptance
- [ ] scripts/preview.mjs parses `apps/web/dist/_headers` (Netlify format: an unindented path pattern, then indented `Name: value` lines; `*` matches any rest of the path) at start-up, as it already does `_redirects`, and sends every header of every matching block, later blocks overriding earlier ones for the same name; the hard-coded `csp` constant and the literal CSP, `X-Content-Type-Options`, `Referrer-Policy`, `X-Frame-Options` and `Cache-Control` values are removed.
- [ ] Content-Type, Content-Length, gzip `Content-Encoding`/`Vary` and the SPA fallback stay computed as today; the `/assets/*` immutable cache and the `no-cache` entry HTML now come from `_headers`.
- [ ] `tests/e2e/preview.spec.ts` case "serves the _headers set": for `/`, a deep route and one `/assets/` file, every header `_headers` declares for that path (read from `apps/web/dist/_headers` in the test) arrives with the same value, `Permissions-Policy` included.
- [ ] Existing preview checks still pass: `pnpm run build` then `PREVIEW_BUILD=1 pnpm exec playwright test --project=chromium tests/e2e/preview.spec.ts tests/e2e/entry.spec.ts`.
