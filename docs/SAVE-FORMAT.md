# Portable v1 save format

The envelope carries schema `1`, engine/catalog IDs, catalog hash, world ID, generation, parent generation, codec, SHA-256 checksum and payload. Payload is gzip over UTF-8 canonical compact JSON. The checksum covers the uncompressed canonical compact JSON, not the envelope or gzip implementation.

Codec `gzip-cjk14` (written) encodes the gzip bytes as dense text: a header character U+4E00 + p, where p (0–13) is the number of zero padding bits, then one character U+4E00 + v per big-endian 14-bit group v (U+4E00–U+8DFF, CJK Unified Ideographs: assigned, no surrogates, stable under every normalization form). Browser storage is budgeted per UTF-16 code unit, where Base64 carries 6 bits and this text 14. Decoding rejects characters outside the range, a padding count above 13, a bit length that is not a whole number of bytes and non-zero padding. Codec `gzip-base64` (standard Base64 of the same gzip bytes) is still read; it is never written.

Canonical JSON sorts object keys by raw UTF-16 order, retains array order, drops undefined object fields, uses finite JSON numbers and encodes exact money as decimal strings. It rejects unsupported values. The complete inflated representation must fit 16 MiB; imports cap 4 MiB. Header, version, checksum, world schema, references, currency and pinned catalog hash are checked before activation.

## Lossless compact representation

`apps/web/src/adapters/packing.ts` is the reference codec. `compact1` keeps current world metadata, a shared string dictionary, owned-match tuples, binary statistics and standings counts. It omits reproducible domestic fixture definitions: reconstruct with the pinned engine's `prepareSeason(world, false)` and apply saved score tuples by fixture index. European fixtures remain explicit.

Match tuples preserve fixture identity/year/round/kind/home/away/country/group/score, owned player IDs, recorded highlights and tactics. Numeric streams use column-transposed unsigned LEB128 without truncation. Current encoding groups actor dimensions, player IDs, highlights and tactics into separate streams; the reader also accepts the former combined actor stream and older explicit match tuples.

Statistics use declared-width bit columns: width 156 for uniform 11-player owned matches (13 rows × 12 counters), otherwise width 12. Exact per-column minima and bit ranges preserve all safe integer bits. The optional `planes` layout groups equivalent bit positions for gzip; omitted layout retains the earlier column interpretation. Optional residual flags encode failed passes/off-target shots and signed interception-versus-tackle differences. Decode restores the original counters; unsafe values, unknown layouts, truncated streams, invalid dimensions and unconsumed data fail validation.

Domestic and European phase standing rows each have width 6, stored in a separate column-transposed unsigned-LEB128 stream with optional signed column deltas. Per-season domestic row counts and per-tournament first/second phase counts reconstruct every row. Event templates and variable-string dictionaries preserve complete event details. String dictionaries and tuples are bounded; unused/missing stream elements fail decoding. No pruning or lossy rounding is allowed.

Seasons closed under rules `1.12.0` or later also archive what their pages need after the live tables are gone. The own league's ten leading scorers (name, club index, role, goals, appearances), the own rank after every league round and the rounded Club Elo spread (world lowest, world highest, own league lowest, own league highest) stay inline in the history JSON. Each knockout bracket (`cup` for the own country's cup, otherwise the continental competition key; the Super Cup is not kept) keeps its rounds from the first round of 32 clubs or fewer to the final: label, league round, legs and bye club indexes stay inline with an empty tie list, while every tie row of every season — [home, away, leg 1 home goals, leg 1 away goals, leg 2 home goals, leg 2 away goals, outcome], each leg in its own fixture's order, 0, 0 for a single match's leg 2, outcome = winner side (0 home, 1 away) + 2 for penalties + 4 for away goals — shares one width-7 column-transposed unsigned-LEB128 stream (`bracketTies`). `bracketCounts` holds, per season, each archived round's tie count in order; counts that disagree with the archived rounds or with the stream's row count fail decoding (`대진 기록 압축 데이터 손상`), as does a stream without archived brackets. Seasons closed earlier have none of these fields and are never backfilled.

Rules `1.13.0` worlds may carry two optional fields inline in the world JSON: `buildNext` (a strategy reserved for the next season: its build cards and an optional name of at most 20 characters) and `managerMarket` (`year` and `round` of the last refresh, `free`: at most eight free-agent managers in the manager shape, `clubs`: per club that changed manager the pair [count, since], and `serial`, the number of free agents created). Other clubs' managers are derived from the seed, the club and its count, so only changes are stored. Earlier worlds have neither field.

Rules `1.14.0` changes no field. Continental knockout rounds drawn from then on put a tie's return leg (`:2`) on its era's calendar instead of the next round; legs stored earlier keep their rounds, and stage labels read both calendars.

Rules `1.15.0` adds one optional field inline in the world JSON: an outgoing (`out`) bid may carry `offer`, the market player it was made for in the player shape with the asking `fee` and `loanFee` as decimal strings, so the bid is answered on those terms whatever the market list shows meanwhile. A bid pending from earlier rules has no `offer` and finds its player in its season's list as those rules did. The rest of `1.15.0` changes results, not fields: every progression mode lives the same days in one order with draws named by what they settle (each day lived advances `revision` by one, so a league round is as many revisions as its days), the amateur level swaps places with the last professional division by the amateur table, a currency change converts every live amount and market lists follow the settings. Checkpoints from `1.0.0` through `1.14.0` remain accepted.

Rules `1.16.0` add, among others, three optional fields inline in the world JSON for the owner's levers, each stored only while it differs from its default: `hiring` (`manager`: the manager criteria `minOvr`, `schools`, `minFlexibility`, `maxPride`, `minYouth`, `traits`, an optional `maxWageOvr` of 50–90 in steps of 5, `priority`, `term`, `poach` and `whenNone`; `coaches`: per department the coach criteria `volunteer`, `minAbility`, an optional `trait`, an optional `maxWageOvr`, `priority` and `term`), `talkRule` (`maxPay` one of 0.9, 1, 1.1, 1.25 and 1.4, `minOvr`, an optional `maxAge` of 28–40) and `buildChanged` (per strategy slot, the `year` and `day` its card last changed; the slot stays locked for 90 days from then, and only running locks are kept). Delegation keys `coach:<department>` replace the single coach-hiring key `staff`. `buildYear` and `buildNext` are read only from older worlds: a load turns `staff` into the seven department keys with its value and drops `buildYear`, so every slot is free; it turns coaching investment levels (`coaching`) into `hiring.coaches` entries where none exists (1 → `volunteer: true`, 2 → nothing, 3 → `minAbility: 65` with `priority: 'ability'`, each over the defaults) and drops `managerRule`; writer activation drops `buildNext` with an inbox item naming it and delegates contract talks where the academy is delegated.

Archived movement frames are not save facts. Historical goal playback uses preserved goal minutes; only the final recorded counters are displayed in that summary playback.

Scorer records keep one stable player identity through transfers within the tracked league. An optional `clubs` array retains actual `{club, goals, appearances}` contributions once more than one club contributes; live records use club IDs and archived top-ten records use stable club indexes. Aggregate totals must equal those contributions, each club occurs once, and the displayed club is the latest contributing one. Older single-club records remain valid without an invented split.

## Second-career feature state

The rules 3.0 feature payload keeps settings (seven responsibilities, progression mode and observations), the recruitment support row, player qualities, staff/manager person links, joint playing-coach proposals, coaching-market refresh dates, actual recruitment arrivals, mediations and promises as canonical fields. The envelope, checksum, two-slot protocol and size limits are unchanged. Release activation and bounded legacy classification are separate from this encoding.

`compact1.careers` is optional and versioned independently as `{ version: 1, people: [...] }`. When present it is the only encoded person-registry source; `world.people` is absent. Each person is one strict 20-column tuple:

1. Shared-dictionary indexes for ID/name; birth year; position index; professionalism; understanding/teaching/judgement grades; playing-status index.
2. Optional club index, optional former-own boolean, optional origin `[club, slot]`, optional loan `[parent club, until]`, and genuinely retained own-career metrics.
3. Employment rows `[role, club, from year, from day, to year, to day, contract-end year, contract-end day, wage, currency, grown-through year]`.
4. Mentor rows `[manager, name, school, club, from year, from day, to year, to day]`.
5. Optional intention `[year, day, retained draw, willing, encouragement year, encouragement day, changed]`, retirement `[announcement year, announcement day, scheduled year, actual year, actual day]`, coaching `[role, actual ability, potential, entry year, entry day]`, and management `[actual ability, potential, school, entry year, entry day]`.

Identity, club, role, school, name and exact decimal-money strings use the existing shared dictionary. Null means absent, preserving false/zero values; dates require both columns together. Learned ability/potential retain finite numeric precision. Player/staff arrays and their stable person links remain inline, preserving qualities and role-specific facts without a second complete person object. All employment and mentor periods survive; missing playing totals stay absent.

The decoder accepts prior `compact1` worlds with an inline registry and no `careers` section. It rejects simultaneous inline/row registries, unknown career-row versions, malformed dimensions or dictionaries, duplicate identities and invalid expanded references/intervals/deadlines. Schedule reconstruction never enrolls people, draws career facts or changes the saved registry. Full canonical save/export/inspect state stays complete; daily UI projections omit lifetime people and bound resolved decisions, with on-demand reads for full details. Drafts and derived display models are not canonical save fields.

## Commit and recovery

Application keys: `haeram-soccor:slot:a`, `haeram-soccor:slot:b`, `haeram-soccor:manifest`. The manifest selects the current slot/world/generation and parent generation. Write/readback-verify the inactive slot, switch/readback-verify the manifest, then acknowledge. The old active slot remains available on quota/write failure.

Validate the manifest's slot, world ID, generation and parent generation against the selected checkpoint. A valid manifest selects the committed generation even when an interrupted write left a newer inactive slot. A valid previous-generation compatible checkpoint may recover the previous world after corruption. Corrupt/missing manifests trigger recovery in descending generation order, with slot A winning a tie. Unsupported selected schemas, engine versions or catalogs are compatibility failures: preserve and export the selected raw career instead of silently falling back to an older one. Loading/recovery does not erase source slots. Export uses the same envelope and can preserve in-memory progress when browser quota prevents a new checkpoint.

Only one Web Lock owner writes. Commands use protocol/session/request/expected revision; duplicate effects are prevented by acknowledgments/receipts and stale revision checks. Main-thread adapters perform storage I/O; the worker validates, projects, compresses and hashes.

Engine rules `1.1.0` accept `1.0.0` careers. Writer activation upgrades only engine metadata, the catalog pin of a save written under an accepted earlier catalog, and revision through a pure transformation and the two-slot protocol; old match/player/economic facts and absent optional fields remain unchanged. Read-only views do not upgrade metadata or disk. Upgrade write failure keeps the old committed career and exportable upgraded memory, with an explicit retry. Unsupported versions/catalogs require an explicit future migration or matching engine. No legacy Flutter JSON importer or automatic downgrade is claimed.

Rules `3.0.0` start new careers. Only known released rules `1.0.0`–`1.22.0` and `2.0.0`, with recognized schema/catalog/codec, matching payload metadata and valid checksum, qualify for the writer-only legacy gameplay reset. Each active checkpoint and parked game is classified independently; unknown/future or corrupt unclassified data stays available for recovery. An interrupted parked cleanup is journaled and retried. Device profile, strategy library, preferences and unrelated storage survive. Legacy file imports remain refused.

Portable fixtures keep the four historical scenarios and their original explicit authority unchanged. `currentRules: true` selects the active founding defaults; marked `announced-player` and `financial-conflict` setups provide deterministic synthetic inputs. Their actual encouragement, joint approval, manual events and mediation use normal commands. The current-rule expected facts also include responsibilities, retained own-person careers, joint proposals and fixed-deadline commitments; `tests/fixtures/run.ts` defines this portable projection.
