# gusta-self-improve 자율 실행 중단 문제: 원인과 수정 요청

작성일: 2026-11-14

## 결론

이번 중단의 직접 원인은 실행자의 판단 오류다. 사용자가 이미 맡긴 **기존 기준을 유지한 실패 수리**를 새로운 정책 승인 문제로 분류하고, 추천안을 구현·검증하는 대신 사용자 선택 뒤로 미뤘다.

제품의 `AGENTS.md`에서 이번 모델 수리를 사용자 승인 대기로 묶는 규칙은 발견하지 못했다. 따라서 제품 지침에서 삭제한 문구는 없다. gusta의 공통 문구와 self-improve 전용 위임 규칙에는 오해를 부르는 간극이 있어, 아래 수정을 요청한다. 설치된 스킬 파일은 직접 수정하지 않았다.

## 실제로 벌어진 일

1. 사용자는 축구 개선을 맡겼고, 기존 실패도 고친 뒤 main에 반영하라고 지시했다.
2. 장기 시뮬레이션에서 기존 디비전 전력 순서와 성장 수준 기준이 실패했다.
3. 실행자는 기존 기준을 유지하며 모델을 고치는 A안과, 연간 순서 약속을 개정하는 B안을 사용자 선택지로 제시했다.
4. 다른 테스트 수리·검증·계측은 진행했지만, 핵심 모델 수정 후보의 구현·실험은 선택 뒤로 미뤘다. 모든 작업이 즉시 멈췄던 것은 아니다.
5. 08시에는 모델 수리가 끝나지 않은 상태로 실행을 마감했다. 이후 확인한 runtime에는 실행 중인 작업이나 heavy 프로세스가 없었다. 계속 실행 중인 백그라운드 작업으로 설명해서는 안 된다.
6. 사용자는 A안을 명시적으로 선택하고, self-improve의 위임대로 스스로 수리·보고하라고 다시 지시했다.

검증이 실패한 코드를 main에 올리지 않은 판단은 유지한다. 수정해야 할 부분은 **실패를 해결하는 작업을 불필요한 승인 대기로 바꾼 것**이다.

일반 문구의 모호함이 실행자의 책임을 없애지는 않는다. 사용자에게는 이미 “기존 실패까지 수리”하라는 구체적인 지시가 있었고, 기존 기준을 유지하는 A안으로 진행할 수 있었다. B안의 계약 개정 여부를 A안 진행의 선행 조건으로 만들 필요가 없었다.

## 제품 지침 판정

- 루트 `AGENTS.md`: 번역, spec 우선 구현, 버전 준비, 독립 리뷰 제공자 규칙은 이번 불필요한 질문의 원인이 아니다. 유지한다.
- `apps/web/AGENTS.md`: 미확정 디자인 추천을 공유 요구사항으로 승격하지 말라는 문구는 해당 디자인 범위에 적용한다. 기존 모델 계약을 복구하는 작업에 확대 적용하지 않는다. 삭제하지 않는다.
- 이 실행에 적용되는 프로젝트 `CLAUDE.md`는 확인되지 않았다.
- “검증 통과 후 main 반영”과 “독립 리뷰”는 계속 지킨다. 이 보호 규칙을 삭제하는 해결책은 요청하지 않는다.

## gusta에 요청하는 수정

### 1. 공통 질문 규칙에 위임 실행 예외를 명시

현재 공통 규칙의 마지막 문장을 다음 취지로 좁힌다. 생성된 설치본뿐 아니라 이를 만드는 공통 원본도 함께 반영해야 한다.

> 대화형 기획 스킬은 필요한 선택을 묻는다. `gusta-start`, `gusta-self-improve` 등 위임 실행은 직접 호출됐어도 이미 허가된 범위의 판단을 추천안으로 결정하고 기록한다. 개별 스킬의 명시적 위임 규칙을 우선 적용한다.

### 2. 사람 판단 경계 앞에 기존 위임 확인 절차 추가

질문 또는 주차 전에 다음을 확인한다.

1. 사용자가 이 작업이나 기존 실패의 수리를 이미 맡겼는가?
2. 제안이 기존 목표·계약을 복구하는가, 새로운 계약을 제안하는가?
3. 제한된 실험과 되돌림, 독립 리뷰, 기존 검증으로 결과를 평가할 수 있는가?
4. 별도 판단이 필요한 후보를 남겨도, 이미 허용된 추천안은 계속 실행할 수 있는가?

기존 기준을 복구하는 버그 수정·보정은 숫자나 이후 경기값이 달라진다는 이유만으로 새로운 공개 계약으로 분류하지 않는다. 기존 위임 안에서 영향이 제한되고 설명되는 경우에 원인·허용 파일·고정 후보·측정 예산·기각 조건을 정해 단계적으로 검증한다. 광범위하거나 영향이 불명확한 변경, 별도의 명시된 제품 정책 변경은 먼저 실제 사용자 위임 범위와 대조한다. 검증식을 유지하더라도 별도 SSOT 정책을 바꾸면 자동으로 단순 복구라고 간주하지 않는다. 사용자 위임 밖의 새 저장 형식·정밀도·계약·검증 범위·정책 또는 되돌리기 어려운 변화는 사람 판단 경계를 유지한다. 위임된 내부 기획 변경은 구현 전에 SSOT에 반영하고 근거를 기록한다.

### 3. 추천안 실행과 보고를 기본 경로로 명시

> 위임 범위의 추천안은 오케스트레이터가 채택하여 구현·독립 리뷰·검증한다. 채택 이유, 대안, 변경점, 실측과 한계를 보고서에 남긴다. 사용자가 판단할 추가 제안은 분리해 기록하되, 그 응답을 이미 허용된 작업의 실행 조건으로 삼지 않는다.

독립 리뷰와 검증은 생략하지 않는다. 기준을 낮추거나 실패를 숨겨 통과시키는 것도 허용하지 않는다.

### 4. 질문·중단 후 실제 재개 상태를 확인

- 비동기 질문을 보냈다는 사실만으로 작업을 승인 대기로 바꾸지 않는다.
- 메시지나 중단 뒤에는 실제 실행기·하위 세션 상태를 확인한다. 최신 지시가 기존 작업의 계속을 요구하고 누적 한도·소유권이 유효한 경우에 `interrupted`·종료 상태의 같은 배정을 실제로 재개한다. 명시적 중단·취소·목표 교체·시간 또는 시도 한도 종료는 자동 재개하지 않는다.
- 대기열에 메시지를 넣은 것과 작업이 다시 실행되는 것을 구분한다.
- 실행 중인 프로세스나 실제 후속 실행 연결이 있을 때만 백그라운드 진행을 보고한다.

| 최종 검증이 실패 | 수정·검증을 계속하거나 실제 한도와 미완료 범위를 보고한다. 성공·push·백그라운드 지속을 꾸며내지 않는다. |

## 이번 요청의 적용 상태

- 제품 지침 삭제: 없음. 해당 원인이 확인되지 않았다.
- 설치된 gusta 스킬 직접 수정: 없음. 이 문서는 upstream 수정 요청서다.
- 실행 원칙: 기존 매년 디비전 순서 보장과 장기 ±5 기준을 유지해 모델 수리를 계속한다. 이미 받은 위임을 다시 묻지 않는다.
- 검증 및 main 반영: 기존 검증과 독립 리뷰를 유지하며, 통과한 결과를 반영한다.
