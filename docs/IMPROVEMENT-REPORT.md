앱의 핵심 루프를 목표 확인 → 빌드 준비 → 경기 → 실제 성장 확인 → 다음 선택으로 정리했다. 개선 기준은 작업을 시작하기 전에 작성한 [가이드라인](IMPROVEMENT-GUIDE.md)이다.

## 재미와 전략 근거

- 네 가지 선수단/상대 상황에서 전술 네 종류를 각각 같은 시드 경기 160개로 비교했다. 점유·역습·압박·균형이 각각 유리한 상황을 확인했다.
- 압박은 같은 선수에게 다른 전술보다 피로 비용이 6 높다. 패스는 점유/정확도, 수비는 상대 슛 억제, 체력과 피로는 압박 지속력에 반영된다.
- 전력 우선/휴식 우선 선발, 유망주 육성/회복, 영입/시설 투자에 실제 비용과 기회비용이 있다. 선택·필터·재접속으로 결과를 다시 추첨하거나 무료 성장을 얻지 않는다.
- 성장 목표는 실제 경력 사실을 사용하며 합성 현금이나 반복 보상을 지급하지 않는다. 이전 준비·컵 승리는 최근 화면 목록에서 빠져도 전체 저장 기록으로 유지된다.

## 최종 검증

성능 기준은 Chromium 153.0.8010.12, 페이지 CPU 4배 감속·Fast 4G·390×844 DPR2 환경이다. 입력 값은 메뉴/재생 조작 후 두 번째 화면 갱신까지의 지연이다. 별도로 측정한 100시즌 재접속은 **1,356ms**이며 감속하지 않은 환경이다. page-target 전송량에서 빠질 수 있는 worker도 전체 자산 예산에 포함했다.

장기 저장은 기본·실제 유망주/회복 훈련과 투자 선택을 하는 두 합성 커리어의 100시즌, 이후 진행 중 저장, 124시즌 시대 전환을 검사했다. 모든 경력 기록의 canonical 일치·재시작 결과 일치·8개국 아카이브/그룹 정합성이 통과했다. 기록 삭제·숫자 반올림·용량 한도 증가는 하지 않았다. 모든 시드와 무한한 경력의 저장을 보장하는 수치는 아니다.

최신 소스 SHA-256: `b3db7c49af2ce3ccadaf73f436682561bdca8dca98b0f8d146b46222ef38b684`. 빌드 SHA-256: `dbc12b031885da51feea327be13625afff9ac10bf21ecfb64688256beeaf70c8`. 기존 T010의 로컬 출시 검증을 함께 마감하고, CI에 저장·성능 게이트와 결과 보관을 연결했다. 원격 CI와 실제 Netlify/App Store 배포는 별도 확인 대상이다.

## 범위

T027에서 [실패한 Linux CI](https://github.com/hetarho/haeram-soccer/actions/runs/37699063758)의 창단 화면을 보정했다. 한글 대체 글꼴로 안내 문구 세 곳이 추가로 줄바꿈되면서 문서가 794~795px로 늘어난 문제였다. 좁은 화면의 여백·줄 간격과 자연스러운 푸터 배치를 수정했고, 글자 크기·48px 조작·불러오기 도구를 유지했다.

실제 WenQuanYi Zen Hei 글꼴로 동일한 실패를 재현한 뒤, 세 브라우저·두 크기에서 문서 높이 740/844px와 모든 조작의 접근성을 확인했다. [측정 기록](improvement/t027-font-proof/independent-font-proof.json)과 [360px 화면](improvement/t027-font-proof/chromium-360x740.png)을 보존했다. 넓은 문자 간격과 줄바꿈을 강제하는 회귀 검사를 포함한 최신 브라우저 검사 162개가 통과했다. 실제 글꼴 확인은 Mac 브라우저 엔진의 검사이며, 수정 커밋의 Linux CI 결과는 푸시 후 확인한다.

현재 산출물은 기존 아키텍처의 웹 서비스다. 앱스토어 배포용 Flutter 포팅·서명·심사·실기기 테스트는 후속 범위이며, 앱스토어 순위나 사용자 반응을 검증했다고 주장하지 않는다. 재미와 장기 난이도의 실제 평가는 사용자 플레이테스트가 필요하다.
