# Shared UI coverage audit

Matchday Print, 2026-10-29. This audits the actual app components and game pages. The workbench's own search, catalogue navigation and developer administration chrome are outside the theme-design scope.

Read the [shared design-system guide](DESIGN-SYSTEM.md) and [resource-skin contract](RESOURCE-SKINS.md) when applying the same approach to another theme.

## Scope and method

- Statically inspected all 120 TSX modules and 69 component stylesheets under `src/ui`, including native controls, surface classes, semantic hooks and shared-component imports. Pure data/geometry helpers are covered by their relevant unit tests.
- The initial audit rendered 50 app-component previews at 1100×850 and 390×844: all 100 loaded without exceptions or document-level overflow. Card brings the catalogue to 51; its desktop/mobile examples and fixture-notebook consumer were inspected with the three material planes.
- Inspected computed image/frame URLs on visible controls; input fields and dropdown triggers all had resource skins. Rechecked expanded analytical groups and opened choice/checkbox states separately.
- Checked all four formation layouts at 320, 390 and 1100px: no overlapping marker boxes; analysis centre-circle width and height match. Full formation selection keeps all eleven detailed facts reachable, with 48px-wide targets.

Default previews do not prove every saved-world state. Read-only command samples, unavailable proposals and empty historical records are intentional fixture states; UI code and shared-role coverage were also inspected for those branches. Formal end-to-end suites remain at the ARCH-30 batch gate.

## Three-plane/Card follow-up

The shared [Card](../src/ui/Card.tsx) assembles sheet/detail surfaces, metadata, title, body
and optional actions. FixtureNotebook uses it instead of ad hoc article panels. The
[material notes](surfaces-print/README.md) own current resources and luminance data. Twenty
representative desktop/mobile/theme renders checked the material bindings and Card fallbacks;
the workbench administration shell remains outside the design scope.

## Explicit exceptions

| Item                                              | Reason                                                                                                                              |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Text, club/player, money and terminology links    | Text-level actions retain their designed underline/icon instead of becoming boxed action buttons.                                   |
| Tabs, navigation and home scene controls          | Their own shared navigation/home roles supply their artwork and selected treatment.                                                 |
| Dialog close and similar utility icons            | The existing icon resource carries the action inside the already framed header; another surrounding card is unnecessary.            |
| Formation players                                 | Circular child artwork supplies the marker; a rectangular button/panel frame would reintroduce collisions.                          |
| Live graph, pitch, heat and kit geometry          | SVG/canvas preserves facts, coordinates and semantic colour scales; authored material sits behind it.                               |
| Layout wrappers, dividers and plain DecisionOwner | Spacing/alignment wrappers do not each need a decorative card. The explicit plain mode intentionally inherits its parent's surface. |
| Tunable laboratory and workbench chrome           | Developer tools retain their administration layout; their disclosure headings are intentionally plain.                              |
| File picker and hidden form values                | The surrounding label uses shared artwork; the operating system's picker and invisible submission fields are not theme surfaces.    |
